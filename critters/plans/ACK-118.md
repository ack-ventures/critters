# ACK-118: Expand Slack notifications to more lifecycle events

## Summary

Add Slack notifications for four new lifecycle events:
1. **Task picked up** — when a critter begins working on an issue (after clone, before planning)
2. **Planning complete** — when the planning phase finishes successfully, before execution begins
3. **Review started** — when a review critter picks up a PR for review
4. **Timeout warning** — when a task has been running for 80% of its timeout limit

Currently, Slack notifications only fire on terminal events (success, failure, review merged/needs-changes/failure). These additions give visibility into in-progress work.

## Files to modify

### 1. `src/slack.ts` — Add four new formatter functions

Add these exported functions following the existing pattern (formatter returns a string, `notify()` via `sendSlackNotification` sends it):

```typescript
export function formatTaskPickedUp(identifier: string, title: string, repoUrl: string): string {
  return `*${identifier}* — ${title}\nPicked up — cloning ${repoUrl}...`;
}

export function formatPlanningComplete(
  identifier: string,
  title: string,
  numTurns?: number,
  costUsd?: number,
): string {
  const stats: string[] = [];
  if (numTurns != null) stats.push(`${numTurns} turns`);
  if (costUsd != null) stats.push(`$${costUsd.toFixed(2)}`);
  const suffix = stats.length > 0 ? ` (${stats.join(", ")})` : "";
  return `*${identifier}* — ${title}\nPlanning complete${suffix} — executing...`;
}

export function formatReviewStarted(identifier: string, title: string, prUrl: string): string {
  return `*${identifier}* — ${title}\nReview started: ${prUrl}`;
}

export function formatTimeoutWarning(
  identifier: string,
  title: string,
  elapsedMinutes: number,
  timeoutMinutes: number,
): string {
  return `*${identifier}* — ${title}\n⚠️ Running for ${elapsedMinutes}/${timeoutMinutes} minutes`;
}
```

**Notes:**
- `formatPlanningComplete` takes optional `numTurns` and `costUsd` to include stats when available (from `SpawnResult`)
- `formatTimeoutWarning` uses a warning emoji since it's an alert, not a status update
- All formatters use the same `*identifier* — title\nDetails` pattern as existing formatters

### 2. `src/spawner.ts` — Integrate new notifications into `runTask()`

**Imports:** Add `formatTaskPickedUp`, `formatPlanningComplete`, `formatTimeoutWarning` to the existing import from `./slack.js`.

**Task picked up notification** — after the clone (line 121) and branch creation (line 124), before planning begins. Insert after line 127 (the `.git/info/exclude` append):

```typescript
await sendSlackNotification(
  this.config.slackWebhookUrl,
  formatTaskPickedUp(task.identifier, task.title, task.repoUrl),
);
```

**Timeout warning** — schedule a `setTimeout` at 80% of the timeout limit. Insert right after the existing timeout `setTimeout` (after line 104):

```typescript
const warningTimeout = setTimeout(async () => {
  const elapsedMinutes = Math.round((this.config.timeoutMinutes * 0.8));
  await sendSlackNotification(
    this.config.slackWebhookUrl,
    formatTimeoutWarning(task.identifier, task.title, elapsedMinutes, this.config.timeoutMinutes),
  );
}, this.config.timeoutMinutes * 0.8 * 60 * 1000);
```

Clear `warningTimeout` in the `finally` block alongside the existing `clearTimeout(timeout)`:

```typescript
clearTimeout(warningTimeout);
```

**Planning complete notification** — after the planning phase succeeds and stats are logged (after line 175), before execution begins. Insert after the `commentOnIssue(task.issueId, planStats)` call:

```typescript
await sendSlackNotification(
  this.config.slackWebhookUrl,
  formatPlanningComplete(task.identifier, task.title, planResult.numTurns, planResult.costUsd),
);
```

### 4. `src/__tests__/slack.test.ts` — Add tests for new formatters

Add test suites for each new formatter, following the existing pattern:

```typescript
import {
  // ... existing imports ...
  formatTaskPickedUp,
  formatPlanningComplete,
  formatReviewStarted,
  formatTimeoutWarning,
} from "../slack.js";

describe("formatTaskPickedUp", () => {
  test("includes identifier, title, and repo URL", () => {
    const msg = formatTaskPickedUp("ACK-1", "Add feature", "git@github.com:org/repo.git");
    expect(msg).toContain("ACK-1");
    expect(msg).toContain("Add feature");
    expect(msg).toContain("git@github.com:org/repo.git");
    expect(msg).toContain("Picked up");
  });
});

describe("formatPlanningComplete", () => {
  test("includes identifier and title", () => {
    const msg = formatPlanningComplete("ACK-1", "Add feature");
    expect(msg).toContain("ACK-1");
    expect(msg).toContain("Add feature");
    expect(msg).toContain("Planning complete");
    expect(msg).toContain("executing");
  });

  test("includes stats when provided", () => {

    const msg = formatPlanningComplete("ACK-1", "Add feature");
    expect(msg).not.toContain("turns");
    expect(msg).not.toContain("$");
  });

describe("formatReviewStarted", () => {
  test("includes identifier, title, and PR URL", () => {
    const msg = formatReviewStarted("ACK-1", "Add feature", "https://github.com/org/repo/pull/1");
    expect(msg).toContain("ACK-1");
    expect(msg).toContain("Add feature");
    expect(msg).toContain("https://github.com/org/repo/pull/1");
    expect(msg).toContain("Review started");
  });
});

describe("formatTimeoutWarning", () => {
  test("includes identifier, title, elapsed and timeout minutes", () => {
    const msg = formatTimeoutWarning("ACK-1", "Add feature", 24, 30);
    expect(msg).toContain("ACK-1");
    expect(msg).toContain("Add feature");
    expect(msg).toContain("24/30 minutes");
```

## Dependencies

- No new packages needed
- No config changes needed — uses existing `config.slackWebhookUrl` and `config.timeoutMinutes`

## Edge cases

- **Missing webhook URL**: `sendSlackNotification` already returns early if `webhookUrl` is undefined, so all new calls are safe
- **Timeout warning after completion**: The `warningTimeout` is cleared in `finally`, so it won't fire after the task completes or fails
- **Planning stats unavailability**: `formatPlanningComplete` handles missing `numTurns`/`costUsd` gracefully with optional params
- **Timeout warning calculation**: Uses `Math.round(config.timeoutMinutes * 0.8)` for the elapsed minutes display, which is the expected elapsed time at the warning point (not actual elapsed)

## Testing approach

1. Unit tests for all four new formatter functions in `src/__tests__/slack.test.ts`
2. Existing tests remain unchanged — no modifications to existing formatters or `sendSlackNotification`
3. Integration testing: run `bun test` to verify all tests pass
