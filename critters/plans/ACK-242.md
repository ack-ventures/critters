# ACK-242: Add critter version to tracker comments and PR descriptions

## Summary

Add the `VERSION` constant from `src/version.ts` to issue tracker comments and PR description stats sections so users can identify which critter version produced a given PR or comment.

## Files to Modify

### 1. `src/runner/execution.ts`

**Add import** (line 1 area):
```typescript
import { VERSION } from "../version.js";
```

**Modify `formatStatsSection()`** (line 158):
Add a version line as the first item after the heading. Change:
```typescript
const lines: string[] = ["## Critter Stats"];
```
to:
```typescript
const lines: string[] = ["## Critter Stats", `- **Critter**: v${VERSION}`];
```

This places the version line at the top of the stats section, before phase duration lines.

### 2. `src/unified-spawner.ts`

**Add import** (line 1 area):
```typescript
import { VERSION } from "./version.js";
```

**Modify PR created comment** (line 812):
Change:
```typescript
await tracker.comment(task.id, `PR created: ${prUrl} (${modelSummary}, completed in ${totalDuration})`);
```
to:
```typescript
await tracker.comment(task.id, `PR created: ${prUrl} (${modelSummary}, critters v${VERSION}, completed in ${totalDuration})`);
```

**Modify generic type completion comment** (line 568):
Change:
```typescript
await tracker.comment(task.id, `Critter [${critterType.name}] (${modelSummary}) completed in ${totalDuration}`);
```
to:
```typescript
await tracker.comment(task.id, `Critter [${critterType.name}] (${modelSummary}, critters v${VERSION}) completed in ${totalDuration}`);
```

**Modify review merged comment** (line 875):
Change:
```typescript
await tracker.comment(task.id, `PR merged by review critter (${critterType.phases[0].model}, ${totalDuration})`);
```
to:
```typescript
await tracker.comment(task.id, `PR merged by review critter (${critterType.phases[0].model}, critters v${VERSION}, ${totalDuration})`);
```

## What NOT to change

- Slack notifications — no version needed
- Auto-retry or transient failure comments — too noisy
- Timeout PR comments
- The "picking up task" comment (line 315) — not a completion comment
- The "PR was already merged" comment (line 872) — informational only
- Phase-level stats within `formatPhaseStats()` — version is a task-level concern

## Format

All version strings use `v${VERSION}` format, producing e.g. `v0.10.0` or `vdev` during development.

## Dependencies

None. `src/version.ts` already exports `VERSION` as a named export.

## Testing Approach

1. **Type checking**: Run `bun run typecheck` to verify imports resolve correctly
2. **Lint**: Run `bun run lint` to verify code style
3. **Unit tests**: Run `bun test` — existing tests should pass since no behavior changes, only string content changes
4. **Manual verification**: Start the daemon with `--dry-run` to verify it loads without errors
5. **Grep verification**: After implementation, grep for `v${VERSION}` in both files to confirm all insertions are present
