# ACK-105: Add tests for stream-filter.jq output

## Summary

Add snapshot-style tests for the jq stream filter (`src/stream-filter.jq`) to catch regressions when the filter is modified. Each test pipes a sample stream-json event through the real `jq` binary with the filter file and asserts on the output.

## Current State

- `src/stream-filter.jq` is the jq filter that pretty-prints Claude's `--output-format stream-json` events
- `src/jq-filter.ts` contains an embedded TypeScript string copy of the same filter (not tested here — we test the `.jq` file directly)
- The filter requires a `$tool_color` variable passed via `jq --arg tool_color '...'`
- Existing test infrastructure: `bun:test`, helpers in `src/__tests__/helpers.ts` (`createTempDir`, `createTestRepo`)
- Existing test patterns: `src/__tests__/smoke.test.ts` (trivial), `src/config.test.ts` (more comprehensive, uses `describe`/`test`/`expect` from `bun:test`)

## File to Create

### `src/__tests__/stream-filter.test.ts`

A single test file with two helpers and one `describe` block containing individual tests for each event type.

#### Helpers

**`stripAnsi(s: string): string`** — Remove ANSI escape sequences from output for easier assertions.

```typescript
function stripAnsi(s: string): string {
  return s.replace(/\x1b\[[0-9;]*m/g, "");
}
```

**`runJqFilter(input: string): Promise<string>`** — Write input to a temp file, pipe it through `jq` with the stream filter, and return the output with ANSI stripped.

```typescript
import { runCommand } from "../utils.js";
import { writeFileSync } from "node:fs";
import { join } from "node:path";

async function runJqFilter(input: string): Promise<string> {
  // Write input to a temp file to avoid shell escaping issues
  const inputFile = join(tmpDir, "input.jsonl");
  writeFileSync(inputFile, input);

  const result = await runCommand("jq", [
    "--unbuffered", "-cr",
    "--arg", "tool_color", "\x1b[36m",
    "-f", "src/stream-filter.jq",
    inputFile,
  ]);

  if (result.code !== 0 && result.stderr) {
    throw new Error(`jq failed (exit ${result.code}): ${result.stderr}`);
  }

  return stripAnsi(result.stdout).trimEnd();
}
```

Key design decisions:
- Uses `runCommand` from `src/utils.ts` (the same helper used in production code), keeping the test consistent with how the codebase invokes external processes.
- Passes `\x1b[36m` as the `tool_color` arg — the actual value doesn't matter for assertions since we strip ANSI, but it must be provided since the filter references `$tool_color`.
- Input is written to a temp file rather than piped via stdin to avoid shell escaping complexity. jq accepts a filename argument directly.
- Runs `jq` with the filter file path `src/stream-filter.jq` (relative to the project root, which is the default cwd for `bun test`).

#### Setup / Teardown

```typescript
import { beforeAll, afterAll } from "bun:test";
import { mkdirSync, rmSync } from "node:fs";

const tmpDir = "/tmp/critters-jq-test";

beforeAll(() => {
  mkdirSync(tmpDir, { recursive: true });
});

afterAll(() => {
  rmSync(tmpDir, { recursive: true, force: true });

```

Uses a fixed temp dir path (same pattern as `src/config.test.ts`) since tests run sequentially within a file and there's no collision risk.

## Dependencies

- `jq` must be installed on the system (it's already listed as a prerequisite in the project README)
- No new npm/bun dependencies needed
- Uses only `bun:test`, `node:fs`, `node:path`, and `src/utils.ts` (`runCommand`)

## Testing Approach

Run `bun test src/__tests__/stream-filter.test.ts` to execute just the new tests, or `bun test` to run all tests including the smoke test and config tests.

Each test is self-contained and constructs its own input event. The `runJqFilter` helper handles file I/O and process spawning. ANSI stripping ensures assertions are readable and don't break when colors change.

The tests exercise every branch of the jq filter:
- All 4 top-level event types (`system`, `assistant`, `user`, `result`)
- All tool name formatting branches (`Read`/`Write`/`Edit`, `Bash`, `Glob`, `Grep`, `Task`, unknown)
- All user event sub-branches (stdout/stderr, file create, subagent completion, tool errors)
- Subagent vs top-level agent paths
- Empty/whitespace filtering
- Stdout truncation at >10 lines
