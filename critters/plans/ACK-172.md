# ACK-172: Add `--type` filter to `--dry-run`

## Summary

Add a `--type <name>` flag that filters `config.critterTypes` when running `--dry-run`, so only the specified critter type is polled. This is useful when many types are configured and you want to test just one.

Usage: `critters --dry-run --type create`

## Files to Modify

```typescript

  const idx = Bun.argv.indexOf("--type");
  return idx !== -1 && Bun.argv[idx + 1] ? Bun.argv[idx + 1] : undefined;
```

**Validate `--type` requires `--dry-run`** (right after flag parsing):

**Filter critterTypes before `createTrackers`** (after line 163 `config.noTmux = ...`, before line 171 `createTrackers`):

This placement ensures that only trackers for the filtered type's provider(s) are instantiated, avoiding credential errors for unused providers.

```typescript
if (typeFilter) {
  const match = config.critterTypes.filter(
    (ct) => ct.name === typeFilter || ct.name.startsWith(typeFilter + ":")
  );
  if (match.length === 0) {
    const baseNames = [...new Set(config.critterTypes.map((ct) => ct.name.split(":")[0]))];
    const available = config.critterTypes.length === baseNames.length
      ? baseNames.join(", ")
      : baseNames.map((base) => {
          const variants = config.critterTypes
            .filter((ct) => ct.name === base || ct.name.startsWith(base + ":"))
            .map((ct) => ct.name);
          return variants.length > 1 ? `${base} (${variants.join(", ")})` : base;
        }).join(", ");
    logError(`Unknown type "${typeFilter}". Available types: ${available}`);
    process.exit(1);
  }
  config.critterTypes = match;
}
```

The filter supports:
- Exact name match: `--type create` matches a type named `create`
- Base name match for multi-provider: `--type create` matches `create:linear` and `create:jira`
- Exact expanded name: `--type create:jira` matches only the Jira variant

## Edge Cases

1. **`--type` without `--dry-run`**: Error with message explaining it only works with `--dry-run`. Exit 1.
2. **`--type` with nonexistent name**: Error listing available type names (showing both base and expanded names for multi-provider types). Exit 1.
3. **`--type` without a value** (e.g., `critters --dry-run --type`): The argv parsing returns `undefined`, so `typeFilter` stays unset and all types run — same as omitting `--type`.
4. **Multi-provider types**: `--type create` matches both `create:linear` and `create:jira`. `--type create:jira` matches only the Jira variant.
5. **Provider credential isolation**: Because filtering happens before `createTrackers`, only the needed provider's tracker is instantiated. A user testing `--type create` (Linear-only) won't need Jira credentials even if other types use Jira.

## Testing Approach

1. **Manual dry-run test**: Run `bun run src/index.ts --dry-run --type create` with a config that has multiple types — verify only `create` type is polled.
2. **Error case**: Run `--dry-run --type nonexistent` — verify error message with available types.
3. **`--type` without `--dry-run`**: Verify error message.
4. **No `--type`**: Verify `--dry-run` still polls all types (backward compatible).
5. **Multi-provider**: With a config using `provider: [linear, jira]`, verify `--type create` picks up both `create:linear` and `create:jira`.
