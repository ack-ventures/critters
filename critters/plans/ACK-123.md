# ACK-123: Add `critters logs` CLI command

## Summary

Add a `critters logs <issue-identifier>` subcommand that displays the output logs for a specific critter run. The command scans the work directory for matching run directories, reads the stream-json log files, and pipes them through the existing jq filter for pretty-printed output. When work directories have been cleaned up, it falls back to fetching log attachments from the Linear issue.

## Files to Create

### `src/logs.ts`

New module containing all log retrieval logic. Named export `runLogs(args: string[])`.

**Core logic:**

1. **Parse arguments:**
   - First positional arg after `logs`: the issue identifier (e.g., `ACK-101`). Required — exit with error if missing.
   - `--phase planning|execution|review`: optional, selects which phase's logs to show.
   - `--follow` / `-f`: optional, tail mode.
   - `--config PATH`: optional, custom config file path (passed through to `loadWorkDir`).
   - Validate the identifier looks like a Linear issue ID (e.g., matches `/^[A-Z]+-\d+$/`).

2. **Load config** (for `workDir` path) using a lightweight config loader. The existing `loadConfig()` requires `LINEAR_API_KEY` which may not be set for a read-only logs command. Use the new `loadWorkDir()` helper from `src/config.ts` that reads just the `workDir` field from config YAML, falling back to `/tmp/critters-work`. This avoids requiring env vars just to read logs.

3. **Strategy 1 — Work directory exists:**
   - Use `readdirSync` on the resolved workDir to find directories matching the identifier.
   - **Use strict regex matching** to avoid prefix collisions (e.g., `ACK-1` must not match `ACK-10-*`):
     - Regular critter dirs: `/^<escaped-identifier>-\d+$/` (e.g., `ACK-101-1718000000000`)
     - Review critter dirs: `/^review-<escaped-identifier>-\d+$/` (e.g., `review-ACK-101-1718000000000`)
   - If multiple matches exist (e.g., retries), use the most recent one (highest timestamp suffix, extracted via split on `-` and parsing the numeric suffix).
   - Determine which phase to show:
     - If `--phase` is specified, use that. Map: `planning` → `.critter-output-plan.json`, `execution` → `.critter-output-exec.json`, `review` → `.critter-output-review.json`.
     - If no `--phase`, auto-detect: check for files in order `review` → `exec` → `plan`, show the first one that exists (most recent/advanced phase).
   - Read the log file and pipe through jq for formatting:
     - Shell out to `jq` with the filter from `src/jq-filter.ts` (write the `STREAM_FILTER` to a temp file at `/tmp/critters-logs-filter.jq`, then run `jq -cr --arg tool_color '\x1b[36m' -f <filter-file> <log-file>`).
     - Pipe jq's stdout directly to `process.stdout`.
   - **Follow mode** (`--follow` / `-f`):
     - Use `tail -f` piped to `jq --unbuffered` for real-time streaming:
       ```bash
       tail -n +1 -f <log-file> | jq -cr --unbuffered --arg tool_color '\x1b[36m' -f <filter-file>
       ```
     - Monitor the raw file in parallel: poll every 2s, check if the last line contains `"type":"result"`. When detected, kill the `tail` | `jq` pipeline and exit cleanly.
     - Also exit on SIGINT.
     - If the file already contains a `"type":"result"` line (run is complete), skip follow mode and just display the full log normally.

4. **Strategy 2 — Work directory not found:**
   - If no matching directory exists in workDir, attempt to fetch logs from Linear.
   - Check if `LINEAR_API_KEY` is available. If not, print: `No logs found for <identifier> in work directory. Set LINEAR_API_KEY to check Linear for uploaded logs.`
   - Initialize the Linear client using `initLinear` from `src/linear.ts`.
   - Look up the issue by identifier using the filter API:
     ```typescript
     const client = getClient();
     const issues = await client.issues({ filter: { identifier: { eq: identifier } } });
     ```
   - Fetch the issue's attachments. Look for attachments matching these exact title patterns (from `uploadFailureLogs` in `spawner.ts` and `uploadReviewLogs` in `review-spawner.ts`):
     - `<identifier>-plan-output.txt`
     - `<identifier>-plan-stderr.txt`
     - `<identifier>-exec-output.txt`
     - `<identifier>-exec-stderr.txt`
     - `<identifier>-review-output.txt`
     - `<identifier>-review-stderr.txt`
     - `<identifier>-plan.md`
     - `<identifier>-checkpoint.md`
   - If `--phase` is specified, filter to only show attachments for that phase.
   - If no `--phase`, prefer showing the output file for the most advanced phase found (review > exec > plan).
   - Download the matching attachment URL via `fetch()` and print content to `process.stdout`.
   - If no attachments found, print: `No logs found for <identifier>. Work directory has been cleaned up and no logs were uploaded to Linear.`

## Implementation Details

### Output conventions

- **Log content** (jq-formatted output, downloaded attachments): write directly to `process.stdout` using `process.stdout.write()` or by piping child process stdout to `process.stdout`.
- **Status/error messages** (e.g., "No logs found", "Checking Linear..."): use `console.error()` so they go to stderr and don't mix with piped log output.

This follows standard CLI conventions — log content to stdout (pipeable), status messages to stderr.

### Phase file mapping

| `--phase` value | Log file in work dir | Work dir pattern | Linear attachment title |
|---|---|---|---|
| `planning` | `.critter-output-plan.json` | `<ID>-\d+` | `<ID>-plan-output.txt` |
| `execution` | `.critter-output-exec.json` | `<ID>-\d+` | `<ID>-exec-output.txt` |
| `review` | `.critter-output-review.json` | `review-<ID>-\d+` | `<ID>-review-output.txt` |

### Auto-detect phase order (no `--phase`)

Check in reverse chronological order of typical execution:
1. `.critter-output-review.json` (in `review-<ID>-\d+` dir)
2. `.critter-output-exec.json` (in `<ID>-\d+` dir)
3. `.critter-output-plan.json` (in `<ID>-\d+` dir)

Show the first one found.

### Directory matching regex

To avoid prefix collisions (e.g., `ACK-1` matching `ACK-10-1234567890`), use strict regex:

```typescript
// Escape special regex chars in identifier (e.g., hyphens are literal in identifiers like ACK-101)
const escaped = identifier.replace(/[.*+?^${}()|[\]\\]/g, "\\$&");
const critterDirPattern = new RegExp(`^${escaped}-\\d+$`);
const reviewDirPattern = new RegExp(`^review-${escaped}-\\d+$`);
```

### jq invocation

Use `Bun.spawn` to run:
```bash
jq -cr --arg tool_color '\x1b[36m' -f <filter-file> <log-file>
```

Write the `STREAM_FILTER` string to a temp file at `/tmp/critters-logs-filter.jq` before invoking jq. Pipe child stdout to `process.stdout` via `Bun.spawn`'s `stdout: "inherit"` or by reading and forwarding.

### Follow mode implementation

1. First check if the log file already contains a result event (grep for `"type":"result"`). If so, display normally (no tailing).
2. Otherwise, spawn:
   ```bash
   tail -n +1 -f <log-file> | jq -cr --unbuffered --arg tool_color '\x1b[36m' -f <filter-file>
   ```
3. In parallel, poll the raw log file every 2s. When a line containing `"type":"result"` appears, wait 1s for jq to process it, then kill the child process.
4. Handle SIGINT to kill the child process and exit cleanly.

### Linear fallback

```typescript
import { LinearClient } from "@linear/sdk";

const apiKey = process.env.LINEAR_API_KEY;
if (!apiKey) {
  console.error(`No logs found for ${identifier} in work directory.`);
  console.error(`Set LINEAR_API_KEY to check Linear for uploaded logs.`);
  process.exit(1);
}

const client = new LinearClient({ apiKey });
const issues = await client.issues({
  filter: { identifier: { eq: identifier } },
});

if (issues.nodes.length === 0) {
  console.error(`Issue ${identifier} not found in Linear.`);
  process.exit(1);
}

const issue = issues.nodes[0];
const attachments = await issue.attachments();
```

Note: We create a new `LinearClient` directly rather than using `initLinear`/`getClient` from `linear.ts`, since those are designed for the daemon's lifecycle and require the full Config object. A standalone client instantiation is simpler here.

## Edge Cases

- **No identifier provided**: Print usage and exit with code 1.
- **Invalid identifier format**: Print error with expected format (e.g., `Expected format: ABC-123`).
- **Multiple work dirs for same identifier** (retries): Pick the one with the highest timestamp suffix.
- **Log file exists but is empty**: Print `Log file is empty for <phase> phase.` to stderr.
- **jq not installed**: Catch the spawn error and print a message suggesting to install jq.
- **Follow mode on a completed run**: Detect the `result` event in existing content and print the logs without tailing.
- **`--config` flag**: Parse from args and pass to `loadWorkDir`.
- **Work directory doesn't exist at all**: Fall through directly to Linear fallback.
- **Identifier with special regex chars**: Escape identifier before using in regex (handled by the escape step).
