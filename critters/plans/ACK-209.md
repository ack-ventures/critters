# ACK-209: Dockerfile + docker-compose for self-hosting

## Summary

Add Docker support so anyone can deploy critters with `docker compose up`. This involves creating a Dockerfile (multi-stage build), docker-compose.yaml, .dockerignore, a small source change to enable stdout logging in Docker, adding a Docker image build/push job to the release CI, and adding a Docker section to the README.

## Files to Create

### 1. `Dockerfile`

Multi-stage build:

**Stage 1 — Build (`oven/bun:1`)**
- Copy `package.json`, `bun.lock`, `tsconfig.json`
- Run `bun install --frozen-lockfile`
- Copy `src/` directory
- Accept a `VERSION` build arg (defaults to `"dev"`)
- Write the version into `src/version.ts` before compilation
- Run `bun build --compile src/index.ts --outfile /app/critters`

**Stage 2 — Runtime (`debian:bookworm-slim`)**
- Install runtime dependencies via apt: `git`, `jq`, `curl`, `ca-certificates`, `gnupg`
- Install Node.js (from NodeSource apt repo — needed for Claude Code CLI which is an npm package)
- Install Claude Code CLI: `npm install -g @anthropic-ai/claude-code`
- Install `gh` CLI (from GitHub's official apt repo)
- Set default git identity for commits (`git config --global user.name "Critters" && git config --global user.email "critters@noreply"`)
- Copy the compiled `critters` binary from Stage 1
- Add a `HEALTHCHECK` using the health endpoint
- Set `WORKDIR /app`
- Expose port `3847` (health/dashboard port)
- `CMD ["./critters", "--no-tmux", "--json-logs", "--skip-update"]`

**Key decisions:**
- Use `debian:bookworm-slim` for runtime because the Bun-compiled binary requires glibc
- Node.js is required in the runtime image because Claude Code CLI (`@anthropic-ai/claude-code`) is an npm package that needs `node` to run — it installs the `claude` binary as a Node.js wrapper script
- `--no-tmux` is essential — containers don't have a terminal, and this mode is already fully supported (the daemon uses `spawnClaudeSubprocess` instead of tmux panes)
- `--json-logs` is paired with `--no-tmux` so logs go to stdout/stderr (see source change below) instead of a log file, making `docker compose logs -f` work correctly
- `--skip-update` prevents the auto-updater from attempting to overwrite the binary inside the container. Without this, the updater would download a new binary that (a) may not match the container's runtime deps, (b) is lost on restart since the writable layer is ephemeral, and (c) could leave the container broken. Updates should be done by pulling a new Docker image instead.
- The compiled binary avoids needing Bun in the runtime image
- `git` is needed at runtime because critters shallow-clones repos into the work directory
- A `VERSION` build arg is used to embed the correct version at build time, matching the pattern in `release.yml` (lines 37-39)
- Default git identity is set so `git commit` works inside the container without user configuration

**Dockerfile content:**

```dockerfile
FROM oven/bun:1 AS build

WORKDIR /app
COPY package.json bun.lock tsconfig.json ./
RUN bun install --frozen-lockfile
COPY src/ src/

ARG VERSION=dev
RUN echo "export const VERSION = \"${VERSION}\";" > src/version.ts

RUN bun build --compile src/index.ts --outfile /app/critters

FROM debian:bookworm-slim

RUN apt-get update && apt-get install -y --no-install-recommends \
    git \
    jq \
    curl \
    ca-certificates \
    gnupg \
  && rm -rf /var/lib/apt/lists/*

# Install Node.js (LTS) — required by Claude Code CLI
RUN curl -fsSL https://deb.nodesource.com/setup_lts.x | bash - \
  && apt-get install -y --no-install-recommends nodejs \
  && rm -rf /var/lib/apt/lists/*

# Install Claude Code CLI
RUN npm install -g @anthropic-ai/claude-code

# Install GitHub CLI
RUN curl -fsSL https://cli.github.com/packages/githubcli-archive-keyring.gpg \
    | gpg --dearmor -o /usr/share/keyrings/githubcli-archive-keyring.gpg \
  && echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/githubcli-archive-keyring.gpg] https://cli.github.com/packages stable main" \
    > /etc/apt/sources.list.d/github-cli.list \
  && apt-get update \
  && apt-get install -y --no-install-recommends gh \
  && rm -rf /var/lib/apt/lists/*

# Set default git identity for commits
RUN git config --global user.name "Critters" \
  && git config --global user.email "critters@noreply"

COPY --from=build /app/critters /app/critters

WORKDIR /app
EXPOSE 3847

HEALTHCHECK --interval=30s --timeout=5s --start-period=10s --retries=3 \
  CMD curl -f http://localhost:3847/healthz || exit 1

CMD ["./critters", "--no-tmux", "--json-logs", "--skip-update"]
```

### 2. `docker-compose.yaml`

```yaml
services:
  critters:
    build: .
    # or: image: ghcr.io/ack-ventures/critters:latest
    env_file: .env
    volumes:
      - ./critters.config.yaml:/app/critters.config.yaml:ro
      - critters-data:/root/.critters     # metrics, state
      - ~/.ssh:/root/.ssh:ro              # SSH keys for git clone
      - ~/.config/gh:/root/.config/gh:ro  # GitHub CLI auth
      # Uncomment if using Claude CLI interactive auth instead of ANTHROPIC_API_KEY:
      # - ~/.claude:/root/.claude
    ports:
      - "3847:3847"
    restart: unless-stopped

volumes:
  critters-data:
```

**Key decisions:**
- `env_file: .env` passes all env vars (LINEAR_API_KEY, JIRA_*, SLACK_*, ANTHROPIC_API_KEY)
- `ANTHROPIC_API_KEY` in `.env` is the primary auth method for Docker (headless-friendly; no interactive auth needed)
- `~/.claude` mount is commented out by default — only needed if using interactive CLI auth instead of `ANTHROPIC_API_KEY`
- `~/.ssh` mounted read-only for SSH-based git clone URLs (`git@github.com:org/repo.git`) — required for the daemon to clone repos
- `critters.config.yaml` mounted read-only — config changes require a container restart (or volume mount without `:ro` if hot-reload is desired)
- `critters-data` named volume for `~/.critters/` (metrics.jsonl, state) — persists across container restarts
- `~/.config/gh` mounted read-only for GitHub CLI auth
- Port 3847 exposed for the health/dashboard server
- `restart: unless-stopped` for daemon-like behavior

### 4. `.github/workflows/release.yml` — Add Docker job

Add a `docker` job that runs after the existing `release` job:

```yaml
  docker:
    needs: release
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: write
    steps:
      - uses: actions/checkout@v4

      - name: Log in to GHCR
        uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Extract version
        id: version
        run: echo "version=${GITHUB_REF_NAME#v}" >> "$GITHUB_OUTPUT"

      - name: Docker meta
        id: meta
        uses: docker/metadata-action@v5
        with:
          images: ghcr.io/ack-ventures/critters
          tags: |
            type=semver,pattern={{version}}
            type=semver,pattern={{major}}.{{minor}}
            type=raw,value=latest

      - name: Build and push
        uses: docker/build-push-action@v6
        with:
          context: .
          push: true
          tags: ${{ steps.meta.outputs.tags }}
          labels: ${{ steps.meta.outputs.labels }}
          build-args: |
            VERSION=${{ steps.version.outputs.version }}
```

**Key decisions:**
- Runs after `release` (not `build`) so the GitHub Release already exists when the image is pushed
- Pushes to `ghcr.io/ack-ventures/critters` (GitHub Container Registry)
- Tags: `v0.8.1` → `0.8.1`, `0.8`, and `latest`
- Uses standard Docker GitHub Actions (login, metadata, build-push)
- Only triggers on `v*` tags (inherited from the workflow's `on.push.tags` trigger)
- Passes `VERSION` build arg with the `v` prefix stripped (matching the existing release.yml pattern at line 38)

## Files to Modify

### 1. `src/index.ts` — Skip file logging when `--json-logs` is used

**The problem:** With `--no-tmux`, `initFileLogging()` is always called (line 275-276), which directs all logs to `~/.critters/critters.log` instead of stdout/stderr. This means `docker compose logs -f` shows nothing.

**The fix:** When `--json-logs` is combined with `--no-tmux`, skip `initFileLogging()`. The JSON log functions in `src/logger.ts` already handle stdout/stderr output when `logFile` is null (lines 157-161). This makes `--json-logs` the natural choice for containerized deployments.

Change at line 275-277 from:
```typescript
  if (noTmux) {
    initFileLogging(config.maxLogSizeMb);
  }
```

To:
```typescript
  if (noTmux && !jsonLogs) {
    initFileLogging(config.maxLogSizeMb);
  }
```

This is a one-line change. When `--json-logs` is set, logs go to stdout (info/warn) and stderr (errors) in structured JSON format, which is the standard for containerized applications. When `--no-tmux` is used without `--json-logs`, behavior is unchanged (logs to file).

## Dependencies / Setup

- No new runtime dependencies for the host
- One small source change in `src/index.ts` (one-line conditional change to skip file logging when `--json-logs` is set)
- The `claude` CLI requires `ANTHROPIC_API_KEY` env var (recommended for Docker) or auth tokens in `~/.claude/`
- The `gh` CLI requires auth tokens in `~/.config/gh/` (mounted as a volume)
- SSH keys in `~/.ssh/` are needed for SSH-based git clone URLs

## Architecture Notes

- The critters daemon already fully supports `--no-tmux` mode, which uses `spawnClaudeSubprocess()` (direct Bun subprocess) instead of `spawnClaude()` (tmux pane). This is the correct mode for containers.
- The compiled Bun binary requires glibc, so Alpine-based images won't work — `debian:bookworm-slim` is the right choice.
- The `workDir` defaults to `/tmp/critters-work` inside the container, which is fine for ephemeral task directories. If persistence is needed, it can be mounted as a volume.
- Config loading (`src/config.ts`) searches `./critters.config.yaml` first, then `~/.critters/config.yaml`. The volume mount of `./critters.config.yaml:/app/critters.config.yaml:ro` works because `WORKDIR` is `/app`.
- The `.env` fallback loader (`src/env.ts`) loads from `~/.critters/.env` if CWD `.env` doesn't exist, but `env_file: .env` in docker-compose passes vars directly as env vars, so `.env` file loading is not needed inside the container.
- The container runs as root. This simplifies volume mount paths (`/root/.ssh`, `/root/.config/gh`, etc.) and avoids UID/GID mapping issues. Adding a non-root user is a future improvement.
- Multi-platform Docker builds (amd64 + arm64) are deferred — the initial image targets `linux/amd64` only (CI runs on `ubuntu-latest`). Can be added later with `docker/build-push-action`'s `platforms` parameter + QEMU. The README notes this limitation for ARM64 users.
- Auto-update is disabled via `--skip-update` — Docker images should be updated by pulling a new image, not by in-place binary replacement.

## Testing Approach

1. **Build the image locally:**
   ```bash
   docker build -t critters .
   ```
   Verify the build completes without errors.

2. **Verify runtime tools are available:**
   ```bash
   docker run --rm critters claude --version
   docker run --rm critters gh --version
   docker run --rm critters git --version
   docker run --rm critters jq --version
   ```

3. **Run with docker-compose:**
   ```bash
   docker compose up
   ```
   With a valid `.env` and `critters.config.yaml`, verify:
   - The daemon starts and JSON logs appear in `docker compose logs -f`
   - Health endpoint responds: `curl http://localhost:3847/healthz`
   - A poll cycle runs (visible in logs)

4. **Verify prerequisites check passes:**
   The `checkPrerequisites()` function in `src/prerequisites.ts` checks for `claude --version` and `gh auth status`. Both must work inside the container. `gh auth status` requires the `~/.config/gh` volume mount with valid auth tokens.

5. **CI verification:**
   - The existing CI (`ci.yml`) is unaffected — it doesn't build Docker images
   - The new Docker job in `release.yml` only runs on tag pushes, so it won't interfere with PR CI
