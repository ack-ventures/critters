# ACK-137: Add missing URL validation and integration tests for checksum verification

## Summary

Two changes needed:

1. **URL validation gap**: In `src/updater.ts`, the checksum file's `browser_download_url` (line 212) is fetched without validation. The binary's URL is validated at line 188 with `isAllowedDownloadUrl()` — the same check must be applied to the checksum URL.

2. **Missing integration tests**: The `makeRelease()` helper in `src/__tests__/updater.test.ts` doesn't include a `checksums-sha256.txt` asset, so all existing `checkForUpdate()` tests skip checksum verification. A new test block is needed.

## Files to modify

### 1. `src/updater.ts`

**Change**: Add URL validation for the checksum file download URL, following the existing pattern at lines 188–193.

Insert after line 211 (inside the `if (checksumAsset && typeof checksumAsset.browser_download_url === "string")` block), before the `fetch` call on line 212:

```typescript
    if (!isAllowedDownloadUrl(checksumAsset.browser_download_url)) {
      let hostname = "unknown";
      try { hostname = new URL(checksumAsset.browser_download_url).hostname; } catch {}
      printError(`Update aborted: checksum URL points to unexpected domain: ${hostname}`);
      return;
    }
```

This is the exact same pattern used for the binary URL at lines 188–193, with the error message adjusted to say "checksum URL" for clarity.

### 2. `src/__tests__/updater.test.ts`

**Changes**:

#### a. Add `createHash` import

Add `createHash` from `"node:crypto"` to the existing `node:fs` import line area (top of file).

#### b. Add a `makeReleaseWithChecksum()` helper

Create a helper that extends the existing `makeRelease()` pattern to include the checksum asset:

```typescript
function makeReleaseWithChecksum(version: string, checksumContent: string) {
  return {
    tag_name: `v${version}`,
    assets: [
      {
        name: `critters-${process.platform}-${process.arch}`,
        browser_download_url: "https://objects.githubusercontent.com/download/critters",
      },
      {
        name: "checksums-sha256.txt",
        browser_download_url: "https://objects.githubusercontent.com/download/checksums-sha256.txt",
      },
    ],
    _checksumContent: checksumContent,
  };
}
```

The `_checksumContent` field is a helper convention — the mock fetch functions will use it to return the correct content when the checksum URL is fetched.

#### c. Add a helper to compute the correct checksum string

```typescript
function makeChecksumFile(content: string): string {
  const hash = createHash("sha256").update(content).digest("hex");
  const binaryName = `critters-${process.platform}-${process.arch}`;
  return `${hash}  ${binaryName}\n`;
}
```

#### d. Add new describe block: `"checkForUpdate checksum verification"`

Four tests:

**Test 1: Checksum valid → update proceeds normally**
- Use `makeReleaseWithChecksum("2.0.0", makeChecksumFile(UPDATED_CONTENT))`
- Mock fetch: API returns the release, binary URL returns `UPDATED_CONTENT`, checksum URL returns the checksum content
- Assert: binary is updated, "Checksum verified (SHA-256)" appears in logs, no errors

**Test 2: Checksum mismatch → update aborts, binary unchanged**
- Use `makeReleaseWithChecksum("2.0.0", "badhash  critters-...\n")`
- Mock fetch: API returns the release, binary URL returns `UPDATED_CONTENT`, checksum URL returns wrong hash
- Assert: binary still contains `ORIGINAL_CONTENT`, error log contains "checksum mismatch"

**Test 3: Checksum file download fails (HTTP error) → update aborts**
- Use `makeReleaseWithChecksum("2.0.0", "...")` (content doesn't matter since fetch will fail)
- Mock fetch: API returns the release, binary URL returns `UPDATED_CONTENT`, checksum URL returns HTTP 500
- Assert: binary still contains `ORIGINAL_CONTENT`, error log contains "failed to download checksum file"

**Test 4: Checksum file missing from release → warning logged, update proceeds**
- Use existing `makeRelease("2.0.0")` (no checksum asset)
- Use existing `mockFetchSuccess("2.0.0")`
- Assert: binary is updated to `UPDATED_CONTENT`, log contains "checksums-sha256.txt not found in release, skipping verification"

**Test 5: Checksum URL points to disallowed domain → update aborts**
- Create a release where the checksum asset has `browser_download_url: "https://evil.com/checksums-sha256.txt"`
- Mock fetch: API returns the release, binary URL returns `UPDATED_CONTENT`
- Assert: binary still contains `ORIGINAL_CONTENT`, error log contains "checksum URL points to unexpected domain"

Each test will need its own mock fetch function (or a flexible shared one) that dispatches based on the URL being fetched to return the appropriate response for the API, binary download, and checksum download URLs.

## Testing approach

- All tests use the existing `beforeEach`/`afterEach` setup (temp dir, fake binary, log capture)
- Tests verify both the positive outcome (file content, log messages) and negative outcome (no file change, error messages)
- The mock fetch dispatches on URL pattern: `api.github.com` → release JSON, `download/critters` → binary content, `download/checksums` → checksum content
- Test 5 validates the new URL validation code added to `src/updater.ts`

## Dependencies

None — both changes are self-contained within the existing codebase.
