# ACK-200: Add Composable Skills Support to Phase Config

## Summary

Add an optional `skills` field to `PhaseConfig` that allows injecting reusable prompt fragments (markdown files) into any phase. Skills are appended to the phase prompt in order, with clear separators, supporting the same `{{var}}` substitution as prompts. This enables composable, shareable behaviors across critter types without duplicating prompt content.

### 2. `src/prompt-template.ts` — Resolve and append skill content

**Changes:**
- Add `basename` to the existing `join` import from `node:path`.
- Add a new exported `resolveSkills()` function that takes a `skills` array and `vars` record, reads each file, applies `{{var}}` substitution, and returns the concatenated content with separators.

**New function:**
```typescript
/**
 * Resolve skill files and return concatenated content with separators.
 * Each skill's content is appended with a separator like:
 *   ---
 *   ## Skill: <filename without path/extension>
 *   <content>
 */
export function resolveSkills(
  skills: string[] | undefined,
  vars: Record<string, string>,
): string {
  if (!skills || skills.length === 0) return "";

  const parts: string[] = [];
  for (const skillRef of skills) {
    const filePath = skillRef.startsWith("~")
      ? join(homedir(), skillRef.slice(1))
      : skillRef;

    if (!existsSync(filePath)) {
      throw new Error(`Skill file not found: ${filePath}`);
    }

    let content = readFileSync(filePath, "utf-8");

    // Apply {{var}} substitution
    for (const [key, value] of Object.entries(vars)) {
      content = content.replace(new RegExp(`\\{\\{${key}\\}\\}`, "g"), value);
    }

    // Extract skill name from filename (without path or extension)
    const skillName = basename(filePath).replace(/\.[^.]+$/, "");

    parts.push(`---\n\n## Skill: ${skillName}\n\n${content.trim()}`);
  }

  return "\n\n" + parts.join("\n\n");
}
```

## Edge Cases

1. **Empty `skills` array**: No-op, same as omitted — handled by `resolveSkills` returning empty string.
2. **Missing skill file**: Error at validation time (`critters validate`) and at runtime (`resolveSkills` throws).
3. **Skills on built-in phases**: Fully supported — skills are appended after the built-in prompt content.
4. **`~` expansion**: Uses `homedir()` + `join()`, consistent with existing prompt resolution.
5. **Relative paths**: Resolved relative to CWD (same as custom prompts). For repo-relative skills (`.critters/skills/`), these resolve correctly at runtime since the runner's CWD is the work directory after clone. At validation time (`critters validate`), relative paths are checked against the daemon's CWD — repo-relative skills may produce false validation errors. This mirrors existing behavior for custom prompt paths. Recommend using `~`-prefixed or absolute paths for non-repo skills.
6. **Variable substitution**: Same `{{var}}` mechanism as prompts, applied per-skill.
7. **Skill ordering**: Skills are appended in array order, which is deterministic from YAML.
8. **Synthesized default types**: `synthesizeDefaultTypes()` does not set skills, so the field is undefined — correctly handled as no-op by `resolveSkills`.

## Testing Approach

1. **Unit tests** for `resolveSkills()`:
   - Empty/undefined skills array returns empty string
   - Single skill file resolves correctly with separator
   - Multiple skills concatenated in order
   - `{{var}}` substitution works within skills
   - Missing file throws descriptive error
   - `~` expansion works

2. **Integration validation**: Add skill paths to the test config at `test-configs/custom-types.yaml` and verify `critters validate` catches missing files and passes with valid ones.

3. **Type checking**: Run `bun x tsc --noEmit` to verify all type changes compile.
