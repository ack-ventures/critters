# ACK-250: Dashboard — Show Estimated Time Remaining for Active Critters

## Summary

Add an "ETA" column to the active critters table in the dashboard that shows estimated time remaining based on historical average duration for that critter type. The estimate is computed as `avgDuration - elapsed`. Color-coded green/yellow/red to indicate on-track/warning/overdue. Shows "—" when fewer than 3 historical data points exist for a type.

All changes are in a single file: `src/dashboard.ts`. The metrics data (`allMetrics`) is already loaded at the top of `renderDashboard()` (line 162) and contains `critterType`, `duration`, and `repoUrl` fields on completed events. The `ActiveCritterDetail` interface already has `critterType` (line 134 of `src/types.ts`).

## Files to Modify

### 1. `src/dashboard.ts` — Compute average durations and add ETA column

#### a. Compute average duration per critter type (after line 186)

After the existing summary stats block (which already computes `avgDuration` globally), add a helper that groups completed task metrics by `critterType` and computes per-type average durations:

```typescript
// Compute average duration per critter type for ETA estimates
const avgDurationByType = new Map<string, number>();
{
  const typeAccum = new Map<string, { total: number; count: number }>();
  for (const m of allMetrics) {
    if (m.event !== "task_completed" && m.event !== "review_completed") continue;
    if (m.duration == null || Number.isNaN(m.duration)) continue;
    const t = m.critterType ?? (m.event.startsWith("review_") ? "review" : "create");
    const acc = typeAccum.get(t);
    if (acc) {
      acc.total += m.duration;
      acc.count++;
    } else {
      typeAccum.set(t, { total: m.duration, count: 1 });
    }
  }
  for (const [t, acc] of typeAccum) {
    if (acc.count >= 3) {
      avgDurationByType.set(t, acc.total / acc.count);
    }
  }
}
```

Key decisions:
- Uses `allMetrics` (unfiltered) rather than `filteredMetrics` so the ETA isn't affected by the type filter dropdown — we always want the full history for accurate averages.
- Only counts successful completions (`task_completed`, `review_completed`), not failures, since failed tasks have abnormal durations.
- Requires `>= 3` data points before showing an estimate (per the task spec).
- Groups by `critterType` only (not by repo). Repo-level grouping would fragment the data too much for most deployments and lead to more "—" results. The type-level average is a good balance.

const critterType = d.critterType ?? "create";
const avgDur = avgDurationByType.get(critterType);
let etaCell: string;
if (avgDur == null) {
  etaCell = `<td style="color: var(--text-dim)">\u2014</td>`;

  const remaining = avgDur - elapsedMs;
  if (remaining < 0) {

## Edge Cases

1. **No historical data for a type**: Shows "—" in dim text. Happens for new/rare critter types or fresh deployments.
2. **Fewer than 3 data points**: Also shows "—" to avoid misleading estimates from small samples.
3. **Overdue (elapsed > avg)**: Shows "overdue" in red with bold weight. This is informational — the task may still complete normally since averages are just averages.
4. **Missing `critterType` on `ActiveCritterDetail`**: Falls back to `"create"` (same pattern used elsewhere in the dashboard, e.g., `inferType()`).
5. **Auto-refresh**: The dashboard already auto-refreshes every 30s, so ETA values update automatically.
