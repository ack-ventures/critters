# ACK-182: Salvage partial work on critter timeout

## Summary

When a critter times out, the abort signal fires but the catch block treats it identically to any other error. The `salvagePartialProgress` function already exists and handles auto-committing, pushing WIP branches, and creating draft PRs. However, several gaps remain:

1. **No timeout detection** — the catch block doesn't distinguish timeout from other failures, so the issue comment is generic
2. **Salvage restricted to `create` type** — any critter type with `repo.branch` could benefit from salvage
3. **No PR comment on timeout** — if a PR already exists (e.g., from a prior attempt or salvage), no comment is added to the PR itself
4. **No timeout-specific context** — the failure comment doesn't mention it was a timeout or what was accomplished

## Files to modify

### 1. `src/unified-spawner.ts` — Enhance timeout handling in `runTask`

**a. Add a `timedOut` flag to distinguish timeout from graceful shutdown (lines ~196-201)**

The `stop()` method also calls `abortController.abort()` on all active controllers, so we can't rely on `abortController.signal.aborted` alone. Add a dedicated flag:

```typescript
let timedOut = false;
const timeout = setTimeout(() => {
  timedOut = true;
  abortController.abort();
}, critterType.timeoutMinutes * 60 * 1000);
```

**b. Detect timeout in the catch block (lines ~433-434)**

Use the `timedOut` flag instead of `abortController.signal.aborted`:

```typescript
const error = timedOut
  ? `Timed out after ${critterType.timeoutMinutes} minutes`
  : (err instanceof Error ? err.message : String(err));
```

**c. Extend salvage to all types with `repo.branch` (lines ~449-460)**

Currently the salvage block is gated on `critterType.name === "create"`. Change to check the actual condition:

```typescript
let salvageResult: { prUrl?: string; branchPushed?: boolean } = {};
if (critterType.repo.branch && branch) {
  salvageResult = await salvagePartialProgress(workDir, branch, task.identifier, task.title, task.repoUrl);
  if (salvageResult.prUrl) {
    salvageInfo = `\n\nPartial progress was saved as a draft PR: ${salvageResult.prUrl}`;
    logTask(task.identifier, `Salvaged partial progress — draft PR: ${salvageResult.prUrl}`);
  } else if (salvageResult.branchPushed) {
    salvageInfo = `\n\nPartial commits were pushed to branch \`${branch}\`.`;
    logTask(task.identifier, `Salvaged partial progress — branch pushed: ${branch}`);
  }
}
```

**d. Add PR comment on timeout (new block after salvage)**

When a timeout occurs and a PR URL is available (either from `task.prUrl` for review types, or from the salvage result), post a comment on the PR:

```typescript
if (timedOut) {
  const prUrlForComment = salvageResult.prUrl ?? task.prUrl;
  if (prUrlForComment) {
    await addPrTimeoutComment(workDir, prUrlForComment, task.identifier, critterType.timeoutMinutes, task.repoUrl);
  }
}
```

**e. Enrich the issue failure comment for timeouts (lines ~481-494)**

Prefix the failure comment with timeout-specific context when `timedOut` is true:

```typescript
let failComment = timedOut
  ? `Critter timed out after ${critterType.timeoutMinutes} minutes.`
  : `${isReviewType ? "Review critter" : "Critter"} failed after ${totalDuration}: ${error}`;
```

The rest of the comment (salvage info, log attachments, checkpoint status) remains the same.

### 2. `src/unified-spawner.ts` — Add `addPrTimeoutComment` helper function

Add a new exported function near `salvagePartialProgress`:

```typescript
export async function addPrTimeoutComment(
  workDir: string,
  prUrl: string,
  identifier: string,
  timeoutMinutes: number,
  repoUrl?: string,
): Promise<void> {
  try {
    const ownerRepo = repoUrl ? extractOwnerRepo(repoUrl) : null;
    const repoArgs = ownerRepo ? ["--repo", ownerRepo] : [];
    const prNumber = prUrl.match(/\/pull\/(\d+)/)?.[1];
    if (!prNumber) return;

    const body = `**Timeout**: Critter \`${identifier}\` timed out after ${timeoutMinutes} minutes. Partial work may have been committed to this branch. See the linked issue for details.`;
    await runCommand("gh", ["pr", "comment", prNumber, "--body", body, ...repoArgs], { cwd: workDir });
  } catch (err) {
    logTaskError(identifier, `Failed to comment on PR: ${err}`);
  }
}
```

The `stop()` method calls `abort()` without setting this flag, so the two cases are now distinguishable. See section 1a.
