# ACK-249: Dashboard Browser Notifications for Critter Events

## Summary

Add opt-in browser desktop notifications to the critters dashboard so users get alerted when critter events occur (task completed, task failed, needs human review) without actively watching the tab.

All changes are in a single file: `src/dashboard.ts`. The feature uses the browser Notifications API, localStorage for persistence, and the existing 30s auto-refresh cycle to detect new events by comparing the `/metrics` endpoint data.

## File to Modify

### `src/dashboard.ts`

#### 1. Add notification toggle button in header (near line 477)

The green dot (`#notif-dot`) is visible when notifications are enabled.

#### 2. Add notification JavaScript block (new `<script>` section after the refresh script)

A new IIFE that handles notification logic:

**State management** — Use `window._notifState` to persist across script re-executions (since the dashboard replaces `body.innerHTML` and re-runs scripts on every 30s refresh):

```javascript
if (!window._notifState) {
  window._notifState = {
    enabled: localStorage.getItem('critters-notif') === 'on',
    lastSeenTimestamp: localStorage.getItem('critters-notif-last-seen') || new Date().toISOString()
  };
}
```

**Toggle button click handler:**
1. If `Notification.permission === 'default'`, call `Notification.requestPermission()`
2. If permission granted, toggle `_notifState.enabled` and update `localStorage`
3. If permission denied, show a brief inline message
4. Update dot visibility

**On each script execution (i.e., each refresh):**
1. Update the dot visibility based on `_notifState.enabled`
2. If notifications are not enabled, skip event checking
3. Fetch `/metrics` (the existing endpoint returning last 100 events as JSON)
4. Filter events with `timestamp > _notifState.lastSeenTimestamp`
5. For each new event, check the `event` field:
   - `task_completed` → `"✅ {identifier} completed — PR created"` (or `"completed"` if no `prUrl`)
   - `task_failed` → `"❌ {identifier} failed"`
   - `review_failed` with `outcome === 'needs_changes'` → `"👀 {identifier} needs human review"` (Note: the metrics system records this as `review_completed` with `outcome: "needs_changes"` or similar — will check exact event shape)
6. Update `_notifState.lastSeenTimestamp` to the latest event timestamp
7. Persist the last-seen timestamp to `localStorage`

**Notification click handler:**
- `notification.onclick`: call `window.focus()` and navigate to `/dashboard/{identifier}` (the existing issue detail page)

**Key design decisions:**
- Fetching `/metrics` on every refresh is lightweight (already cached 30s server-side) and avoids needing a new endpoint
- Using `window._notifState` survives the innerHTML replacement + script re-execution pattern
- `lastSeenTimestamp` is initialized to `new Date().toISOString()` on first enable, preventing historical notifications
- The notification check runs as part of the script re-execution triggered by `doRefresh()`, so it naturally fires every 30 seconds

#### 3. Detecting "needs human review" events

Looking at the metrics event types in `src/metrics.ts`, the relevant events are:
- `task_completed` — with optional `prUrl` field
- `task_failed` — with optional `error` field
- `review_completed` with `outcome` field — when outcome indicates needs_changes

The `review_completed` event's `outcome` field will contain `"needs_changes"` based on the review runner logic in `src/runner/review.ts`. This maps to the "Needs human review" notification.

#### 4. Complete script structure

```javascript
(function() {
  // Initialize state (persists across refresh re-executions)
  if (!window._notifState) {
    window._notifState = {
      enabled: localStorage.getItem('critters-notif') === 'on',
      lastSeenTimestamp: localStorage.getItem('critters-notif-last-seen') || new Date().toISOString()
    };
  }

  var state = window._notifState;
  var btn = document.getElementById('notif-btn');
  var dot = document.getElementById('notif-dot');

  // Update UI to reflect current state
  function updateUI() {
    if (dot) dot.style.display = state.enabled ? 'inline-block' : 'none';
    if (btn) btn.title = state.enabled ? 'Notifications enabled (click to disable)' : 'Enable browser notifications';
  }
  updateUI();

  // Toggle handler
  if (btn) {
    btn.addEventListener('click', function() {
      if (!('Notification' in window)) return;

      if (Notification.permission === 'default') {
        Notification.requestPermission().then(function(perm) {
          if (perm === 'granted') {
            state.enabled = true;
            state.lastSeenTimestamp = new Date().toISOString();
            localStorage.setItem('critters-notif', 'on');
            localStorage.setItem('critters-notif-last-seen', state.lastSeenTimestamp);
            updateUI();
          }
        });
      } else if (Notification.permission === 'granted') {
        state.enabled = !state.enabled;
        localStorage.setItem('critters-notif', state.enabled ? 'on' : 'off');
        if (state.enabled) {
          state.lastSeenTimestamp = new Date().toISOString();
          localStorage.setItem('critters-notif-last-seen', state.lastSeenTimestamp);
        }
        updateUI();
      }
      // If 'denied', do nothing — browser blocked notifications
    });
  }

  // Check for new events (runs on each refresh)
  if (state.enabled && Notification.permission === 'granted') {
    fetch('/metrics')
      .then(function(res) { return res.json(); })
      .then(function(events) {
        var newEvents = events.filter(function(e) {
          return e.timestamp > state.lastSeenTimestamp;
        });

        newEvents.forEach(function(e) {
          var title = '';
          var id = e.identifier || e.issueId || 'Unknown';
          var tag = 'critters-' + id + '-' + e.event;

          if (e.event === 'task_completed') {
            title = '✅ ' + id + (e.prUrl ? ' completed — PR created' : ' completed');
          } else if (e.event === 'task_failed') {
            title = '❌ ' + id + ' failed';
          } else if (e.event === 'review_completed' && e.outcome === 'needs_changes') {
            title = '👀 ' + id + ' needs human review';
          } else {
            return; // Skip other event types
          }

          var notif = new Notification(title, {
            body: e.critterType ? 'Type: ' + e.critterType : '',
            tag: tag,
            icon: '🐛'
          });
          notif.onclick = function() {
            window.focus();
            window.location.href = '/dashboard/' + id;
            notif.close();
          };
        });

        // Update last seen to most recent event timestamp
        if (events.length > 0) {
          var latest = events.reduce(function(max, e) {
            return e.timestamp > max ? e.timestamp : max;
          }, state.lastSeenTimestamp);
          state.lastSeenTimestamp = latest;
          localStorage.setItem('critters-notif-last-seen', latest);
        }
      })
      .catch(function() { /* ignore fetch errors */ });
  }
})();
```

## Dependencies

None — uses only the browser Notifications API and the existing `/metrics` endpoint.

## Testing Approach

1. **Manual testing**: Open dashboard, click bell icon, grant permission, verify dot appears
2. **Notification firing**: Trigger a critter task (or mock a metrics entry), wait for refresh, verify desktop notification appears
3. **Click-to-navigate**: Click notification, verify tab focuses and navigates to issue detail page
4. **Persistence**: Refresh page, verify notification state is restored from localStorage
5. **No historical notifications**: Enable notifications, verify only new events (after enable timestamp) trigger notifications
6. **Permission denied**: Block notifications in browser, verify button does nothing (no errors)
7. **Type check**: Run `bun run typecheck` to verify no TypeScript errors (the notification code is inline JS in template strings, so minimal TS impact)

## Edge Cases

- **Browser without Notification API**: The `'Notification' in window` check guards against this
- **Multiple tabs**: The `tag` field on notifications prevents duplicates for the same event across tabs
- **Script re-execution on refresh**: `window._notifState` initialization is guarded by `if (!window._notifState)` so state persists
- **Large time gaps**: If the dashboard tab is backgrounded for a long time, only the last 100 events from `/metrics` are checked — old events beyond that window are naturally skipped
- **Notification permission revoked**: The `Notification.permission === 'granted'` check before sending prevents errors
