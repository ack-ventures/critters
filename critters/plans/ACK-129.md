# ACK-129: Fix Dashboard Duration, Charts, and Missing Reviews

## Summary

Three bugs in `src/dashboard.ts`:

1. **Duration displayed in milliseconds instead of minutes** — `formatDuration()` treats its input as minutes, but `recordMetric()` passes `Date.now() - taskStart` (milliseconds). Durations show as e.g. "450511m" instead of "~8m".
2. **Bar charts render as empty** — `.bar-stack` CSS is missing `height: 100%`, so percentage-based bar heights collapse to 0px.
3. **Reviews missing from dashboard** — Only `task_completed` and `task_failed` events are filtered for display. `review_completed` and `review_failed` events are recorded but ignored in summary stats, charts, and the activity table.

## Files to Modify

### 1. `src/dashboard.ts`

#### Fix 1: Duration conversion (line 14-18)

Remove the local `formatDuration` function entirely and import the existing `formatDuration` from `src/utils.ts` (line 42), which already correctly handles milliseconds:

```typescript
// utils.ts formatDuration(ms: number): string
// - < 60s → "Xs"
// - < 60m → "Xm Ys"
// - ≥ 60m → "Xh Ym"
```

The dashboard's local version will be replaced by adding to the import section:

```typescript
import { formatDuration } from "./utils.js";
```

And removing the local `formatDuration` function (lines 14-18).

The call site on line 310 (`formatDuration(m.duration)`) passes `number | undefined`, but `utils.formatDuration` expects `number`. The call sites already guard against undefined via the `formatDuration` wrapper. We need a small inline wrapper or keep a thin dashboard-specific version that handles `undefined`:

```typescript
function fmtDuration(ms: number | undefined): string {
  if (ms == null || Number.isNaN(ms)) return "\u2014";
  return formatDuration(ms);
}
```

Then rename all call sites from `formatDuration` to `fmtDuration` within `dashboard.ts` (lines 207 and 310).

#### Fix 2: Bar chart CSS (line 146)

Add `height: 100%` to the `.bar-stack` CSS rule. Change:

```css
.bar-stack { display: flex; flex-direction: column-reverse; width: 100%; align-items: center; }
```

To:

```css
.bar-stack { display: flex; flex-direction: column-reverse; width: 100%; align-items: center; height: 100%; }
```

#### Fix 3: Include review events (lines 80-82, 51, 53-76, 86-91, 94, 305-323)

**a. Filter (`taskMetrics`, line 80-82):** Add `review_completed` and `review_failed` to the filter:

```typescript
const taskMetrics = allMetrics.filter(
  (m) => m.event === "task_completed" || m.event === "task_failed" ||
         m.event === "review_completed" || m.event === "review_failed",
);
```

**b. Summary stats (lines 86-87):** Update succeeded/failed counts to include review events:

```typescript
const succeeded = taskMetrics.filter(
  (m) => m.event === "task_completed" || m.event === "review_completed",
).length;
```

The `failed` calculation (`totalTasks - succeeded`) already works correctly since it's derived.

**c. `computeDailyStats` (line 66):** Update the event filter inside `computeDailyStats` to also count review events:

```typescript
if (m.event !== "task_completed" && m.event !== "task_failed" &&
    m.event !== "review_completed" && m.event !== "review_failed") continue;
```

And update the completed/failed bucketing:

```typescript
if (m.event === "task_completed" || m.event === "review_completed") stat.completed++;
else stat.failed++;
```

**d. Activity table status text (lines 307-309):** Show distinguishable status for reviews vs tasks:

```typescript
const isReview = m.event === "review_completed" || m.event === "review_failed";
const isOk = m.event === "task_completed" || m.event === "review_completed";
const statusClass = isOk ? "status-ok" : "status-fail";
const statusText = isReview
  ? (isOk ? "Review Completed" : "Review Failed")
  : (isOk ? "Completed" : "Failed");
```
