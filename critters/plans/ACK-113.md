# ACK-113: Graceful partial failure handling

## Summary

When a critter fails mid-execution but has already made commits or created a draft PR, preserve and surface that progress instead of silently cleaning it up. Before marking the issue as "Critter Failed", the error handler should check for partial work (commits on the branch, existing PRs), attempt to push the branch and/or create a draft PR, and include that information in the failure comment on Linear.

The issue still moves to "Critter Failed" in all cases — but the comment and draft PR make it easy for a human to pick up where the critter left off.

## Files to modify

### 1. `src/spawner.ts` — Add salvage logic to the catch block in `runTask()`

**Add a new `salvagePartialProgress()` async helper function** (private method or module-level function, matching the existing pattern of `detectPr()` and `uploadFailureLogs()` as module-level functions):

```typescript
async function salvagePartialProgress(
  workDir: string,
  branch: string,
  identifier: string,
  title: string,
): Promise<{ prUrl?: string; branchPushed?: boolean }>
```

This function wraps all salvage logic in a try/catch so it never throws (returning `{}` on failure). Internally it:

1. **Auto-commit uncommitted changes** — call `hasUncommittedChanges(workDir)` and if true, call `autoCommit(workDir, identifier, ...)` to capture any in-progress work. This should be wrapped in its own try/catch so a failed commit doesn't prevent the rest of salvage.

2. **Check for commits on the branch** — call `hasCommitsOnBranch(workDir, branch, identifier)`. If no commits exist, return `{}` immediately (nothing to salvage).

3. **Check for an existing PR** — use `runCommand("gh", ["pr", "list", "--head", branch, "--json", "url", "--limit", "1"], { cwd: workDir })`. If a PR already exists, return `{ prUrl: parsedUrl, branchPushed: true }`.

4. **Push the branch** — use `runCommand("git", ["push", "origin", branch], { cwd: workDir })`. If push fails, log the error and return `{}` (can't salvage without pushing).

5. **Create a draft PR** — use `runCommand("gh", ["pr", "create", "--draft", "--head", branch, "--title", `[${identifier}] ${title} (partial)`, "--body", "Critter failed mid-execution. See Linear issue for details."], { cwd: workDir })`. Parse the URL from stdout (gh outputs the URL on success). Return `{ prUrl, branchPushed: true }`.

6. If the draft PR creation fails, still return `{ branchPushed: true }` since the commits were pushed.

**Modify the catch block in `runTask()` (lines 254–291)**:

After the existing `logTaskError` call (line 256) and before `uploadFailureLogs` (line 271), insert a call to `salvagePartialProgress()`:

```typescript
// Attempt to salvage partial progress
const salvage = await salvagePartialProgress(workDir, branch, task.identifier, task.title);
if (salvage.prUrl) {
  logTask(task.identifier, `Salvaged partial progress — draft PR: ${salvage.prUrl}`);
} else if (salvage.branchPushed) {
  logTask(task.identifier, `Salvaged partial progress — branch pushed: ${branch}`);
}
```

## Edge cases handled

- **No commits on branch (failed during planning or early execution)**: `hasCommitsOnBranch` returns false → salvage returns `{}` → existing behavior unchanged.
- **Commits exist but push fails (network issue, auth)**: Push failure is caught → salvage returns `{}` → existing behavior unchanged.
- **PR already exists (critter created PR but failed during post-PR steps)**: Detected via `gh pr list` → returned as `{ prUrl }` → no duplicate PR created.
- **Draft PR creation fails**: Branch was still pushed → returned as `{ branchPushed: true }` → comment mentions branch.
- **Uncommitted changes exist**: Auto-committed before checking for commits, so partial work in the working tree is captured too. If auto-commit fails, we proceed anyway — any previously committed work is still salvageable.
- **Salvage itself throws**: Entire function is wrapped in try/catch → returns `{}` → doesn't mask original error.
- **Timeout abort**: The abort signal fires, the execution phase throws, and the catch block runs. The salvage logic uses `runCommand()` which spawns new processes not tied to the abort controller, so push/PR creation should work.
- **workDir doesn't exist or is corrupted**: Git commands will fail → caught by salvage try/catch → returns `{}`.

- **Test cases**:
  1. Returns `{}` when no commits on branch (mocks `hasCommitsOnBranch` → false)
  2. Returns `{ prUrl }` when a PR already exists (mocks `gh pr list` → returns PR)
  3. Returns `{ prUrl, branchPushed: true }` when push succeeds and draft PR is created (mocks `git push` → success, `gh pr create` → URL)

  6. Returns `{}` and doesn't throw when everything fails
  7. Attempts auto-commit when uncommitted changes exist before checking for commits

- **Integration testing**: Manual testing by running a critter against a repo with a task that will fail mid-execution (e.g., impossible requirement after some code changes), verifying:
