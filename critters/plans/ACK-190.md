**Stats section generation** — add a private `formatStatsSection` helper:

```ts
function formatStatsSection(stats: { name: string; durationMs: number; costUsd?: number }[]): string {
  const lines: string[] = ["## Critter Stats"];
  let totalMs = 0;
  let totalCost = 0;
  let hasCost = false;

  for (const phase of stats) {
    totalMs += phase.durationMs;
    if (phase.costUsd != null) {
      totalCost += phase.costUsd;
      hasCost = true;
    }
    const duration = formatDuration(phase.durationMs);
    const capitalizedName = phase.name.charAt(0).toUpperCase() + phase.name.slice(1);
    if (phase.costUsd != null) {
      lines.push(`- **${capitalizedName}**: ${duration} · $${phase.costUsd.toFixed(2)}`);
    } else {
      lines.push(`- **${capitalizedName}**: ${duration}`);
    }
  }

  // Total line (only if more than one phase)
  if (stats.length > 1) {
    const totalDuration = formatDuration(totalMs);
    if (hasCost) {
      lines.push(`- **Total**: ${totalDuration} · $${totalCost.toFixed(2)}`);
    } else {
      lines.push(`- **Total**: ${totalDuration}`);
    }
  }

  return lines.join("\n");
}
```

Import `formatDuration` from `../utils.js`.

**Updated body construction** in `updatePrWithPlan` — replace the simple `currentBody + plan` concatenation:

The existing error handling (log-and-return on failure, non-fatal) is preserved. The function already logs but does not throw on `gh pr edit` failure.

### 4. Move the `updatePrWithPlan` call from execution runner to `handleCreateSuccess`

**Why**: `updatePrWithPlan` is currently called inside `ExecutionPhaseRunner.run()` at line 73, which runs *before* `handleCreateSuccess`. At that point, only the execution phase's stats are available — not planning. Moving the call to `handleCreateSuccess` gives access to all phase stats.

**In `src/runner/execution.ts`**:
- Remove lines 71-74 (the `if (prUrl) { await updatePrWithPlan(...) }` block)
- Export the function (add `export` keyword)

**In `src/unified-spawner.ts`**:
- Import `updatePrWithPlan` from `./runner/execution.js`
- In `handleCreateSuccess`, call it early (after the status update but before metrics/hooks), wrapped in try/catch to keep it non-fatal:

```ts
try {
  await updatePrWithPlan(workDir, prUrl, task.identifier, allPhaseStats);
} catch (err) {
  logTaskError(task.identifier, `Failed to update PR description: ${err}`);
}
```

This positioning ensures that a failure in PR body update does not block status updates, Slack notifications, metrics recording, or hook triggering.

### 5. Handle edge case: stats without plan

The current `updatePrWithPlan` returns early if no plan file exists. Update the logic:

- Read the plan file — if missing, set `planContent` to empty string (don't return early)
- Build the new body with stats section (if stats available) + plan section (if plan available)
- Only skip the `gh pr edit` call if neither stats nor plan content is available
