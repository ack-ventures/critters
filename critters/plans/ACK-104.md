# ACK-104: Add tests for config loading

## Summary

Add a new test file `src/__tests__/config.test.ts` that tests `loadConfig` end-to-end — specifically the YAML parsing, default value application, environment variable loading, per-repo config parsing, and team repo fallback. The existing `src/config.test.ts` already covers `validateWorkDir`, `validateConfig`, `validateRepoUrls`, and `resolveConfigPath` thoroughly. This new file focuses on the integration-level `loadConfig` behavior that isn't yet tested.

## Files to create

### `src/__tests__/config.test.ts`

New test file using Bun's test framework (`bun:test`). Uses `createTempDir()` from `./helpers.ts` for isolated temp directories and `writeFileSync` to create YAML config files.

## Test cases

### 1. `loadConfig` with a valid, fully-specified config file

Write a temp YAML file with all fields explicitly set to non-default values. Call `loadConfig(path)`. Assert every field on the returned `Config` object matches the YAML values:
- `pollIntervalSeconds`, `concurrency`, `timeoutMinutes`, `triggerLabel`
- `maxPlanningTurns`, `maxExecutionTurns`, `tmuxSession`
- `workDir` (resolved through `realpathSync`)
- `defaultAllowedTools` array
- `linearApiKey` from `process.env.LINEAR_API_KEY`
- `slackWebhookUrl` from `process.env.SLACK_WEBHOOK_URL`
- `noTmux` defaults to `false`

### 2. `loadConfig` with missing optional fields — verify defaults

Write a minimal YAML with only the required field (`defaultAllowedTools`). Assert defaults:
- `pollIntervalSeconds` → 30
- `concurrency` → 2
- `timeoutMinutes` → 30
- `workDir` → `realpathSync("/tmp/critters-work")`
- `triggerLabel` → "Critter"
- `maxPlanningTurns` → 50
- `maxExecutionTurns` → 75
- `tmuxSession` → "critters"
- `repos` → empty object
- `teamRepos` → empty object
- `noTmux` → false

### 3. `loadConfig` with no config file — error handling

Call `loadConfig` with a path to a nonexistent file. Assert it throws (file not found from `readFileSync`).

### 4. `loadConfig` with `~/.critters/config.yaml` fallback

Use `process.chdir()` to a temp directory (no `critters.config.yaml` present). Create `~/.critters/config.yaml` (using a mock approach — or skip if the real home dir can't be safely written to). Since we can't safely write to the user's actual `~/.critters/`, test the `resolveConfigPath` logic indirectly:
- Verify that when `configPath` is explicitly passed, it uses that path (already shown by other tests).
- Verify that when no config exists at CWD or `~/.critters/`, the error message mentions both locations.

Note: The existing `resolveConfigPath` test in `src/config.test.ts` already covers the error case. We add a test that verifies the CWD fallback works: place a `critters.config.yaml` in a temp dir, `chdir` there, call `loadConfig()` without an explicit path.

### 5. Per-repo config — `repos` map with `url` and `extraAllowedTools`

Write YAML with multiple repo entries:
```yaml
repos:
  "proj-1":
    url: "git@github.com:org/repo-a.git"
    extraAllowedTools:
      - "Bash(python:*)"
      - "Bash(pip:*)"
  "proj-2":
    url: "https://github.com/org/repo-b.git"
```
Assert:
- `config.repos["proj-1"].url` is correct
- `config.repos["proj-1"].extraAllowedTools` equals `["Bash(python:*)", "Bash(pip:*)"]`
- `config.repos["proj-2"].url` is correct
- `config.repos["proj-2"].extraAllowedTools` defaults to `[]` (when omitted in YAML)

### 6. Team repo fallback — `teamRepos` map

Write YAML with `teamRepos` entries:
```yaml
teamRepos:
  "team-1": "git@github.com:org/default-repo.git"
  "team-2": "https://github.com/org/other-repo.git"
```
Assert:
- `config.teamRepos["team-1"]` and `config.teamRepos["team-2"]` have correct values
- Both entries are present

### 7. Environment variable handling

- **LINEAR_API_KEY present**: Set `process.env.LINEAR_API_KEY`, load config, assert `config.linearApiKey` matches.
- **LINEAR_API_KEY missing**: Delete `process.env.LINEAR_API_KEY`, attempt `loadConfig`, assert it throws `"LINEAR_API_KEY not set"`. Restore env var in cleanup.
- **SLACK_WEBHOOK_URL present**: Set it, load config, assert `config.slackWebhookUrl` matches.
- **SLACK_WEBHOOK_URL absent**: Ensure it's not set, load config, assert `config.slackWebhookUrl` is `undefined`.

### 8. CWD fallback resolution

- Create a temp dir, write `critters.config.yaml` inside it
- `chdir` to that temp dir
- Call `loadConfig()` without arguments
- Assert it loads successfully (resolves from CWD)
- Restore original CWD in `finally` block

## Setup and teardown

```typescript
import { afterEach, beforeEach, describe, expect, test } from "bun:test";
import { writeFileSync } from "node:fs";
import { realpathSync } from "node:fs";
import { createTempDir } from "./helpers.js";
import { loadConfig } from "../config.js";
```

- `beforeEach`: Create a temp dir via `createTempDir()`, set `process.env.LINEAR_API_KEY = "test-key"`
- `afterEach`: Call `cleanup()` from `createTempDir()`, restore any modified env vars, restore CWD if changed

## Dependencies

- No new dependencies required
- Uses existing `createTempDir()` helper from `src/__tests__/helpers.ts`
- Uses `bun:test` framework (already in project)
- Uses `writeFileSync` from `node:fs` for writing temp YAML files

## Testing approach

- Each test writes its own minimal YAML to a temp dir and passes the explicit path to `loadConfig()`
- Tests that check env var behavior save/restore env vars in beforeEach/afterEach
- Tests that use `process.chdir()` restore the original CWD in a `finally` block
- No interference with real user config (all paths are temp dirs with explicit `configPath` argument)
