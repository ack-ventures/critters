# ACK-110: Support custom prompt files in ~/.critters/ for planning, execution, and review

## Summary

Add support for optional custom prompt files in `~/.critters/` that get appended to the planning, execution, and review prompts. This allows users to provide extra context (coding conventions, architectural notes, tool preferences) without editing critters source code.

The three files are:
- `~/.critters/planning-prompt.md` → appended to `buildPlanningPrompt()`
- `~/.critters/execution-prompt.md` → appended to `buildExecutionPrompt()`
- `~/.critters/review-prompt.md` → appended to `buildReviewPrompt()`

## Files to modify

### 1. `src/prompt.ts` — Add helper + integrate into planning & execution prompts

**Add `readCustomPrompt()` helper:**
- Import `existsSync`, `readFileSync` from `node:fs`, `homedir` from `node:os`, `join` from `node:path`
- Add exported function `readCustomPrompt(filename: string): string | null`
  - Builds path: `join(homedir(), ".critters", filename)`
  - If file doesn't exist (`!existsSync`), return `null`
  - Read file with `readFileSync(path, "utf-8")`
  - If content is empty or whitespace-only (`.trim() === ""`), return `null`
  - Otherwise return the trimmed content

**Modify `buildPlanningPrompt()`:**
- After the existing return string is built, call `readCustomPrompt("planning-prompt.md")`
- If non-null, append `\n\n## Additional Context\n${content}` to the prompt string
- Approach: build into a `let prompt = ...` variable, conditionally append, then return

**Modify `buildExecutionPrompt()`:**
- Same pattern: call `readCustomPrompt("execution-prompt.md")`
- If non-null, append `\n\n## Additional Context\n${content}`

### 2. `src/review-prompt.ts` — Integrate into review prompt

**Modify `buildReviewPrompt()`:**
- Import `readCustomPrompt` from `./prompt.js`
- Call `readCustomPrompt("review-prompt.md")`
- If non-null, append `\n\n## Additional Context\n${content}` to the prompt string

### 3. `src/init.ts` — Create placeholder files during init

**Add prompt file creation to `runInit()`:**
- Define constants for the three prompt filenames and their placeholder content
- After the config file creation block (line 73), add a loop or three blocks that:
  - Check `existsSync` for each prompt file path
  - If it doesn't exist, write a placeholder using `writeFileSync`
  - Placeholder content: `<!-- Optional: Add extra context for the {phase} phase here. This content will be appended to the {phase} prompt. -->\n`

The three placeholder files and their comments:

## Edge cases handled

- **File doesn't exist**: `existsSync` returns false → `null` → no section appended
- **Empty file**: Content is empty string → trimmed is empty → `null` → no section appended
- **Whitespace-only file**: Trimmed is empty → `null` → no section appended
- **HTML comment only (placeholder)**: The placeholder `<!-- ... -->` is NOT whitespace-only, so it would be appended. However, this is acceptable — the HTML comment won't affect Claude's behavior. If we want to suppress it, we could strip HTML comments before the trim check, but that adds complexity for minimal benefit. The ticket says "empty custom file should not add an empty section" — a file with only an HTML comment is not empty, so appending it is correct behavior.
- **File read errors**: If `readFileSync` throws (e.g., permission denied), it should propagate. This is intentional — a user who creates a custom prompt file expects it to work, so a hard error is better than silent failure.

## Dependencies

- No new npm/bun dependencies needed
- Only uses Node.js built-ins: `fs`, `os`, `path`

- Add integration tests to existing `src/__tests__/review-prompt.test.ts`

- For testing the `build*Prompt` functions with custom content, we can either:
  - Use `Bun.spyOn` / `mock.module` to mock the `readCustomPrompt` import
  - Or write actual files to a temp dir and pass `baseDir` through (requires the functions to accept the parameter or use dependency injection)

  The simplest approach: since `build*Prompt` functions call `readCustomPrompt` internally, use `mock.module` from `bun:test` to mock `./prompt.js` exports for the review-prompt tests, and directly test `readCustomPrompt` with temp files for unit tests.
