# ACK-225: Add configurable work directory cleanup interval and stale threshold

## Summary

Work directory cleanup currently uses hardcoded thresholds that can be too aggressive for long-running tasks, and `critters clean` can delete directories belonging to active tasks. This plan adds two new config fields (`cleanupIntervalMinutes`, `cleanupStaleMinutes`) and makes `critters clean` aware of active critters via the health endpoint.

## Files to modify

### 1. `src/types.ts` — Add config fields

Add two optional fields to the `Config` interface:

```typescript
cleanupIntervalMinutes?: number;
cleanupStaleMinutes?: number;
```

Place them after `workDir` (line 36) to keep related fields grouped.

### 2. `src/config.ts` — Parse new fields

In `loadConfig()`, parse the new fields from YAML with defaults:

```typescript
cleanupIntervalMinutes: (yaml.cleanupIntervalMinutes as number) ?? undefined,
cleanupStaleMinutes: (yaml.cleanupStaleMinutes as number) ?? undefined,
```

Add validation in `validateConfig()`:
- `cleanupIntervalMinutes` must be > 0 if set
- `cleanupStaleMinutes` must be > 0 if set

### 3. `src/unified-spawner.ts` — Use config values

**`cleanupStale()` (line 133-137):**
Change from:

const maxTimeout = Math.max(...this.config.critterTypes.map(ct => ct.timeoutMinutes));
const maxAgeMinutes = maxTimeout + 30;

To:

### 4. `src/cli-clean.ts` — Use config and protect active dirs

**Use `cleanupStaleMinutes` from config (line 60):**

Replace the hardcoded `STALE_THRESHOLD_MS`:
```typescript
const STALE_THRESHOLD_MS = 60 * 60_000; // 60 minutes
```

With config-aware logic. Since `cli-clean.ts` uses `loadWorkDir()` (lightweight config loading), we need to also load the stale threshold. Two approaches:

**Approach: Add a `loadCleanConfig()` helper** that reads just `workDir` and `cleanupStaleMinutes` from the YAML config (similar to `loadWorkDir()` but returning both values). This avoids loading the full config (which requires env vars for provider credentials).

Add to `config.ts`:
```typescript
export function loadCleanConfig(configPath?: string): { workDir: string; cleanupStaleMinutes?: number; healthPort: number } {
  let resolved: string | undefined;
  try {
    resolved = resolveConfigPath(configPath);
  } catch {
    return { workDir: "/tmp/critters-work", healthPort: 3847 };
  }
  const raw = readFileSync(resolved, "utf-8");
  const yaml = parseYaml(raw) as Record<string, unknown>;
  const workDir = (yaml.workDir as string) ?? "/tmp/critters-work";
  validateWorkDir(workDir);
  const resolvedWorkDir = existsSync(workDir) ? realpathSync(workDir) : workDir;
  return {
    workDir: resolvedWorkDir,
    cleanupStaleMinutes: (yaml.cleanupStaleMinutes as number) ?? undefined,
    healthPort: (yaml.healthPort as number) ?? 3847,
  };
}
```

**Protect active dirs by querying `/healthz`:**

Before cleaning, attempt to fetch `http://localhost:<healthPort>/healthz` to get `activeCritterDetails`. Extract the `workDir` field from each active critter and skip those directories during cleanup.

```typescript
async function getActiveWorkDirs(healthPort: number): Promise<Set<string>> {
  const active = new Set<string>();
  try {
    const resp = await fetch(`http://localhost:${healthPort}/healthz`, { signal: AbortSignal.timeout(3000) });
    if (resp.ok) {
      const data = await resp.json() as { activeCritterDetails?: Array<{ workDir?: string | null }> };
      for (const d of data.activeCritterDetails ?? []) {
        if (d.workDir) active.add(d.workDir);
      }
    }
  } catch {
    // Daemon not running or unreachable — no protection available
  }
  return active;
}
```

In `runClean()`:
1. Replace `loadWorkDir(configPath)` with `loadCleanConfig(configPath)` to get `workDir`, `cleanupStaleMinutes`, and `healthPort`
2. Use `cleanupStaleMinutes` for the stale threshold (fall back to 60 minutes if not set)
3. Call `getActiveWorkDirs(healthPort)` and skip any directories whose full path matches an active work dir
4. Log a message when skipping active directories so the user knows why

Changes to directory listing output:
- Directories matching active work dirs get labeled "active (in-use)" instead of "active"/"stale"
- These are never included in `toRemove`, even with `--all`

### 5. `CLAUDE.md` — Update config reference table

Add two rows to the config table:

| Field | Default | Description |
|---|---|---|
| `cleanupIntervalMinutes` | 60 | How often periodic work directory cleanup runs (minutes) |
| `cleanupStaleMinutes` | `max(timeoutMinutes) + 30` | Age threshold (minutes) for considering work directories stale |

## Edge cases

1. **Daemon not running when `critters clean` is called**: The `/healthz` fetch will fail silently, and cleanup proceeds without active-dir protection (same as current behavior — acceptable since no daemon means no active tasks).
2. **`--all` flag with active dirs**: Even with `--all`, active work directories (confirmed via health endpoint) should be skipped. This is the key safety improvement.
3. **`cleanupStaleMinutes` not set**: Falls back to current behavior (`maxTimeout + 30` for periodic cleanup, 60 minutes for CLI).
4. **`cleanupIntervalMinutes` not set**: Falls back to current 60-minute interval.
5. **Health port is 0 (disabled)**: Skip the health endpoint query in `cli-clean.ts` — no active-dir protection available.

## Testing approach

1. **Unit-level verification**: Confirm `loadConfig()` correctly parses both new fields, including when omitted (defaults apply).
2. **Validation**: Confirm that negative or zero values for the new fields throw validation errors.
3. **`unified-spawner.ts`**: Verify that `cleanupStale()` uses `cleanupStaleMinutes` when set and falls back to `maxTimeout + 30` when not set. Verify `startPeriodicCleanup()` uses `cleanupIntervalMinutes`.
4. **`cli-clean.ts`**: Test that active work dirs from the health endpoint are skipped, and that `cleanupStaleMinutes` from config is respected.
5. **Integration**: Run `critters validate` with the new config fields to verify parsing works end-to-end.

## Dependencies

No new dependencies required. The `fetch` API is available globally in Bun.
