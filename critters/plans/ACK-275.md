# ACK-275: Tighten the README quickstart for first-time setup

## Summary

The "Development quick start" prerequisites line (README.md line 59) lists the Claude Code CLI as a prerequisite but does not indicate it must be authenticated. Meanwhile, `gh` CLI on the same line explicitly says "(authenticated)". A first-time developer could install Claude Code CLI, follow all the setup steps, run `bun start`, and hit a confusing auth error because they never ran `claude` interactively to authenticate.

The fix is to add "(authenticated)" to the Claude Code CLI prerequisite, matching the existing pattern used for `gh` CLI.

## Files to modify

### `README.md` (line 59)

**Before:**
```
**Prerequisites:** [Bun](https://bun.sh), [Claude Code CLI](https://docs.anthropic.com/en/docs/claude-code), [`gh` CLI](https://cli.github.com) (authenticated), `tmux`, `jq`
```

**After:**
```
**Prerequisites:** [Bun](https://bun.sh), [Claude Code CLI](https://docs.anthropic.com/en/docs/claude-code) (authenticated), [`gh` CLI](https://cli.github.com) (authenticated), `tmux`, `jq`
```

## Rationale

- The `.env.example` file explicitly notes that `ANTHROPIC_API_KEY` is "required for Claude Code CLI in Docker; interactive auth uses `~/.claude` instead" — confirming that dev-mode auth happens interactively, not via env var.
- The Docker section (line 98) calls out `ANTHROPIC_API_KEY` as an explicit requirement, but the dev quickstart relies on interactive auth with no mention of it.
- Adding "(authenticated)" is the minimal, consistent fix: it mirrors the `gh` CLI pattern already on the same line, and nudges the user to run `claude` once before starting the daemon.

## Dependencies / setup

None — this is a docs-only change to a single line.

## Testing approach
