# ACK-150: Fix dashboard chart rendering: z-index, responsiveness, and y-axis labels

## Summary

Three fixes to the dashboard charts in `src/dashboard.ts`:

1. **Tooltip z-index bug** — bar chart tooltips (both `.bar[data-tooltip]:hover::after` with `z-index: 10` and `.bar-group[data-tooltip]:hover::after` with `z-index: 20`) render behind adjacent chart cards because the tooltips' z-index values only apply within the `.chart-card` stacking context.
2. **Narrow viewport handling** — x-axis labels overlap and bars get cramped at small widths.
3. **Y-axis label rounding** — y-axis shows exact max values instead of clean round numbers; no mid-point label.

## Files to Modify

- `src/dashboard.ts` — all changes are in this single file.

## Detailed Changes

### 1. Tooltip z-index fix

**Problem:** Both `.bar[data-tooltip]:hover::after` (z-index: 10, line 169) and `.bar-group[data-tooltip]:hover::after` (z-index: 20, line 185) have z-index values that only stack within their `.chart-card` parent. Adjacent chart cards in the CSS grid can overlap these tooltips.

**Fix:** Add a CSS rule so the hovered chart card elevates above its siblings:

```css
.chart-card:hover { z-index: 10; position: relative; }
```

This is added right after the existing `.chart-card` rule (line 153). Both tooltip pseudo-elements (`.bar` and `.bar-group`) will now render above adjacent cards because their containing `.chart-card` sits on top during hover.

### 2. Responsive chart handling

**Problem:** At narrow widths, x-axis date labels overlap and bars are too cramped when showing 14 days of data.

**Fixes — all CSS changes in the `<style>` block:**

a. **Reduce `.charts` grid min-width** from `320px` to `260px` (line 152). This allows chart cards to fit on narrower screens without triggering single-column layout as early. 260px accommodates the y-axis (~45px) plus 14 bars at ~14px each with 2px gaps:
   ```css
   .charts { display: grid; grid-template-columns: repeat(auto-fit, minmax(260px, 1fr)); gap: 16px; margin-bottom: 24px; }
   ```

b. **Extend the existing `@media (max-width: 600px)` block** (lines 232–237) with:
   ```css
   .bar-chart { gap: 2px; }
   .bar-group:nth-child(even) .bar-label { visibility: hidden; }
   .bar-label { transform: rotate(-45deg); transform-origin: top center; font-size: 0.55rem; }
   .y-axis { width: 35px; }
   ```

   - `gap: 2px` reduces bar spacing from 4px at narrow widths
   - Every other bar group's label is hidden via `visibility: hidden` (preserves layout spacing so bars stay evenly distributed)
   - Remaining labels are rotated -45° for better fit
   - Y-axis is narrowed slightly for mobile

### 3. Y-axis label rounding and mid-point

**Problem:** Y-axis displays exact max values like "49" or "$67.86". These should be "nice" round numbers, and a mid-point label should be added.

**Fix — add a TypeScript helper function and update the rendering:**

a. **Add a `niceMax` helper** (new function, placed after `computeDailyStats`, after line 86):

```typescript
function niceMax(value: number, isCost: boolean): number {
  if (value <= 0) return isCost ? 1 : 1;
  // Find the order of magnitude, then pick the smallest "nice" ceiling
  // from multiples of 1, 2, 5 within that magnitude
  const magnitude = Math.pow(10, Math.floor(Math.log10(value)));
  const nice = [1, 2, 5, 10]; // multiplied by magnitude
  for (const n of nice) {
    const candidate = n * magnitude;
    if (candidate >= value) {
      // For cost, also allow half-steps at small values
      if (isCost && magnitude < 1) {
        const smallSteps = [0.1, 0.25, 0.5, 1, 2, 5];
        for (const s of smallSteps) {
          const c = Math.ceil(value / s) * s;
          if (c >= value && c <= candidate) return parseFloat(c.toFixed(2));
        }
      }
      return candidate;
    }
  }
  // Fallback
  return Math.ceil(value / magnitude) * magnitude;
}
```

This produces:
- Tasks: 49 → 50 (magnitude=10, 5×10=50 ≥ 49), 7 → 10 (magnitude=1, 10×1=10), 23 → 50 (magnitude=10, 5×10=50 ≥ 23), 3 → 5 (magnitude=1, 5×1=5)
- Cost: $67.86 → $100 (magnitude=10, 10×10=100 ≥ 67.86)... actually that's too high.

Let me reconsider. The issue with a pure 1-2-5 sequence is that 67.86 lands between 50 and 100. We need finer granularity. Let me use a richer step set:

```typescript
function niceMax(value: number, isCost: boolean): number {
  if (value <= 0) return 1;
  const magnitude = Math.pow(10, Math.floor(Math.log10(value)));
  // Candidates: 1, 1.5, 2, 2.5, 3, 4, 5, 6, 7, 8, 10 × magnitude
  const nice = [1, 1.5, 2, 2.5, 3, 4, 5, 6, 7, 8, 10];
  for (const n of nice) {
    const candidate = n * magnitude;
    if (candidate >= value) {
      if (isCost) return parseFloat(candidate.toFixed(2));
      return Math.round(candidate);
    }
  }
  return Math.ceil(value / magnitude) * magnitude;
}
```

This produces:
- Tasks: 49 → 50 (mag=10, 5×10=50), 7 → 7 (mag=1, 7×1=7)... but 7 isn't "nice"
- Cost: $67.86 → $70 (mag=10, 7×10=70)

The problem is 7 isn't a conventional "nice" number. Let me refine to only use universally clean numbers:

```typescript
function niceMax(value: number, isCost: boolean): number {
  if (value <= 0) return 1;
  const magnitude = Math.pow(10, Math.floor(Math.log10(value)));
  const nice = [1, 2, 2.5, 5, 10];
  for (const n of nice) {
    const candidate = n * magnitude;
    if (candidate >= value) {
      if (isCost) return parseFloat(candidate.toFixed(2));
      return Math.round(candidate);
    }
  }
  return Math.ceil(value / magnitude) * magnitude;
}
```

Results:
- Tasks: 49 → 50 (mag=10, 5×10=50), 7 → 10 (mag=1, 10×1=10), 23 → 25 (mag=10, 2.5×10=25), 3 → 5 (mag=1, 5×1=5), 1 → 1, 100 → 100
- Cost: $67.86 → $100 (mag=10, 10×10=100)

$67.86 → $100 is a big jump. The ticket says "$67.86 → $70" as an example. To get there we need steps like 7 in the multiplier. Let me compromise — for cost, use a denser step set:

```typescript
function niceMax(value: number, isCost: boolean): number {
  if (value <= 0) return 1;
  const magnitude = Math.pow(10, Math.floor(Math.log10(value)));
  const steps = isCost
    ? [1, 2, 2.5, 3, 4, 5, 6, 7, 7.5, 8, 10]
    : [1, 2, 2.5, 5, 10];
  for (const n of steps) {
    const candidate = n * magnitude;
    if (candidate >= value) {
      if (isCost) return parseFloat(candidate.toFixed(2));
      return Math.round(candidate);
    }
  }
  return Math.ceil(value / magnitude) * magnitude;
}
```

Results:
- Tasks: 49 → 50, 7 → 10, 23 → 25, 3 → 5
- Cost: $67.86 → $70 (mag=10, 7×10=70), $4.50 → $5, $0.50 → $0.50 (mag=0.1, 5×0.1=0.5), $0.05 → $0.05 (mag=0.01, 5×0.01=0.05)

This is the correct approach. The task-axis uses a classic 1-2-2.5-5-10 "nice numbers" sequence (well established in charting libraries like D3). The cost-axis uses a denser sequence to get closer fits since monetary values look odd at purely mathematical "nice" intervals.
