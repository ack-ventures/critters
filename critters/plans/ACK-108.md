# ACK-108: Add missing planningModel/executionModel and review fields to init config template

## Summary

The `DEFAULT_CONFIG` template string in `src/init.ts` is missing two fields (`planningModel`, `executionModel`) that `loadConfig()` in `src/config.ts` reads, and has five review-related fields commented out instead of active. This means users who run `init` get an incomplete config that relies entirely on fallback defaults in `loadConfig()`, making these settings invisible and harder to discover.

## Changes

### File: `src/init.ts`

Modify the `DEFAULT_CONFIG` template string (lines 9–51) to:

1. **Add `planningModel: opus` and `executionModel: opus`** after the `tmuxSession` line (line 16), matching the defaults in `config.ts` lines 120–121. Place them together with a blank line before the `defaultAllowedTools` section:

   ```yaml
   tmuxSession: critters
   planningModel: opus
   executionModel: opus
   ```

2. **Uncomment the five review settings** (lines 46–50), changing them from:
   ```yaml
   # Review critter settings
   # reviewTriggerLabel: "Critter Review"
   # reviewModel: opus
   # reviewConcurrency: 2
   # reviewTimeoutMinutes: 15
   # maxReviewTurns: 30
   ```
   to:
   ```yaml
   # Review critter settings
   reviewTriggerLabel: "Critter Review"
   reviewModel: opus
   reviewConcurrency: 2
   reviewTimeoutMinutes: 15
   maxReviewTurns: 30
   ```
   The comment header `# Review critter settings` stays as a section label. The five key-value lines become active YAML.

### No other files need changes

- `src/config.ts` — no changes needed; it already reads all these fields with correct fallback defaults.
- `src/types.ts` — no changes needed; the `Config` interface already declares all these fields.
