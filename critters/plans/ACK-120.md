# ACK-120: Add Web Dashboard for Critter Activity

## Summary

Add a self-contained HTML dashboard served from the existing `Bun.serve()` health check server. The dashboard displays critter activity summary cards, a recent activity table, simple charts (CSS-based bar charts), and active critter status. No external dependencies — all CSS and JS are inline.

## Files to Create

### 1. `src/dashboard.ts` — Dashboard HTML renderer

Create a module exporting `renderDashboard(metricsPath: string, status: HealthStatus): string`.

```typescript
import { getRecentMetrics, type MetricEvent } from "./metrics.js";
import { type HealthStatus } from "./health.js";
import { VERSION } from "./version.js";
```

The function:

1. Calls `getRecentMetrics(10000)` to get all available metrics (the `metricsPath` parameter is accepted for signature compatibility but `getRecentMetrics` uses its module-level path).
2. Computes summary data from the metrics:
   - **Total tasks**: count of `task_completed` + `task_failed` events
   - **Success rate**: `task_completed / total * 100` (handle division by zero → "N/A")
   - **Total cost**: sum of `costUsd` across all `task_completed` + `task_failed` events
   - **Average duration**: mean of `duration` across all `task_completed` + `task_failed` events (in minutes)
3. Extracts the last 50 `task_completed` or `task_failed` events for the recent activity table, showing: `identifier`, status (derived from event type), `duration` (formatted as minutes), `costUsd` (formatted as $X.XX), `prUrl` (as clickable link if present), `timestamp` (formatted as relative or ISO date)
4. Computes chart data:
   - **Tasks per day (last 14 days)**: group `task_completed` + `task_failed` by date, fill zeros for missing days
   - **Success vs failure rate**: simple two-bar comparison
   - **Cost per day (last 14 days)**: sum `costUsd` by date
5. Reads `status.activeCritters`, `status.queuedCritters`, `status.activeReviews`, `status.queuedReviews` for the active critters section
6. Returns a complete HTML string with:
   - `<meta http-equiv="refresh" content="30">` for auto-refresh
   - `<meta name="viewport" content="width=device-width, initial-scale=1">` for responsive layout
   - Inline `<style>` block with:
     - CSS variables for colors (dark theme for monitoring feel)
     - CSS grid/flexbox for responsive card layout
     - Mobile-friendly breakpoints using `@media` queries
   - All charts rendered as CSS bar charts using `<div>` elements with percentage-based widths/heights — no SVG, no JS charting libraries
   - Summary cards at top, charts in middle, activity table at bottom, active critters sidebar/section

Key design decisions:
- Use `getRecentMetrics()` directly (same as `health.ts` does) rather than reading the file path manually — keeps consistency with the existing pattern
- The `metricsPath` parameter exists in the signature per the task spec but the actual data comes from the module-level `getRecentMetrics()`. This is consistent with how `health.ts` already works.
- All HTML generation uses tagged template literals
- CSS-only bar charts (no SVG, no canvas, no external JS) — each bar is a `<div>` with height set as inline style percentage
- Dark color scheme: `#1a1a2e` background, `#16213e` cards, `#0f3460` accents, `#e94560` for failures, `#4ecca3` for success
- Table rows alternate colors for readability
- Escape all user-provided strings (identifiers, URLs) to prevent XSS

## Edge Cases

- **Empty metrics file**: Dashboard renders with "0" totals and "N/A" for rates — no errors
- **Missing cost/duration fields**: Some `MetricEvent` entries may have `costUsd` or `duration` as `undefined` — handle by defaulting to 0 or "—"
- **XSS prevention**: All identifiers and URLs inserted into HTML must be escaped (replace `<`, `>`, `&`, `"`, `'`)
- **Very large metrics file**: `getRecentMetrics(10000)` is bounded; for the activity table we only show last 50
- **No active critters**: Show "0" in the active section, not an error
- **`metricsPath` not provided**: The `getRecentMetrics()` function uses the module-level path set by `initMetrics()`, so even if the parameter is empty the data still loads correctly
