# ACK-178: Add Cost Tracking to Dashboard

## Summary

The codebase already has significant cost tracking infrastructure:
- `MetricEvent` has `inputTokens`, `outputTokens`, `cacheReadTokens`, `costUsd` fields
- `SpawnResult` carries token/cost data from `parseClaudeJsonLog` in `claude.ts`
- The dashboard already renders "Total Cost" card, "Cost per Day" chart, and per-critter "Cost" column
- `handleCreateSuccess` and `handleReviewOutcome` already record full token/cost data in metrics

**The gaps are:**
1. The **generic success path** (custom critter types, ~line 420 in `unified-spawner.ts`) records `costUsd` but not `inputTokens`/`outputTokens`/`cacheReadTokens`
2. The **failure path** (~line 510) records no token/cost data at all
3. The `/healthz` endpoint's `computeMetricsSummary()` returns only `totalTasks`/`succeeded`/`failed` — no cost data
4. No average cost per critter stat on the dashboard

## Files to Modify

#### b. Failure path (~line 509-520)

Currently records no cost data. The `phaseResults` array may have partial data from completed phases before the failure. Need to aggregate whatever we have:

```typescript
const totalTurns = phaseResults.reduce((sum, r) => sum + (r.numTurns ?? 0), 0);
const totalInput = phaseResults.reduce((sum, r) => sum + (r.inputTokens ?? 0), 0);
const totalOutput = phaseResults.reduce((sum, r) => sum + (r.outputTokens ?? 0), 0);
const totalCache = phaseResults.reduce((sum, r) => sum + (r.cacheReadTokens ?? 0), 0);
const totalCost = phaseResults.reduce((sum, r) => sum + (r.costUsd ?? 0), 0);

const metricEvent = isReviewType ? "review_failed" : "task_failed";
recordMetric({
  timestamp: "",
  event: metricEvent,
  issueId: task.id,
  identifier: task.identifier,
  repoUrl: task.repoUrl,
  ...(task.prUrl ? { prUrl: task.prUrl } : {}),
  duration: Date.now() - taskStart,
  error,
  numTurns: totalTurns || undefined,
  inputTokens: totalInput || undefined,
  outputTokens: totalOutput || undefined,
  cacheReadTokens: totalCache || undefined,
  costUsd: totalCost || undefined,
  critterType: critterType.name,
});
```

**Note:** `phaseResults` is declared at line 309 (`const phaseResults: SpawnResult[] = []`) and is populated as phases complete. If a phase throws mid-execution, `spawnClaude`/`spawnClaudeSubprocess` will still return a `SpawnResult` with token data (parsed from the json log), but the runner's `run()` method may throw *after* that. However, the current code structure means `phaseResults` only gets results for phases that completed their runner successfully. For failures *within* a phase runner (e.g., exit code != 0), the runner throws before returning, so `phaseResults` won't have that phase's data. This is acceptable — we capture cost from any completed phases, which is better than nothing.

### 2. `src/health.ts` — Add cost data to `/healthz` response

#### a. Expand `computeMetricsSummary()` (~line 116-139)

Add `totalCost` and `avgCost` fields:

```typescript
function computeMetricsSummary(): {
  totalTasks: number;
  succeeded: number;
  failed: number;
  totalCost: number;
  avgCost: number;
} {
  const now = Date.now();
  if (cachedSummary && now - cachedAt < CACHE_TTL_MS) {
    return cachedSummary;
  }

  const all = getRecentMetrics(10000);
  let totalTasks = 0;
  let succeeded = 0;
  let failed = 0;
  let totalCost = 0;
  for (const m of all) {
    if (m.event === "task_completed") {
      totalTasks++;
      succeeded++;
      totalCost += m.costUsd ?? 0;
    } else if (m.event === "task_failed") {
      totalTasks++;
      failed++;
      totalCost += m.costUsd ?? 0;
    } else if (m.event === "review_completed" || m.event === "review_failed") {
      totalTasks++;
      if (m.event === "review_completed") succeeded++;
      else failed++;
      totalCost += m.costUsd ?? 0;
    }
  }

  const avgCost = totalTasks > 0 ? totalCost / totalTasks : 0;

  cachedSummary = { totalTasks, succeeded, failed, totalCost, avgCost };
  cachedAt = now;
  return cachedSummary;
}
```

Update the `cachedSummary` type to include the new fields.

## Testing Approach

1. **Unit tests**: No new unit tests needed — the changes are straightforward aggregation and display. The existing `formatPhaseStats` and `formatTokenCount` tests already cover the formatting utilities.

2. **Type checking**: Run `bun run typecheck` to verify the expanded `computeMetricsSummary` return type is compatible with all callers.

3. **Manual verification**:
   - Run a `--dry-run` to ensure the daemon starts without errors
   - Check the dashboard HTML output includes the new "Avg Cost" card
   - Verify `/healthz` response includes `totalCost` and `avgCost` in the `metrics` object

4. **Linting**: Run `bun run lint` to catch any issues.

## Edge Cases

- **No cost data in old metrics**: `costUsd` may be `undefined` in historical entries. All aggregation uses `?? 0` which handles this gracefully.
- **Failure with zero completed phases**: `phaseResults` will be empty, all sums will be 0, and we use `|| undefined` to avoid recording misleading zeros.
- **Cache invalidation**: `resetMetricsSummaryCache()` already exists and is called appropriately. The new fields in `cachedSummary` will be cleared alongside the existing ones.
