# ACK-245: Dashboard — Add Tracker Ticket Link on Issue Detail Page

## Summary

The issue detail page (`/dashboard/{id}`) displays the critter identifier as plain text. This change adds a clickable link to the actual tracker ticket (Linear/Jira URL) so users can quickly navigate to the source issue.

## Changes Required

### 1. Add `issueUrl` to `ActiveCritterDetail` (`src/types.ts`)

Add `issueUrl?: string` to the `ActiveCritterDetail` interface (after `prUrl`):

```ts
export interface ActiveCritterDetail {
  identifier: string;
  title: string;
  phase: string;
  repo: string;
  branch: string;
  startedAt: number;
  prUrl?: string;
  issueUrl?: string;   // <-- add this
  timeoutMinutes?: number;
  critterType?: string;
  workDir?: string;
}
```

### 2. Populate `issueUrl` when setting active critter detail (`src/unified-spawner.ts`)

In the `activeCritterMap.set()` call (~line 221), add `issueUrl: item.task.issueUrl`:

```ts
this.activeCritterMap.set(item.task.id, {
  identifier: item.task.identifier,
  title: item.task.title,
  phase: item.critterType.phases[0]?.name ?? typeName,
  repo: shortRepoName(item.task.repoUrl),
  branch: item.task.prBranch ?? branchName(item.task.identifier, item.task.title, this.config.branchPrefix),
  startedAt: Date.now(),
  prUrl: item.task.prUrl,
  issueUrl: item.task.issueUrl,   // <-- add this
  timeoutMinutes: item.critterType.timeoutMinutes,
  critterType: typeName,
});
```

### 3. Extract `issueUrl` in `renderIssuePage` (`src/dashboard.ts`)

After the `prUrl` resolution (~line 1653), add:

```ts
const issueUrl = activeDetail?.issueUrl ?? taskStarted?.issueUrl ?? taskEnded?.issueUrl;
```

This resolves `issueUrl` from active critter detail first, then falls back to metrics data (task_started, then task_ended). This gracefully handles older metrics that don't have `issueUrl`.

### 4. Add link in header section (`src/dashboard.ts`, ~line 1887)

Change the header `<h1>` to include a link when `issueUrl` is available:

```html
<h1>${issueUrl ? `<a href="${escapeHtml(issueUrl)}" target="_blank" rel="noopener" style="color: inherit; text-decoration: none;">${safeId} <span style="font-size: 0.6em; opacity: 0.6;">&#x2197;</span></a>` : safeId}</h1>
```

This makes the identifier itself a link with a small external link arrow (↗). When no `issueUrl` is available, it stays as plain text.

### 5. Add link in Issue Info card (`src/dashboard.ts`, ~line 1898-1899)

Change the Identifier row in the info grid to include a link:

```html
<span class="info-label">Identifier</span>
<span>${issueUrl ? `<a href="${escapeHtml(issueUrl)}" target="_blank" rel="noopener">${safeId} &#x2197;</a>` : safeId}</span>
```

## Files Modified

| File | Change |
|---|---|
| `src/types.ts` | Add `issueUrl?: string` to `ActiveCritterDetail` interface |
| `src/unified-spawner.ts` | Pass `issueUrl` from `TrackerTask` into `ActiveCritterDetail` |
| `src/dashboard.ts` | Extract `issueUrl` from active detail / metrics; render as link in header and info card |

## Edge Cases

- **Older metrics without `issueUrl`**: Falls back gracefully — the identifier remains plain text (no link)
- **Active critters**: `issueUrl` comes from `ActiveCritterDetail` which gets it from `TrackerTask` (both Linear and Jira trackers already populate this field)
- **Completed/failed critters**: `issueUrl` comes from metrics (`task_started` or `task_completed`/`task_failed` events, which already record `issueUrl`)

## Testing Approach

1. **Typecheck**: Run `bun run typecheck` to verify the interface change compiles
2. **Visual verification**: Start the dashboard and navigate to `/dashboard/{id}` for an issue with `issueUrl` in metrics — verify the link appears in both the header and info card
3. **Fallback**: Check an older issue without `issueUrl` in metrics — verify no broken rendering (plain text identifier)
4. **External link**: Click the link and verify it opens the correct Linear/Jira issue in a new tab

## Dependencies

- `issueUrl` is already available on `MetricEvent` (added in ACK-243)
- `issueUrl` is already populated by both Linear and Jira trackers in `TrackerTask`
- `issueUrl` is already recorded in metrics events by `unified-spawner.ts`
