# ACK-280: Skip committing plan files to branch, keep them only in PR description

## Summary

The planning phase currently commits plan files (`critters/plans/<ID>.md`) to the target branch. This is redundant because the execution phase already injects the plan into the PR description via `updatePrWithPlan()`. This change makes plan files local-only by default — they stay on disk for the execution phase to read, but are no longer committed to the branch.

The `commitPlans` option already exists in the codebase; the changes are:
1. Gate the `commitFile()` call in the planning runner on `ctx.critterType.repo.commitPlans`
2. Flip the default from `true` to `false` in both `synthesizeDefaultTypes()` and the execution prompt template
3. Update tests to reflect the new default

## Files to modify

### 1. `src/runner/planning.ts` (lines 42-48)

**Change:** Wrap the `commitFile()` call in a conditional check on `ctx.critterType.repo.commitPlans`.

Current code (lines 42-48):
```typescript
await commitFile(
  workDir,
  `critters/plans/${task.identifier}.md`,
  `[${task.identifier}] Add implementation plan`,
  task.identifier,
);
```

New code:
```typescript
if (ctx.critterType.repo.commitPlans) {
  await commitFile(
    workDir,
    `critters/plans/${task.identifier}.md`,
    `[${task.identifier}] Add implementation plan`,
    task.identifier,
  );
}
```

The plan file is still written to disk by the planning Claude instance — this only gates the git commit. The execution phase reads the file from `workDir` directly, so it doesn't need it committed.

### 2. `src/critter-type.ts` — `synthesizeDefaultTypes()` (line 59)

**Change:** Add `commitPlans: false` to the `repo` object for the "create" critter type.

Current:
```typescript
repo: { clone: true, branch: true },
```

New:
```typescript
repo: { clone: true, branch: true, commitPlans: false },
```

The "review" type (line 91) doesn't have a planning phase, so no change needed there.

### 3. `src/prompt.ts` — `buildExecutionPrompt()` (line 262)

**Change:** Flip the default from `true` to `false` in the nullish coalescing on `options?.commitPlans`.

Current:
```typescript
${(options?.commitPlans ?? true) ? "Commit the checkpoint..." : "Do NOT commit files under `critters/`..."}
```

New:
```typescript
${(options?.commitPlans ?? false) ? "Commit the checkpoint..." : "Do NOT commit files under `critters/`..."}
```

This means when `commitPlans` is not explicitly set (undefined), the execution prompt will instruct Claude not to commit `critters/` files. When `commitPlans: true` is explicitly configured, the old behavior is preserved.

### 4. `src/__tests__/prompt.test.ts` — new tests in "buildExecutionPrompt checkpointing" describe block

**Change:** Add tests to verify the new default behavior and the opt-in behavior.

New tests to add:
- **"defaults to not committing critters files when commitPlans is not set"** — calls `buildExecutionPrompt(task, allowedTools)` (no `commitPlans` option) and asserts the prompt contains "Do NOT commit files under `critters/`".
- **"instructs not to commit critters files when commitPlans is false"** — calls with `{ commitPlans: false }` and asserts the same.
- **"instructs to commit checkpoint when commitPlans is true"** — calls with `{ commitPlans: true }` and asserts the prompt contains "Commit the checkpoint file alongside your code changes".

## Files NOT changed

- `src/runner/execution.ts` — already passes `commitPlans: ctx.critterType.repo.commitPlans` correctly (line 35). No change needed.
- `updatePrWithPlan()` — per task requirements, this is not touched.
- `src/critter-type.ts` `CritterTypeConfig` interface — `commitPlans` is already declared as `boolean | undefined` (line 32). No change needed.
- `src/critter-type.ts` `parseCritterType()` — already parses `commitPlans` from YAML (line 200). No change needed.

## Dependencies / setup

None. All changes are in existing files with no new dependencies.

## Testing approach

1. **Unit tests (prompt.test.ts):** Three new tests covering the default, explicit false, and explicit true cases for the `commitPlans` option in `buildExecutionPrompt`.
2. **Type check:** Run `bun run typecheck` to verify no type errors.
3. **Existing tests:** Run `bun test` to ensure no regressions. The existing checkpointing tests should still pass — they don't assert on the commit/don't-commit text, they only check for the presence of the checkpoint section and file path.

## Behavioral summary

| `commitPlans` value | Planning phase commits plan? | Execution prompt says... |
|---|---|---|
| `undefined` (new default) | No | "Do NOT commit files under `critters/`" |
| `false` (explicit) | No | "Do NOT commit files under `critters/`" |
| `true` (explicit opt-in) | Yes | "Commit the checkpoint file alongside your code changes" |
