# ACK-180: Add `--json-logs` flag for structured log output

## Summary

Add a `--json-logs` CLI flag that switches all log output to structured JSON (one JSON object per line). This enables log aggregation tools (Datadog, CloudWatch, etc.) to parse critter logs. The flag works with both stdout (tmux/default) and file logging (`--no-tmux`).

## Changes

### 1. `src/logger.ts` — Add JSON output mode

**Current state:** The logger module has a `logFile` variable for file logging and a `writeLog()` function that formats text with timestamps. It exports `log`, `logError`, `logTask`, `logTaskWarn`, `logTaskError`.

**Changes:**

- Add a module-level `let jsonMode = false` flag.
- Add `export function enableJsonLogs(): void` that sets `jsonMode = true`.
- Modify `writeLog()` to check `jsonMode`. When enabled, instead of formatting a text line, emit a JSON object:
  ```json
  {"timestamp":"2026-03-05T12:00:00.000Z","level":"info","message":"..."}
  ```
- Parse the `level` parameter in `writeLog()` to extract structured fields:
  - Level string `""` → `level: "info"`
  - Level string `"ERROR: "` → `level: "error"`
  - Level string `"[ACK-123] "` → `level: "info"`, `identifier: "ACK-123"`
  - Level string `"[ACK-123] WARN: "` → `level: "warn"`, `identifier: "ACK-123"`
  - Level string `"[ACK-123] ERROR: "` → `level: "error"`, `identifier: "ACK-123"`
- The JSON object fields: `timestamp` (ISO 8601), `level` ("info" | "warn" | "error"), `message` (the message + args joined), and optionally `identifier` (when present in the level prefix).
- When `jsonMode` is true and `logFile` is set, write JSON lines to the file.
- When `jsonMode` is true and `logFile` is not set, write to `process.stdout.write()` (not `console.log`) to avoid double-formatting. Use `process.stderr.write()` for error level.
- Note: `type` and `phase` fields are not included in the base logger because `writeLog` doesn't receive them. These could be added later by extending `logTask` variants or by callers adding context to messages. For now, the `identifier` extraction from the level prefix is sufficient — callers already embed type and phase info in their messages.

## Design Decisions

1. **Module-level flag vs config field:** Using a module-level boolean in `logger.ts` (like the existing `logFile` pattern) keeps it simple. The logger already uses module-level state for file logging. No need to thread config through every call site.

2. **No `type`/`phase` fields in JSON:** The current `logTask`/`logTaskWarn`/`logTaskError` functions only receive `identifier` and `message`. Adding `type` and `phase` would require changing every call site. Instead, the identifier is extracted from the level prefix, and type/phase info is already embedded in log messages by callers. This can be extended later if needed.

3. **stdout vs stderr for JSON mode:** Using `process.stdout.write()` for info/warn and `process.stderr.write()` for errors keeps JSON logs on stdout for piping while preserving error separation.

4. **No config file option:** The flag is CLI-only (`--json-logs`), consistent with `--no-tmux` and `--dry-run`. This is a runtime concern, not a persistent config setting.

## Testing Approach

1. **Unit tests for logger.ts:**
   - Test that `enableJsonLogs()` switches output to JSON format.
   - Test that `log("hello")` produces `{"timestamp":"...","level":"info","message":"hello"}`.
   - Test that `logTask("ACK-1", "msg")` produces JSON with `identifier: "ACK-1"`.
   - Test that `logError("fail")` produces JSON with `level: "error"`.
   - Test that `logTaskWarn("ACK-1", "warn")` produces JSON with `level: "warn"` and `identifier: "ACK-1"`.
   - Test JSON output to file (when `logFile` is set).

2. **Integration smoke test:**
   - Run `critters --json-logs --dry-run` and verify output lines are valid JSON.

3. **Manual verification:**
   - Confirm `--json-logs --no-tmux` writes JSON lines to the log file.
   - Confirm JSON logs can be piped through `jq` for validation.
