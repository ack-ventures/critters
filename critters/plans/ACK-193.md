# ACK-193: Add `critters tail` command for live multi-critter output

## Summary

Add a `critters tail` command that live-streams interleaved output from all active critters, prefixed with colored identifiers. This is the multi-critter equivalent of `critters logs <ID> -f`.

## Files to Create

### `src/cli-tail.ts`

New file exporting `tailCommand(args: string[]): Promise<void>`.

#### Argument parsing

- `--config PATH` — custom config file path (same pattern as other CLI commands)
- `--type <name>` — filter to a specific critter type (matched against `activeCritterDetails` entries)

Uses manual arg parsing (same style as `logs.ts:parseArgs` and `cli-clean.ts`).

#### Config loading

Follow the `status.ts` / `cli-kickoff.ts` pattern for reading healthPort + workDir from config:

```typescript

  // Check ./critters.config.yaml then ~/.critters/config.yaml
  // Return { healthPort: 3847, workDir: "/tmp/critters-work" } as defaults

```

Also loads `workDir` from config (needed to locate log files on disk). Uses the `loadWorkDir()` helper from `config.ts`.

#### Core logic

1. **Fetch active critters** — `GET http://localhost:<healthPort>/healthz`, extract `activeCritterDetails` array. Each entry has: `identifier`, `title`, `phase`, `repo`, `branch`, `elapsed`, `prUrl`, `timeoutMinutes`.

2. **Filter by type** — If `--type` is provided, filter `activeCritterDetails` to entries whose phase or type matches. Since the healthz endpoint doesn't expose the critter type name directly, we need to add it. See "Health endpoint change" below.

3. **If no active critters** — Print "No active critters" and exit.

4. **Determine log file paths** — For each active critter, find the work directory and current phase log file:
   - Scan `workDir` for directories matching `<identifier>-<timestamp>` or `review-<identifier>-<timestamp>` (same regex as `logs.ts:findWorkDir`)
   - Use the newest matching directory
   - The active log file is `.critter-output-<phaseName>.json` inside that directory
   - Phase names from the healthz endpoint: `planning` -> `plan`, `execution` -> `exec`, `review` -> `review`, or for custom types, the phase name directly
   - Map: `{ planning: "plan", execution: "exec", review: "review" }` with fallback to the phase name as-is for custom types

5. **Spawn tail processes** — For each critter with a valid log file:
   - Spawn `tail -n 0 -f <logFile>` (start from end, only new output) piped through `jq` using the same stream filter as `logs.ts`
   - Read stdout line by line
   - Prefix each line with `[<identifier>/<phase>]` in a cycling color

6. **Color cycling** — Define a small array of ANSI colors (e.g., cyan, green, yellow, magenta, blue, red) and assign each critter a color by index mod length. Store in a `Map<string, string>` so colors persist across poll cycles.

7. **Periodic poll** — Every 10 seconds, re-fetch `/healthz`:
   - **New critters**: Start a new `tail -f` process for them
   - **Finished critters**: When a critter disappears from the active list, print `[<identifier> completed]` in its assigned color, kill the tail process
   - Update the tracked set accordingly

8. **Clean exit on Ctrl+C** — Register `SIGINT` handler that kills all tail child processes and exits.

#### Phase name mapping

The healthz endpoint returns phase names as they are in the config (e.g., `planning`, `execution`, `review`, or custom names like `audit`). The log files use abbreviated names for built-in phases:

```typescript
const PHASE_TO_FILE_TAG: Record<string, string> = {
  planning: "plan",
  execution: "exec",
  review: "review",
};

function phaseFileTag(phaseName: string): string {
  return PHASE_TO_FILE_TAG[phaseName] ?? phaseName;
}
```

This maps to `.critter-output-<tag>.json`.

#### Line reading from tail+jq

Use `Bun.spawn` with stdout as a readable stream. Read lines from the stream and prefix each with the colored identifier tag before writing to `process.stdout`.

```typescript
const proc = Bun.spawn(["sh", "-c", `tail -n 0 -f ${quotedPath} | jq -cr --unbuffered --arg tool_color '\\x1b[36m' -f ${FILTER_TMP_PATH}`], {
  stdout: "pipe",
  stderr: "ignore",
});
```

Read from `proc.stdout` using a `ReadableStream` reader, split by newlines, and prefix each line.

## Implementation Details

### Color assignment

```typescript
const COLORS = [
  "\x1b[36m", // cyan
  "\x1b[32m", // green
  "\x1b[33m", // yellow
  "\x1b[35m", // magenta
  "\x1b[34m", // blue
  "\x1b[91m", // bright red
];
const RESET = "\x1b[0m";

// Assign colors by insertion order, persisted across poll cycles
const colorMap = new Map<string, string>();
let colorIdx = 0;

function getColor(identifier: string): string {
  if (!colorMap.has(identifier)) {
    colorMap.set(identifier, COLORS[colorIdx % COLORS.length]);
    colorIdx++;
  }
  return colorMap.get(identifier)!;
}
```

### Stream reading

```typescript
async function readLines(
  stream: ReadableStream<Uint8Array>,
  prefix: string,
): Promise<void> {
  const reader = stream.getReader();
  const decoder = new TextDecoder();
  let buffer = "";

  while (true) {
    const { done, value } = await reader.read();
    if (done) break;
    buffer += decoder.decode(value, { stream: true });
    const lines = buffer.split("\n");
    buffer = lines.pop() ?? "";
    for (const line of lines) {
      if (line.trim()) {
        process.stdout.write(`${prefix} ${line}\n`);
      }
    }
  }
}
```

### Process management

Track active tail processes in a `Map<string, { proc: Subprocess; reader: Promise<void> }>` keyed by critter identifier. On poll:
- For new critters: start tail process, add to map
- For removed critters: kill process, print completion message, remove from map

### jq filter file

Reuse `STREAM_FILTER` from `src/jq-filter.ts` and write it to a temp file (same as `logs.ts:writeFilterFile`).

## Edge Cases

- **Log file doesn't exist yet**: A critter may be active but its current phase's log file may not exist yet (e.g., still cloning). Skip it and pick it up on the next poll.
- **Daemon not running**: Print "Critters daemon is not running" and exit (same as `status.ts`).
- **No critters active**: Print "No active critters" and exit with code 0.
- **Critter phase changes**: When a critter moves to a new phase (e.g., planning -> execution), the old tail process will stop getting output. On the next poll cycle, we'll detect the phase change, kill the old tail, and start a new one for the new log file.
- **workDir not yet set**: The healthz response may show a critter with no `workDir` if it was just queued. Skip these until the next poll.

## Testing Approach
