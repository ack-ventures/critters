# ACK-207: Add Bearer Token Auth to Dashboard Endpoints

## Summary

Add optional bearer token authentication to the health server's POST endpoints (`/poll`, `/review-poll`). When `dashboardToken` is configured (via YAML config or `DASHBOARD_TOKEN` env var), mutating endpoints require `Authorization: Bearer <token>`. GET endpoints remain open. Full backward compatibility — no auth required if token is not set.

## Files to Create

### 1. `src/auth.ts` (new)

Create a named export `checkAuth`:

```typescript
export function checkAuth(req: Request, token: string | undefined): Response | null {
  if (token === undefined) return null;

  const header = req.headers.get("Authorization");
  if (header === `Bearer ${token}`) return null;

  return Response.json({ error: "Unauthorized" }, { status: 401 });
}
```

- If `token` is `undefined` → return `null` (no auth configured, allow)
- If `Authorization` header matches `Bearer <token>` (exact, case-sensitive) → return `null` (authorized)
- Otherwise → return 401 JSON response

### 2. `src/__tests__/auth.test.ts` (new)

Unit tests for `checkAuth`:

1. Returns `null` when token is `undefined` (no auth configured)
2. Returns `null` when `Authorization` header matches `Bearer <token>`
3. Returns 401 when `Authorization` header is missing
4. Returns 401 when `Authorization` header has wrong token
5. Returns 401 when `Authorization` header uses non-Bearer scheme (e.g., `Basic <token>`)

Uses `bun:test` with `describe`/`test`/`expect` — matching existing test patterns. Tests create `new Request()` objects directly (no server needed).

**Dashboard JS**: Update the client-side `fetch('/poll', { method: 'POST' })` call (around line 900) to include the bearer token header when configured. Inject the token as a JS variable in the rendered HTML:

```javascript
var __dashboardToken = ${dashboardToken ? JSON.stringify(dashboardToken) : 'null'};
```

Then update the fetch call:

```javascript
var headers = {};
if (__dashboardToken) {
  headers['Authorization'] = 'Bearer ' + __dashboardToken;
}
fetch('/poll', { method: 'POST', headers: headers })
```

**Note**: Exposing the token in client-side HTML is acceptable because (a) the dashboard is already served over the same connection that would use the token, (b) the token protects against casual unauthorized POST requests and automated scanners, not against someone who can already view the dashboard, and (c) this matches the threat model — the ngrok tunnel already has its own basic auth layer via `tunnel.auth`.

**Caller update in `src/health.ts`**: Pass `dashboardToken` to `renderDashboard()` in the dashboard handler:

