# ACK-149: Add hover tooltips and Y-axis labels to dashboard charts

## Summary

Replace browser-native `title` tooltips on dashboard chart bars with styled CSS-based tooltips, add bar-group-level tooltips showing date + combined stats, add a subtle hover effect on bars, and add Y-axis labels (max value at top, "0" at bottom) to the "Tasks per Day" and "Cost per Day" charts. All changes are in `src/dashboard.ts` (pure CSS/HTML, no JS frameworks).

#### E. New helper function

Add a `formatShortDate` function near the other formatting helpers:

```typescript
function formatShortDate(dateStr: string): string {
  const months = ["Jan","Feb","Mar","Apr","May","Jun","Jul","Aug","Sep","Oct","Nov","Dec"];
  const parts = dateStr.split("-");
  if (parts.length < 3) return dateStr;
  const monthIdx = parseInt(parts[1], 10) - 1;
  const day = parseInt(parts[2], 10);
  return `${months[monthIdx] ?? parts[1]} ${day}`;
}
```

## Edge cases

- **Zero-height bars**: Only add `data-tooltip` when the bar has a non-zero height (already handled by the existing conditional pattern `${h > 0 ? ... : ""}`)
- **Empty data**: Y-axis still shows "1" / "0" for tasks (since `maxTasksPerDay` is `Math.max(1, ...)`) and "$0.01" / "$0" for cost (since `maxCostPerDay` is `Math.max(0.01, ...)`)
- **Long tooltips**: `white-space: nowrap` prevents wrapping; the tooltip content is short enough not to be a problem
- **Overlapping tooltips**: Bar tooltips have `z-index: 10`, group tooltips have `z-index: 20`. The bar-level tooltip appears when hovering a specific bar; the group tooltip appears when hovering the group area outside the bars. Since bars are children of bar-group, hovering a bar triggers both — but the bar tooltip (`z-index: 10`) sits directly above the bar while the group tooltip (`z-index: 20`) sits above the group. To avoid overlap, we should only add the group-level tooltip to the Tasks per Day and Cost per Day charts' `.bar-group` elements, and rely on the individual bar tooltips being sufficient. However, since both could show simultaneously (bar hover triggers both bar and parent group hover), we should avoid the group tooltip when a bar is hovered. The simplest pure-CSS approach: add the group tooltip on the `.bar-group` only, and suppress individual bar tooltips. But the task asks for both. A cleaner approach: put group tooltip on `.bar-group:hover::before` (using `::before` instead of `::after`) positioned above the chart, and bar tooltips on `.bar:hover::after`. This avoids collision. Actually, the simest approach is to use `pointer-events: none` on the tooltip (already specified) and position the bar-group tooltip higher (e.g., `bottom: calc(100% + 16px)`). Let me revise: just use the bar-group tooltip only for the combined stats, and keep individual bar tooltips for individual values. The group tooltip will be positioned at the top of the group element above the bars, while bar tooltips are positioned directly above each bar. Since the group tooltip uses `bottom: 100%` of the bar-group (which is the full chart height), it'll be at the very top above the chart. The bar tooltips use `bottom: 100%` of the individual bar, so they appear just above that bar. This provides sufficient visual separation.
