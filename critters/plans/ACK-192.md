# ACK-192: Add warning-level output to critters validate

## Summary

`critters validate` currently only reports errors (hard failures). This change adds warning-level checks for non-critical config values that may indicate mistakes, without blocking startup.

## Files to Modify

### 1. `src/validate.ts`

**Return type change:**
- Change `validateConfigFile` return type from `{ errors: string[]; summary?: string }` to `{ errors: string[]; warnings: string[]; summary?: string }`
- Initialize `const warnings: string[] = []` alongside `errors`
- Return `{ errors, warnings, summary }` at the end

**Warning checks to add** (after existing error checks, before the summary):

1. **High planning/execution turns** — After lines 45-53 where `maxPlanningTurns` and `maxExecutionTurns` are validated:
   ```ts
   if (maxPlanningTurns > 100) {
     warnings.push(`High turn count (${maxPlanningTurns}) for maxPlanningTurns may lead to expensive runs`);
   }
   if (maxExecutionTurns > 100) {
     warnings.push(`High turn count (${maxExecutionTurns}) for maxExecutionTurns may lead to expensive runs`);
   }
   ```

2. **Timeout over 60 minutes** — After line 37 where `timeoutMinutes` is validated:
   ```ts
   if (timeoutMinutes > 60) {
     warnings.push(`Timeout over 60 minutes (${timeoutMinutes}) may indicate a misconfiguration`);
   }
   ```

3. **High concurrency** — After line 33 where `concurrency` is validated:
   ```ts
   if (concurrency > 5) {
     warnings.push(`High concurrency (${concurrency}) — ensure you have sufficient API quota`);
   }
   ```

4. **Short poll interval** — After line 42 where `pollIntervalSeconds` is validated:
   ```ts
   if (pollIntervalSeconds < 30) {
     warnings.push(`Very short poll interval (${pollIntervalSeconds}s) may hit API rate limits`);
   }
   ```

5. **Health server disabled** — After line 77 where `healthPort` is validated:
   ```ts
   if (healthPort === 0) {
     warnings.push("Health server disabled — dashboard and kickoff will not work");
   }
   ```

6. **Phase-level warnings** (inside the critterTypes loop, after successful `parseCritterTypes`):
   For each expanded critter type, iterate over its phases:
   ```ts
   for (const phase of type.phases) {
     if (phase.model === "haiku") {
       warnings.push(`Haiku model in phase '${phase.name}' (type '${typeName}') may produce unreliable results (see docs)`);
     }
     if (phase.maxTurns < 5) {
       warnings.push(`Low maxTurns (${phase.maxTurns}) in phase '${phase.name}' (type '${typeName}') may not give Claude enough room to work`);
     }
   }
   ```
   Also check phases from `synthesizeDefaultTypes` in the else branch.

7. **Also check reviewConcurrency and reviewTimeoutMinutes for warnings** — same thresholds: `reviewConcurrency > 5`, `reviewTimeoutMinutes > 60`.

**Summary update:**
- Include warning count in summary when warnings exist but no errors:
  ```ts
  const summary = errors.length === 0
    ? `Config valid: ${critterTypes.length} critter type(s), provider: ${provider}${warnings.length > 0 ? ` (${warnings.length} warning(s))` : ""}`
    : undefined;
  ```

**`runValidate` function update:**
- Display warnings with yellow "WARN:" prefix using ANSI codes
- Show warnings regardless of whether there are errors
- Keep exit code 0 for warnings-only, exit code 1 for errors

```ts
export async function runValidate(configPath?: string): Promise<void> {
  try {
    const result = validateConfigFile(configPath);

    if (result.warnings.length > 0) {
      console.log(`\n\x1b[33m${result.warnings.length} warning(s):\x1b[0m\n`);
      for (let i = 0; i < result.warnings.length; i++) {
        console.log(`  \x1b[33mWARN:\x1b[0m ${result.warnings[i]}`);
      }
    }

    if (result.errors.length > 0) {
      console.error(`\n\x1b[31m${result.errors.length} error(s):\x1b[0m\n`);
      for (let i = 0; i < result.errors.length; i++) {
        console.error(`  \x1b[31mERROR:\x1b[0m ${result.errors[i]}`);
      }
      process.exit(1);
    }

    if (result.summary) {
      console.log(result.summary);
    }
  } catch (e) {
    console.error(`\x1b[31mERROR:\x1b[0m ${(e as Error).message}`);
    process.exit(1);
  }
}
```

### 2. `src/index.ts`

No changes needed — the validate command handler at lines 110-118 calls `runValidate()` which handles all display logic internally. The `runValidate` function already manages exit codes.

## Dependencies

None — this only touches existing files and uses no new dependencies.

## Testing Approach

Add new tests to `src/__tests__/validate.test.ts`:

1. **Valid config returns empty warnings array** — Verify existing valid config tests also check `result.warnings` is empty
2. **High turn count warning** — Set `maxPlanningTurns: 150`, verify warning about high turn count
3. **Timeout warning** — Set `timeoutMinutes: 90`, verify warning
4. **High concurrency warning** — Set `concurrency: 8`, verify warning
5. **Short poll interval warning** — Set `pollIntervalSeconds: 10`, verify warning (note: must be >= 5 to avoid error)
6. **Health port disabled warning** — Set `healthPort: 0`, verify warning
7. **Haiku model warning** — Define a custom critter type with `model: haiku`, verify warning
8. **Low maxTurns warning** — Define a phase with `maxTurns: 3`, verify warning
9. **Warnings don't cause errors** — Verify that warnings-only result still has `errors.length === 0` and summary is present
10. **Multiple warnings accumulate** — Config with several warning-triggering values, verify all are reported

## Edge Cases

- `pollIntervalSeconds` between 5 and 29: valid (no error) but should warn. The error threshold is `< 5`, the warning threshold is `< 30` — these don't overlap.
- `concurrency` of exactly 5: no warning (threshold is `> 5`). Same for `timeoutMinutes` of exactly 60.
- Synthesized default types: warning checks on phases must also run for defaults (e.g., if `planningModel: haiku` is set in flat config).
- The `maxPlanningTurns`/`maxExecutionTurns` warning checks use the resolved values (with defaults), but only warn when the user explicitly set them. We should check `typeof yaml.maxPlanningTurns === "number"` before warning, consistent with the error checks pattern. Actually, since the defaults are 50 and 75 (both under 100), the default values won't trigger warnings, so checking the resolved value directly is fine and simpler.
