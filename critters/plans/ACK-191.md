# ACK-191: Add stale remote branch cleanup to critters clean

## Summary

Add a `--branches` flag to `critters clean` that finds and deletes stale critter branches from remote repositories. A branch is considered stale if it matches the configured `branchPrefix` pattern and either (a) has no open PR and its issue is in a terminal state, or (b) has no PR at all and is older than 7 days, or (c) has a merged/closed PR but the branch was never deleted. Branches with open PRs are never deleted.

## Files to modify

### 1. `src/git.ts` — Add `deleteRemoteBranch` helper

Add a new exported function:

```typescript
export async function deleteRemoteBranch(repoUrl: string, branch: string): Promise<void> {
  const { code, stderr } = await runCommand("git", ["push", repoUrl, "--delete", branch]);
  if (code !== 0) {
    throw new Error(`Failed to delete remote branch ${branch}: ${stderr}`);
  }
}
```

This follows the existing pattern of thin wrappers around git commands that throw on failure (see `shallowClone`, `createBranch`, `commitFile`).

### 2. `src/cli-clean.ts` — Add `--branches` logic

#### Changes to `runClean`:

1. **Parse `--branches` flag** from `args` (alongside existing `--all`, `--dry-run`, `--config`).
2. **Run both modes when applicable**: if `--branches` is set, run branch cleanup. Then, regardless, run directory cleanup (existing behavior) unless `--branches` was the only action. Actually, simplest approach: if `--branches` is present, run `cleanStaleBranches()`. If `--branches` is NOT present, run directory cleanup. Users who want both can run the command twice. This avoids conflating `--all` and `--dry-run` semantics across two very different operations.

#### New function `cleanStaleBranches(configPath?: string, dryRun: boolean)`:

1. **Load config partially** — since `loadConfig()` validates provider credentials and will throw if they're missing, we need a lighter approach. Use `loadWorkDir`-style partial parsing: read the YAML file, extract `repos`, `teamRepos`, and `branchPrefix` directly, without calling `validateConfig()`. Create a new `loadBranchCleanConfig(configPath?)` helper that returns `{ repos, teamRepos, branchPrefix, provider, jiraStatusMap }`.
2. **Try to create trackers** — wrap `createTracker()` + `init()` in try/catch. If credentials are missing or init fails, log a warning and proceed with age-only checks.
3. **Collect unique repo URLs** from `repos` (values have `.url`) and `teamRepos` (values are URLs directly). Deduplicate by URL.
4. **For each repo URL**:
   a. Derive `ownerRepo` using `extractOwnerRepo()` from `utils.ts`. If it returns null, skip with warning.
   b. Run `git ls-remote --heads <repoUrl>` to list all remote branches. Parse output — each line is `<sha>\trefs/heads/<branchName>`.
   c. Filter branches matching `branchPrefix + "/"` prefix.
   d. For each matching branch:
      - Extract the issue identifier from the branch name using `extractIdentifier()`.
      - Check if a PR exists: run `gh pr list --head <branch> --state all --json number,state --repo <ownerRepo> --limit 100`. Parse JSON output.
      - If any PR exists with state `"OPEN"`, skip this branch — never delete branches with open PRs.
      - If a PR exists with state `"MERGED"` or `"CLOSED"` (no open PR), mark as stale — the branch should have been cleaned up already.
      - If no PR exists at all:
        - Try to check issue status via the tracker. Call `tracker.findIssueByIdentifier(identifier)`. If the issue is in a terminal state ("Done", "Cancelled", "Canceled", "Critter Failed"), mark as stale.
        - If no issue found or tracker unavailable, fall back to age check: use `gh api repos/{owner}/{repo}/commits/{sha} --jq '.commit.committer.date'` to get the commit date.
        - If the branch commit is older than 7 days, mark as stale.
5. **Report findings**: list each stale branch with its repo and reason.
6. **If not dry-run**, call `deleteRemoteBranch(repoUrl, branch)` for each stale branch. Log each deletion: `"Deleted stale branch: critter/ACK-123-foo-bar from org/repo"`.

#### Config loading for `--branches`:

Add a new function `loadBranchCleanConfig(configPath?: string)` that:
- Resolves config path using `resolveConfigPath(configPath)`.
- Reads and parses the YAML.
- Extracts only the fields needed: `repos`, `teamRepos`, `branchPrefix`, `provider`, `jiraStatusMap`.
- Does NOT call `validateConfig()` or `checkProviderCredentials()`.
- This avoids the requirement for tracker credentials when just cleaning branches from known repos.

#### Tracker initialization:

- Read provider credentials from env vars directly.
- Attempt to create and init trackers, wrapped in try/catch.
- If tracker init fails (e.g., no API key), set tracker to null and log a warning: `"Could not initialize tracker — will use age-based detection only"`.

## Implementation details

### Extracting identifier from branch name

Branch names follow the pattern from `branchName()` in `utils.ts`:
```
<prefix>/<IDENTIFIER>-<slug>
```

Example: `critter/ACK-123-fix-login-bug`

Extraction (case-insensitive to support Jira lowercase project keys):
```typescript
function extractIdentifier(branch: string, prefix: string): string | null {
  const afterPrefix = branch.slice(prefix.length + 1); // "ACK-123-fix-login-bug"
  const match = afterPrefix.match(/^([A-Za-z][A-Za-z0-9]*-\d+)/);
  return match ? match[1] : null;
}
```

### Terminal states

Define a set of terminal states:
```typescript
const TERMINAL_STATES = new Set(["Done", "Cancelled", "Canceled", "Critter Failed"]);
```

For Jira, also check the reverse-mapped values from `jiraStatusMap`. Build a combined set:
```typescript
function buildTerminalStates(jiraStatusMap?: Record<string, string>): Set<string> {
  const states = new Set(TERMINAL_STATES);
  if (jiraStatusMap) {
    for (const [internal, jiraName] of Object.entries(jiraStatusMap)) {
      if (TERMINAL_STATES.has(internal)) {
        states.add(jiraName);
      }
    }
  }
  return states;
}
```

### Staleness criteria (summary)

A branch matching `branchPrefix/` is stale if:
1. It has a merged or closed PR (no open PR) → stale (branch should have been auto-deleted)
2. It has no PR AND its issue is in a terminal state → stale
3. It has no PR AND no issue found/tracker unavailable AND commit is older than 7 days → stale

A branch is NOT stale if:
1. It has an open PR → never delete
2. It has no PR, issue is not in terminal state, and commit is younger than 7 days → keep

### Error handling

- If `gh` command fails, warn and skip PR checks for that branch (treat as "no PR").
- If tracker init fails, warn and use age-only fallback for all branches.
- If a branch deletion fails, log error and continue with remaining branches.
- If `git ls-remote` fails for a repo, log warning and skip that repo.
- If `extractOwnerRepo()` returns null for a repo URL, skip with warning.

### Logging

Follow the existing `cli-clean.ts` pattern of using `console.log` for output. Log format:

```
Scanning branches in org/repo...
  critter/ACK-123-foo-bar  no PR, issue Done       stale
  critter/ACK-456-baz      open PR #42              skip
  critter/ACK-789-qux      no PR, 12 days old      stale
  critter/ACK-012-wip      merged PR #55            stale

Would delete 3 stale branches from org/repo
```

Or without `--dry-run`:
```
Deleted stale branch: critter/ACK-123-foo-bar from org/repo
Deleted stale branch: critter/ACK-789-qux from org/repo
Deleted stale branch: critter/ACK-012-wip from org/repo

Cleaned up 3 stale branches across 1 repo
```

```typescript
const STALE_BRANCH_AGE_MS = STALE_BRANCH_AGE_DAYS * 24 * 60 * 60_000;
```

## Testing approach

1. **Manual testing with `--dry-run`**: Run `critters clean --branches --dry-run` against a repo with known stale branches. Verify it correctly identifies stale branches without deleting them.
2. **Edge cases to verify**:
   - Repo with no critter branches → "No stale branches found"
   - Branch with open PR → never deleted
   - Branch with merged PR → deleted (branch should have been auto-cleaned)
   - Branch with closed PR (no merge) → deleted
   - Branch with no PR, issue in terminal state → deleted
   - Branch with no PR, older than 7 days, no issue found → deleted
   - Branch with no PR, younger than 7 days, issue not in terminal state → kept
   - Invalid branch name (doesn't match identifier pattern) → skipped with note
   - `git ls-remote` fails → skip repo with warning
   - Tracker unavailable (no credentials) → fall back to age-only check, log warning
   - `extractOwnerRepo()` returns null → skip repo with warning
3. **Verify `--branches` without `--dry-run`** actually deletes branches (test on a scratch repo).
