# ACK-119: Add Health Check HTTP Endpoint

## Summary

Add a lightweight HTTP health check server using `Bun.serve()` so the Critters daemon can be monitored externally. The server exposes two endpoints:

- `GET /healthz` — returns daemon status, uptime, version, and queue state
- `GET /metrics` — returns the last 100 entries from the JSONL metrics file

## Files to Create

### 1. `src/health.ts` — Health check HTTP server

Create a new module that exports `startHealthServer()`.

```typescript
import { log } from "./logger.js";
import { getRecentMetrics } from "./metrics.js";
import { VERSION } from "./version.js";

export interface HealthStatus {
  activeCritters: number;
  queuedCritters: number;
  activeReviews: number;
  queuedReviews: number;
  lastPollAt: string | null;
}

export function startHealthServer(
  port: number,
  getStatus: () => HealthStatus,
): { stop: () => void } {
  const startTime = Date.now();

  const server = Bun.serve({
    port,
    fetch(req) {
      const url = new URL(req.url);

      if (url.pathname === "/healthz") {
        const status = getStatus();
        return Response.json({
          status: "ok",
          uptime: Math.floor((Date.now() - startTime) / 1000),
          version: VERSION,
          activeCritters: status.activeCritters,
          queuedCritters: status.queuedCritters,
          activeReviews: status.activeReviews,
          queuedReviews: status.queuedReviews,
          lastPollAt: status.lastPollAt,
          metrics: computeMetricsSummary(),
        });
      }

      if (url.pathname === "/metrics") {
        const entries = getRecentMetrics(100);
        return Response.json(entries);
      }

      return new Response("Not Found", { status: 404 });
    },
  });

  log(`Health server listening on port ${server.port}`);

  return {
    stop: () => server.stop(),
  };
}

function computeMetricsSummary(): { totalTasks: number; succeeded: number; failed: number } {
  const all = getRecentMetrics(10000); // read all available
  let totalTasks = 0;
  let succeeded = 0;
  let failed = 0;
  for (const m of all) {
    if (m.event === "task_completed") {
      totalTasks++;
      succeeded++;
    } else if (m.event === "task_failed") {
      totalTasks++;
      failed++;
    } else if (m.event === "task_started") {
      // Count started but not yet completed/failed as in-progress
      // but for the summary we only count completed/failed
    }
  }
  return { totalTasks, succeeded, failed };
}
```

Key design decisions:
- `startTime` is captured at server start to calculate uptime in seconds
- `getStatus()` callback is provided by the caller (index.ts) and reads from Spawner/ReviewSpawner
- `computeMetricsSummary()` reads all metrics to produce aggregate totals (completed + failed = totalTasks)
- Returns a `{ stop }` object for graceful shutdown
- Uses `Bun.serve()` per Bun conventions
- `lastPollAt` can be `null` if no poll has occurred yet

### 2. `src/__tests__/health.test.ts` — Tests

Tests using `bun:test` following the existing test patterns (see `metrics.test.ts`, `config.test.ts`):

1. **`GET /healthz` returns 200 with correct shape** — start server, fetch `/healthz`, verify JSON structure has all expected fields (status, uptime, version, activeCritters, etc.)
2. **`GET /healthz` uptime increases over time** — verify uptime is a non-negative number
3. **`GET /healthz` reflects getStatus callback values** — pass a mock `getStatus` returning specific values, verify they appear in response
4. **`GET /metrics` returns recent metrics as JSON array** — write some metrics via `recordMetric`, fetch `/metrics`, verify array contents
5. **`GET /metrics` returns empty array when no metrics file exists** — init metrics to a nonexistent path, verify `[]` response
6. **Unknown routes return 404** — fetch `/unknown`, verify 404 status
7. **`stop()` shuts down the server** — call stop, verify server is no longer accepting connections

Each test will:
- Use port 0 (let OS assign) to avoid conflicts, or use a random high port
- Call `server.stop()` in `afterEach` cleanup
- Use `createTempDir` from helpers for metrics file isolation

### 7. `src/index.ts` — Wire health server into daemon lifecycle

After config load and `initMetrics()`, before watchers start:

```typescript
import { startHealthServer } from "./health.js";

// In main(), after initMetrics() and before initLinear():
let healthServer: { stop: () => void } | null = null;
if (config.healthPort !== 0) {
  let lastPollAt: string | null = null;
  // Expose a way for the watcher to update lastPollAt
  // (We'll use a simple closure variable)

  healthServer = startHealthServer(config.healthPort, () => ({
    activeCritters: spawner.getActiveCount(),
    queuedCritters: spawner.getQueueSize(),
    activeReviews: reviewSpawner.getActiveCount(),
    queuedReviews: reviewSpawner.getQueueSize(),
    lastPollAt,
  }));
}
```

Note: The health server must be started *after* spawner/reviewSpawner are created but *before* `Promise.all([watcher.start(), ...])`. The `getStatus` callback closure captures the spawner/reviewSpawner references.

For `lastPollAt`: Add a callback mechanism. The simplest approach is to have the `Watcher` accept an optional `onPoll` callback:

In `src/watcher.ts`, add to the constructor:
```typescript
private onPoll?: () => void;

constructor(config: Config, spawner: Spawner, onPoll?: () => void) {
  // ...
  this.onPoll = onPoll;
}
```

And call it after each successful poll in `start()`:
```typescript
this.onPoll?.();
```

Then in `index.ts`:
```typescript
const watcher = new Watcher(config, spawner, () => {
  lastPollAt = new Date().toISOString();
});
```

Similarly for `ReviewWatcher` — add the same optional callback pattern.

In the shutdown handler, add:
```typescript
healthServer?.stop();
```

## Testing Approach

- Unit tests in `src/__tests__/health.test.ts` using `bun:test`
- Use `createTempDir` from existing test helpers for file isolation
- Test all routes: `/healthz` (200), `/metrics` (200), unknown (404)
- Test `stop()` graceful shutdown
- Test that `getStatus` callback values flow through to `/healthz` response
- Test metrics summary computation (completed + failed counts)
- Test with no metrics file (should return `[]` for `/metrics`, zeros for summary)
- Use port 0 to let the OS assign ports and avoid conflicts in CI
- Config tests: add cases for `healthPort` validation (0 allowed, <1024 rejected, >65535 rejected, default 3847)

## Edge Cases

- **Port 0 disables the server**: When `healthPort: 0`, skip starting the health server entirely
- **Missing metrics file**: `GET /metrics` returns `[]`, `/healthz` metrics summary returns `{totalTasks: 0, succeeded: 0, failed: 0}`
- **No polls yet**: `lastPollAt` is `null` until the first poll completes
- **Concurrent requests**: `Bun.serve()` handles this natively
- **Shutdown ordering**: Health server is stopped in the shutdown handler before the process exits
