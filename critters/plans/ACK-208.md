# ACK-208: Add createIssue + listTeams to IssueTracker interface and Linear implementation

## Summary

Extend the `IssueTracker` interface with two new methods — `createIssue` and `listTeams` — and implement both in `LinearTracker`. These will be consumed by a future dashboard API for creating critter tickets and populating team dropdowns. Three new supporting types are also added: `CreateIssueInput`, `CreatedIssue`, and `TrackerTeam`.

## Files to modify

### 1. `src/tracker/types.ts` — New types + interface additions

Add three new interfaces after the existing `TrackerTask` interface:

```typescript
export interface CreateIssueInput {
  teamId: string;        // Linear team ID or Jira project key
  title: string;
  description: string;
  labelNames: string[];  // e.g., ["Critter"] — resolved to IDs by the tracker
}

export interface CreatedIssue {
  id: string;
  identifier: string;    // e.g., "ACK-210"
  url: string;           // Web URL to the created issue
}

export interface TrackerTeam {
  id: string;
  name: string;
  key: string;
}
```

Add two new methods to the `IssueTracker` interface:

```typescript
createIssue(input: CreateIssueInput): Promise<CreatedIssue>;
listTeams(): Promise<TrackerTeam[]>;
```

### 2. `src/tracker/linear.ts` — Implementation

**Import** the new types: `CreateIssueInput`, `CreatedIssue`, `TrackerTeam`.

**`listTeams()` method:**

```typescript
async listTeams(): Promise<TrackerTeam[]> {
  const teams = await this.client.teams();
  return teams.nodes.map((t) => ({ id: t.id, name: t.name, key: t.key }));
}
```

This reuses the same `this.client.teams()` call already used in `loadTeamStatuses()`.

**`createIssue(input)` method:**

1. Resolve each label name in `input.labelNames` to an ID:
   - Query `this.client.issueLabels({ filter: { name: { eq: labelName } } })`
   - If found (nodes.length > 0), use `nodes[0].id`
   - If not found, create via `this.client.createIssueLabel({ name: labelName, color: "#8B5CF6" })`, then get ID from `result.issueLabel` (awaited, since it's a promise). This follows the same pattern as the existing `ensureLabel()` method at line 234.
2. Call `this.client.createIssue({ teamId: input.teamId, title: input.title, description: input.description, labelIds })`.
3. Await `result.issue` (it's a promise in the Linear SDK).
4. If issue is null/undefined, throw `new Error("Failed to create issue")`.
5. Return `{ id: issue.id, identifier: issue.identifier, url: issue.url }`.

Note: The label resolution logic in `createIssue` duplicates the find-or-create pattern in `ensureLabel()`. This is intentional — `ensureLabel()` returns `void` (it's a fire-and-forget setup method), while `createIssue` needs the label ID. Refactoring `ensureLabel` to return an ID would change the `IssueTracker` interface contract for all implementors, which is out of scope for this task.

## Edge cases considered

- **Label resolution**: A label name might not exist yet. The implementation creates it (matching `ensureLabel` pattern with the same `#8B5CF6` color).
- **Multiple labels**: `labelNames` is an array. Each label is resolved independently. All resolved IDs are passed as `labelIds`.
- **Empty labelNames**: If `input.labelNames` is empty, `labelIds` will be an empty array, which is valid for the Linear API.
- **Issue creation failure**: The `result.issue` promise can resolve to null if the mutation fails. The method throws an explicit error.
- **Jira compatibility**: Jira stubs throw `Error("Not implemented")` to satisfy the interface. This is appropriate since Jira implementation is out of scope for this task.
