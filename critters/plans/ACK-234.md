# ACK-234: Clean up stale tmux panes from failed critters

## Summary

Failed or timed-out critters can leave orphaned tmux panes that accumulate in the session. This plan adds:
1. A `cleanupStalePanes()` function in `src/claude.ts` that identifies and kills orphaned panes
2. Automatic pane cleanup on daemon startup (in `src/index.ts`)
3. A `--panes` flag on `critters clean` for manual cleanup (in `src/cli-clean.ts`)

## Files to Modify

### 1. `src/claude.ts` — Add `cleanupStalePanes()` function

**New exported function:** `cleanupStalePanes(tmuxSession: string, activeWorkDirs: Set<string>, mainPaneId?: string)`

**Return value**: `Array<{ paneId: string; title: string; reason: string }>` — the list of panes identified as orphans. The caller decides whether to kill them or just report (dry-run). This keeps the function pure and testable.

**New function:** `killStalePanes(tmuxSession: string, panes: Array<{ paneId: string; title: string; reason: string }>)` — kills the identified panes, checking pane count before each kill to avoid destroying the session. Returns `{ killed: number; failed: number }`.

Logic for `cleanupStalePanes`:
1. Check `tmux has-session -t <session>` — return empty array if session doesn't exist
2. Run `tmux list-panes -t <session> -F '#{pane_id} #{pane_pid} #{pane_current_command} #{pane_title}'` to enumerate all panes
3. For each pane, skip if:
   - It's the main pane (matches `mainPaneId` parameter, or title starts with "Critters ")
   - Its title doesn't match the critter pane pattern
4. A critter-titled pane is orphaned if its identifier has no corresponding entry in `activeWorkDirs`
5. Return the list of orphaned panes with titles and reasons

**Pane title format** (from `buildPaneLabel`): `<IDENTIFIER>: <title> / <phase> | <repo>` optionally with `| <elapsed>` appended by the periodic updater.

**Detecting critter panes**: Parse the pane title with a regex like `/^([A-Z]+-\d+): .+ \/ (plan|exec|review|[\w-]+)/`. If the title matches, it's a critter pane. Extract the identifier to check against active work dirs.

**Key insight on orphan detection**: Since tmux panes are created with `split-window /bin/bash scriptFile` and `remain-on-exit` is not set, panes auto-close when the bash script finishes. This means stale panes are almost always ones still running a process (claude, jq, etc.) from a previous daemon run — not idle shells. The primary orphan signal is therefore "critter-titled pane with no corresponding active work dir", regardless of what process is running. At daemon startup, `activeWorkDirs` is empty, so all critter-titled panes are correctly identified as orphans from a prior run.

**Conservative safety**:
- Panes with non-critter titles are never touched (user-created panes are safe)
- The main daemon pane is always protected
- Never kill the last pane in the session

**Extract helper**: `parsePaneList(output: string)` — pure function that parses tmux list-panes output into structured objects. This is unit-testable without tmux.

### 2. `src/index.ts` — Call pane cleanup on startup

After the spawner is created and stale work dirs are cleaned (line 336-337), add:

```typescript
if (!noTmux) {
  const { cleanupStalePanes, killStalePanes } = await import("./claude.js");
  const stalePanes = await cleanupStalePanes(config.tmuxSession, spawner.getActiveWorkDirs(), mainPaneId);
  if (stalePanes.length > 0) {
    const result = await killStalePanes(config.tmuxSession, stalePanes);
    log(`Cleaned up ${result.killed} stale tmux pane(s)`);
    for (const pane of stalePanes) log(`  Killed pane ${pane.paneId}: ${pane.title} (${pane.reason})`);
  }
}
```

This runs after `spawner.cleanupStale()` (line 336) and before the watcher starts. The `mainPaneId` captured at line 309 is passed to avoid killing the daemon's own pane.

**Dependency**: Need to expose `getActiveWorkDirs()` on UnifiedSpawner. At startup, this set will be empty (no critters running yet), which is correct — all critter panes from a previous run are orphaned.

### 3. `src/cli-clean.ts` — Add `--panes` flag

Add a new branch in `runClean()` that handles `--panes`:

```typescript
if (args.includes("--panes")) {
  await cleanStaleTmuxPanes(configPath, dryRun);
  return;
}
```

**New function** `cleanStaleTmuxPanes(configPath, dryRun)`:
1. Load config to get `tmuxSession` and `healthPort`
2. Call `cleanupStalePanes()` from claude.ts with active work dirs from health endpoint
3. If dry-run: print the panes that would be killed, then return
4. Otherwise call `killStalePanes()` and print summary

### 4. `src/unified-spawner.ts` — Expose active work dirs

Add a public method if not already available:


## Edge Cases

- **No tmux session**: `cleanupStalePanes` returns empty array if `tmux has-session` fails
- **Single pane**: `killStalePanes` checks pane count before each kill to avoid destroying the session
- **Race condition**: A critter could start between enumeration and kill — mitigated by checking active work dirs at the moment of enumeration. At startup this isn't an issue since no critters are running yet
- **Non-critter panes**: User may have manually created panes — skip any pane whose title doesn't match the critter pattern
- **Daemon not running** (CLI mode): When `--panes` is used and daemon isn't running, query health endpoint returns empty active set, so all critter-titled panes are treated as orphans (correct behavior)
- **Panes still running claude**: At startup these are from a dead daemon — they should be killed. During runtime via `--panes`, the health endpoint provides active work dirs so actively-tracked panes are protected

## Testing Approach

1. **Unit tests**: `parsePaneList()` is a pure function — test with sample tmux output strings to verify correct parsing and orphan detection
2. **Manual testing**: Start daemon, create critter panes, kill the daemon, verify panes remain, restart daemon — confirm stale panes are cleaned on startup
3. **CLI testing**: Run `critters clean --panes --dry-run` to verify detection without killing
4. **Edge case testing**: Verify that manually-created panes (non-critter titles) are not killed, and that the last pane is never killed
