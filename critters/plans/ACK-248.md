# ACK-248: Dashboard — Show Live Cost on Active Critters

## Summary

Add a "Cost" column to the active critters table on the dashboard that displays the running cost for each active critter. When a `costBudget` is configured, show cost as a fraction with color-coding based on budget usage percentage. Cost updates naturally with the dashboard's 30-second auto-refresh.

## Files to Modify

### 1. `src/types.ts` — Add `costUsd` to `ActiveCritterDetail`

Add two optional fields to the `ActiveCritterDetail` interface:

```ts
costUsd?: number;        // running cost in USD
costBudget?: number;     // effective cost budget (if configured)
```

The `costBudget` field is included so the dashboard can render budget fractions and color-coding without needing separate config access.

**b. Always create the cost monitoring interval (line ~440-458):**

Currently the cost monitoring interval only runs when `effectiveCostBudget != null`. For dashboard display, we want cost tracking always. Remove the `if (effectiveCostBudget != null)` guard and always create the interval. Inside it, always compute and update `detail.costUsd`. Only check budget exceeded if `effectiveCostBudget != null`.

```ts
const phaseTag = phaseFileTag(phase.name);
const outputFile = `${workDir}/.critter-output-${phaseTag}.json`;
const costMonitorInterval = setInterval(() => {
  const currentPhaseCost = readPartialCost(outputFile);
  const completedPhaseCost = phaseResults.reduce((sum, r) => sum + (r.costUsd ?? 0), 0);
  const totalCost = completedPhaseCost + currentPhaseCost;
  // Update active detail for dashboard
  const activeDetail = this.activeCritterMap.get(task.id);
  if (activeDetail) activeDetail.costUsd = totalCost;
  // Budget enforcement (only when budget is configured)
  if (effectiveCostBudget != null && totalCost > effectiveCostBudget) {
    logTask(task.identifier, `Cost budget exceeded: $${totalCost.toFixed(2)} spent, $${effectiveCostBudget.toFixed(2)} budget`);
    costBudgetExceeded = true;
    costBudgetSpent = totalCost;
    costBudgetLimit = effectiveCostBudget;
    costBudgetPhase = phase.name;
    abortController.abort();
  }
}, 30_000);
costMonitorInterval.unref();
```

The `clearInterval` in the existing `finally` block already handles cleanup. The `let costMonitorInterval` declaration and conditional clear need to be adjusted to always declare and always clear.

### 4. `src/dashboard.ts` — Add Cost column to active critters table

**a. Add table header** (line ~586, between "PR" and "Elapsed"):

```html

```

**b. Add table cell** in the row rendering (line ~611-617), between the PR cell and the elapsed cell:

```ts
const costCell = (() => {
  if (d.costUsd == null || d.costUsd === 0) return '<span style="color:var(--text-muted)">&mdash;</span>';
  const costStr = `$${d.costUsd.toFixed(2)}`;
  if (d.costBudget != null && d.costBudget > 0) {
    const pct = d.costUsd / d.costBudget;
    const color = pct > 0.8 ? "var(--failure)" : pct > 0.5 ? "#e2b93d" : "var(--success)";
    return `<span style="color:${color}">${costStr} / $${d.costBudget.toFixed(2)}</span>`;
  }
  return costStr;
})();
```

Add the cell:
```html
<td>${costCell}</td>
```

Color-coding matches the existing dashboard patterns:
- Green (`var(--success)` / `#4ecca3`): < 50% of budget
- Yellow (`#e2b93d`): 50-80% of budget — same color used by `.elapsed-warn`
- Red (`var(--failure)` / `#e94560`): > 80% of budget — same color used by `.elapsed-danger`

## Edge Cases

1. **No cost data yet**: When a critter just started and no output file exists, `readPartialCost` returns 0. The dashboard shows "—" for zero/undefined cost.
2. **No cost budget configured**: Shows just the dollar amount without fraction or color-coding.
3. **Cost budget is 0**: Treated as "no budget" (`costBudget > 0` check).
4. **Multiple phases**: Cost accumulates across phases correctly — completed phase costs from `phaseResults` plus current phase's partial cost.
5. **CSS colors**: Uses existing dashboard color conventions — `var(--success)`, `#e2b93d`, `var(--failure)` — matching the elapsed time column's color-coding pattern.
