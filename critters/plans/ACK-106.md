# ACK-106: Add configurable planning and execution model options

## Summary

Add `planningModel` and `executionModel` config fields so users can choose different Claude models for each phase (e.g., plan with opus, execute with sonnet). Both default to `"opus"` to preserve existing behavior.

## Files to modify

### 1. `src/types.ts` — Add new fields to Config interface

Add two new string fields to the `Config` interface, after `noTmux` (line 29):

```typescript
planningModel: string;
executionModel: string;
```

### 2. `src/config.ts` — Parse new fields from YAML

In `loadConfig()`, add the two fields to the config object literal (around line 119, after `noTmux: false`):

```typescript
planningModel: (yaml.planningModel as string) ?? "opus",
executionModel: (yaml.executionModel as string) ?? "opus",
```

This follows the exact same pattern used for other string config fields like `triggerLabel` (line 114) and `tmuxSession` (line 118). No additional validation is needed — invalid model values will be caught by the Claude CLI at runtime.

### 3. `src/claude.ts` — Accept model parameter in both spawn functions

**`spawnClaude()`** (line 22): Add a `model: string` parameter after `tmuxSession`:

```typescript
export async function spawnClaude(
  prompt: string,
  allowedTools: string[],
  workDir: string,
  maxTurns: number,
  identifier: string,
  phase: string,
  tmuxSession: string,
  model: string,
  signal?: AbortSignal,
): Promise<SpawnResult> {
```

In the bash script template (line 62), replace the hardcoded `--model opus` with:

```
--model ${shellEscape(model)}
```

## Dependencies / Setup

None — this is a pure config-plumbing change with no new dependencies.

## Testing approach

1. **Type-check**: Run `bun run tsc --noEmit` (or equivalent) to verify no type errors after the changes.
2. **Default behavior**: Start the daemon with no `planningModel`/`executionModel` in config — both should default to `"opus"`, preserving current behavior.
3. **Custom models**: Set `planningModel: sonnet` and `executionModel: opus` in `critters.config.yaml`, run a critter, and verify the tmux pane or subprocess command includes the correct `--model` flag for each phase.
4. **Invalid model**: Set an invalid model name and verify the Claude CLI surfaces an appropriate error (no critters-side validation needed).
