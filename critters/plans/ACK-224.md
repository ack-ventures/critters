# ACK-224: Always log daemon output to file, even in tmux mode

## Summary

Currently, file logging (`initFileLogging()`) is only called when `--no-tmux` is used without `--json-logs`. This means in tmux mode, if the process crashes, the only record is the tmux scrollback buffer. The fix ensures `initFileLogging()` is always called so logs persist to `~/.critters/critters.log` regardless of mode.

## Key Finding

The task description states that `writeLog` in `src/logger.ts` "already writes to both the log file AND stdout/stderr when a log file is set." **This is incorrect.** The current code uses an `if/else if/else` chain (lines 172–188), meaning it writes to the file OR console, never both. To achieve the desired behavior (file + console in tmux mode), the logger must also be updated.

## Files to Modify

### 1. `src/index.ts` (line 293–295)

**Current code:**
```typescript
if (noTmux && !jsonLogs) {
  initFileLogging(config.maxLogSizeMb);
}
```

**New code:**
```typescript
if (!jsonLogs) {
  initFileLogging(config.maxLogSizeMb);
}
```

We keep the `!jsonLogs` guard because when `--json-logs` is enabled, the `writeJsonLog` function has its own file-writing path that also needs the file initialized. Actually, looking more carefully at `writeJsonLog` (lines 143–162), it also uses `if (logFile)` with an `else` — same pattern. So for `--json-logs` mode, we should also init file logging.

**Revised new code:**
```typescript
initFileLogging(config.maxLogSizeMb);
```

Remove the condition entirely. Always call `initFileLogging()`. This works for all modes:
- `--no-tmux` (no json): file + stdout (after logger fix)
- `--no-tmux --json-logs`: file + stdout (structured JSON)
- tmux mode (no json): file + colored console
- tmux mode + `--json-logs`: file + structured JSON to stdout

### 2. `src/logger.ts` — `writeLog` function (lines 164–189)

Change the `if/else` chain so that when `logFile` is set, the log is written to **both** the file and the console.

**Current logic (simplified):**
```
if logFile → write to file only
else if ERROR → console.error (colored)
else if WARN → console.warn (colored)
else → console.log (colored)
```

**New logic:**
```
if logFile → write to file
// Always write to console (not else-if)
if ERROR → console.error (colored)
else if WARN → console.warn (colored)
else → console.log (colored)
```

This means removing the `else` before the console output branches, so console output always happens regardless of whether `logFile` is set.

### 3. `src/logger.ts` — `writeJsonLog` function (lines 143–162)

Same pattern fix. Currently writes to file OR stdout/stderr. Should write to file AND stdout/stderr.

**Current logic:**
```
if logFile → write to file only
else if ERROR → stderr
else → stdout
```

**New logic:**
```
if logFile → write to file
// Always write to stdout/stderr
if ERROR → stderr
else → stdout
```

## Files NOT Modified

- No config changes needed
- No test changes needed (behavior is additive)
- `src/logger.ts` exports (`initFileLogging`, `log`, etc.) — signatures unchanged

## Edge Cases

1. **Dry-run mode**: `initFileLogging()` is called after the dry-run early-exit (line 262–274), so dry runs won't create log files. This is correct — dry runs are short-lived and log to console only.

   Wait — actually, looking at the code flow: `config.noTmux = noTmux || dryRun` is set at line 230, and the `initFileLogging` call is at line 293–295, which is after the dry-run exit at line 262–274. So dry runs already exit before reaching the logging init. No issue here.

2. **Log rotation**: `initFileLogging` sets up an hourly rotation timer. This already works correctly and is unref'd so it won't keep the process alive.

3. **`--json-logs` mode**: With the logger fix, `writeJsonLog` will write structured JSON to both the file and stdout/stderr. This is the desired behavior — json-logs users get structured output on stdout for piping AND a persistent file.

4. **Console colors in file**: The file gets plain text (no ANSI codes) because `writeLog` uses `formatted` (plain) for the file and `colorizeForConsole` (colored) for console output. These are already separate code paths, so no color codes will leak into the log file.

## Testing Approach

1. **Manual test (tmux mode)**: Start the daemon in tmux without `--no-tmux`. Verify `~/.critters/critters.log` is created and receives log entries. Verify console still shows colored output.
2. **Manual test (`--no-tmux`)**: Start with `--no-tmux`. Verify both file and console output work (regression test).
3. **Manual test (`--json-logs`)**: Start with `--json-logs`. Verify structured JSON appears in both the file and stdout.
4. **Log rotation**: Verify rotation still works by checking the timer is set up.

## Risk Assessment

Low risk. The change is additive — we're enabling an existing capability in more scenarios. The logger changes are minimal (removing `else` keywords). No new dependencies or APIs.
