#### `describe("resolveRepoUrl")`

Uses minimal `CritterTask` and `Config` objects. Tests the priority chain:

| Test | Scenario | Expected |
|------|----------|----------|
| from description (highest priority) | task with `repo:` in description | returns URL from description |
| from project config (2nd priority) | task with projectId matching config.repos entry, no repo in description | returns config.repos[projectId].url |
| from team config (3rd priority) | task with teamId matching config.teamRepos, no project match | returns config.teamRepos[teamId] |
| returns null when nothing matches | task with no repo line, no project/team config | `null` |
| description takes priority over project config | task with both repo line and project config | returns URL from description |
| project config takes priority over team config | task with both project and team config, no description URL | returns project config URL |

## Dependencies / Setup

- No new dependencies needed

## Testing Approach

- Use `import { describe, test, expect } from "bun:test"` (matching existing patterns)
- Group tests in nested `describe` blocks: outer block per source file, inner block per function
- Focus on edge cases alongside happy paths (empty strings, boundary values, null/undefined fields)
- Use `toBeGreaterThan(0)` / `toBeLessThan(0)` for `compareSemver` sign checks (exact return values are implementation detail)
- Use `toBe` for string comparisons, `toEqual` for objects
- Construct minimal mock objects for `resolveRepoUrl` tests — only include fields needed by the function
