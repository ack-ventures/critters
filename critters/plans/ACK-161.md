# ACK-161: Fix GCS upload content-type header mismatch in uploadFileToIssue

## Summary

The `uploadFileToIssue` function in `src/linear.ts` passes a `contentType` to `client.fileUpload()`, which includes it in the GCS signed URL signature. However, the subsequent PUT request to GCS only forwards headers from `uploadFile.headers`. If `content-type` is not present in that header list, GCS returns a `400 MalformedSecurityHeader` error because the signed URL expects the header but the request doesn't include it.

## Files to Modify

### `src/linear.ts` (lines 281-285)

**Current code:**
```ts
const headers: Record<string, string> = {};
for (const h of uploadFile.headers) {
  headers[h.key] = h.value;
}
```

**Changed code:**
```ts
const headers: Record<string, string> = {};
for (const h of uploadFile.headers) {
  headers[h.key] = h.value;
}
if (!headers["content-type"] && !headers["Content-Type"]) {
  headers["content-type"] = contentType;
}
```

After building the headers map from `uploadFile.headers`, check whether `content-type` is already present (case-insensitive check covering the two common casings). If absent, add it using the `contentType` parameter that was already passed to `client.fileUpload()`.

## Dependencies

None. This is a self-contained fix within a single function.

## Risk Assessment

**Low risk.** The added check is defensive — it only sets the header when it's missing, so if the Linear SDK starts including `content-type` in `uploadFile.headers` in the future, this code becomes a no-op. The fix uses the same `contentType` value that was already used in the `fileUpload()` call, ensuring consistency with the signed URL.
