# ACK-255: Add `--type` filter to `critters history` command

> **Note**: This is an **implementation plan** — a design document describing what changes will be made during the execution phase. The files described below do not yet exist or have not yet been modified. The plan is approved based on correctness and completeness of the *design*, not whether the code changes have been applied.

## Summary

Add an optional `--type NAME` flag to the `critters history` CLI command that filters displayed history entries by critter type name (e.g., `critters history --type review`). The core filtering logic already exists in `src/cli-history.ts`; this task adds test coverage and a minor export change.

## Current State

The `--type` filter is **already implemented** in `src/cli-history.ts` on the `main` branch:

1. **Flag parsing** (lines 48-53): `parseArgs()` already handles `--type` with proper error messaging for missing values.
2. **Filtering** (lines 80-82): `runHistory()` already filters `results` by `m.critterType === opts.type`.
3. **Help text** (in `src/index.ts` lines 91-92): The history help section already documents `--type NAME — Filter by critter type`.
4. **JSON output** (lines 96-106): The `--json` output includes `critterType` in the output.

The implementation follows the same pattern as `--dry-run --type` in `src/index.ts` (lines 247-248) — reading the next argv element after the `--type` flag.

### 2. Create `src/__tests__/cli-history.test.ts`

#### Mock setup and module import order

The test file uses the same `mock.module()` → `await import()` pattern proven in `src/__tests__/cli-retry.test.ts` (lines 27-34). This pattern works because Bun's `mock.module()` intercepts the named import at load time when called before the first `await import()`:

```typescript
import { beforeEach, describe, expect, mock, spyOn, test } from "bun:test";
import type { MetricEvent } from "../metrics.js";

// 1. Set up mock BEFORE importing the module under test
const mockReadAllMetrics = mock<() => MetricEvent[]>(() => []);
mock.module("../metrics.js", () => ({
  readAllMetrics: mockReadAllMetrics,
}));

// 2. Dynamic import AFTER mock is registered
const { runHistory, parseArgs } = await import("../cli-history.js");
```

This is identical to `cli-retry.test.ts` lines 27-34 where `mock.module("../tracker/index.js", ...)` is called before `await import("../cli-retry.js")`.

#### beforeEach cleanup

Following the `cli-retry.test.ts` pattern (lines 55-67):

```typescript
let consoleErrorSpy: ReturnType<typeof spyOn>;
let consoleLogSpy: ReturnType<typeof spyOn>;

beforeEach(() => {
  mockReadAllMetrics.mockReset();
  mockReadAllMetrics.mockReturnValue([]);

  spyOn(process, "exit").mockImplementation(() => {
    throw new Error("process.exit called");
  });
  consoleErrorSpy = spyOn(console, "error").mockImplementation(() => {});
  consoleLogSpy = spyOn(console, "log").mockImplementation(() => {});
});
```

#### Test cases

**`parseArgs` tests:**
- Default values: returns `{ last: 20, failed: false, type: null, json: false }`
- `--type review`: returns `{ ..., type: "review" }`
- `--type` without a value: calls `process.exit(1)` with error message
- Combination `--type create --failed --last 5 --json`: returns `{ last: 5, failed: true, type: "create", json: true }`

**`runHistory` integration tests:**
- No `--type`: all completion events shown (4 from mock data)
- `--type create`: only events with `critterType === "create"` shown (2 from mock data: ACK-100 completed, ACK-101 failed)
- `--type review`: only review events shown (2: ACK-102 completed, ACK-103 failed)
- `--type nonexistent`: prints "No matching runs found." (not "No history found." which is the empty-metrics path)
- `--type create --failed`: only failed create events (1: ACK-101)
- `--type create --json`: JSON output contains only create events, verify each output object has `type: "create"`
- `--type create` filters out metrics with undefined critterType (ACK-105 in mock data has no `critterType`, should not appear in `--type create` results)
