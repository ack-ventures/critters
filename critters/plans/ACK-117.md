# ACK-117: Add Log Rotation

## Summary

Add log rotation to prevent `~/.critters/critters.log` from growing unbounded. The rotation utility will be implemented in `src/logger.ts` as an exported function so it can also be used by any future metrics module for `metrics.jsonl` rotation. Rotation is configurable via `maxLogSizeMb` in the config and triggered both at startup and periodically during runtime.

## Files to Modify

### 1. `src/logger.ts` — Add rotation utility and integrate it

**Add `rotateFileIfNeeded(filePath: string, maxSizeMb: number, maxFiles: number = 3)` exported function:**
- Uses `Bun.file(filePath).size` to check current file size. Note: `Bun.file(path).size` returns 0 for non-existent files (does not throw), so no special handling is needed for missing files — they simply won't exceed the threshold.
- If size exceeds `maxSizeMb * 1024 * 1024`:
  - Working backward from `maxFiles` to 1:
    - Delete `filePath.{maxFiles}` if it exists (using `unlinkSync`)
    - Rename `filePath.{N}` → `filePath.{N+1}` for N from `maxFiles-1` down to 1 (using `renameSync` from `node:fs`)
  - Rename `filePath` → `filePath.1`
  - After rotation, the original file path no longer exists. The next `appendFileSync` call in `writeLog` will implicitly recreate it as an empty file. This is standard Node/Bun behavior and requires no explicit action.
- Wrap entire rotation in try/catch — on failure, log a warning via `console.warn()` (not via `writeLog` to avoid recursion) and continue
- Default `maxFiles` parameter: 3

**Modify `initFileLogging()` to accept optional `maxLogSizeMb` parameter (default: 10) and optional `logDir` parameter (default: `join(homedir(), ".critters")`) for testability:**
- After setting `logFile`, call `rotateFileIfNeeded(logFile, maxLogSizeMb, 3)` to rotate on startup
- Store `maxLogSizeMb` in module-level variable for periodic rotation

**Add periodic rotation (write-counter + timer):**
- Add a module-level write counter (`writeCount`)
- In `writeLog()`, increment counter after each `appendFileSync` call
- Every 1000 writes, call `rotateFileIfNeeded(logFile, storedMaxLogSizeMb, 3)`
- Also start a `setInterval` timer in `initFileLogging()` that checks rotation once per hour (3600000ms), for cases where writes are infrequent but the file grows due to external factors or long-running sessions. Call `.unref()` on the timer so it doesn't prevent process exit.
- Wrap both periodic checks in try/catch to never crash the daemon

## Dependencies

No new dependencies needed. Uses only:
- `Bun.file()` — already available in the Bun runtime
- `node:fs` (`renameSync`, `unlinkSync`, `existsSync`) — already imported in the project

## Edge Cases

- **File doesn't exist:** `Bun.file(path).size` returns 0 for non-existent files, so no rotation is triggered — correct behavior
- **Permission errors:** Caught by outer try/catch, logged as `console.warn()` warning
- **Concurrent access:** `renameSync` is atomic on POSIX. The rotation only runs from the main thread (single-threaded Bun), so no locking needed
- **Recursion risk:** `rotateFileIfNeeded` uses `console.warn()` for its own error logging, not `writeLog()`, to avoid infinite recursion
- **Post-rotation file recreation:** After rotating `filePath` → `filePath.1`, the next `appendFileSync` in `writeLog` implicitly recreates the original path as an empty file — no explicit creation needed
- **Future `metrics.jsonl` usage:** `rotateFileIfNeeded` is exported and stateless, so any future metrics module can call it directly with its own file path and size limits

## Testing Approach

- All tests run with `bun test`
- Tests use temp directories (via `createTempDir()` helper) to avoid polluting the real filesystem
- `initFileLogging` accepts an optional `logDir` parameter to enable testing without writing to `~/.critters/`
- Tests create files of known sizes and verify rotation behavior
- No mocking needed — tests operate on real temp files
- Pattern follows existing test files: `bun:test` imports, `beforeEach`/`afterEach` lifecycle, `describe`/`test` structure
- Existing `config.test.ts` updated to cover the new `maxLogSizeMb` field
