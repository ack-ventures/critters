# ACK-223: Add global unhandled rejection/exception handlers

## Summary

Add `process.on("unhandledRejection")` and `process.on("uncaughtException")` handlers early in the `main()` function of `src/index.ts` to prevent the daemon from crashing when async code throws without a `.catch()` or when synchronous exceptions go uncaught. These handlers will log the full stack trace using the existing `logError()` function and allow the daemon to continue running.

## Files to modify

### `src/index.ts`

Add two global error handlers at the very beginning of the `main()` function (line 184, right after `async function main() {`), before any other initialization. This ensures they are active as early as possible, catching errors from config loading, tracker init, and the poll loop.

```ts
process.on("unhandledRejection", (reason) => {
  logError(`Unhandled rejection: ${reason instanceof Error ? reason.stack ?? reason.message : String(reason)}`);
});

process.on("uncaughtException", (err) => {
  logError(`Uncaught exception: ${err.stack ?? err.message}`);
});
```

**Placement rationale**: These must go before `loadEnvFallback()`, `loadConfig()`, tracker init, and the `watcher.start()` poll loop — all of which are async and could produce unhandled rejections. Placing them as the first lines of `main()` maximizes coverage. They should be inside `main()` (not at module top level) because the subcommand routing above `main()` exits early and doesn't need daemon-level resilience.

**No other files need changes.** The `logError` function is already imported from `./logger.js` on line 14.

## Dependencies

None. Uses only the existing `logError` import and Node.js `process` global.

## Testing approach

1. **Manual verification**: Add a temporary `setTimeout(() => { throw new Error("test uncaught"); }, 5000)` inside `main()` after the handlers are registered. Start the daemon and confirm it logs the error with full stack trace but does not exit.
2. **Manual rejection test**: Add `setTimeout(() => { Promise.reject(new Error("test rejection")); }, 5000)` and verify the same behavior.
3. **Code review**: Confirm the handlers are placed before all async operations in `main()`.
4. **CI**: Existing `bun run lint` and `bun run typecheck` should pass with no changes needed beyond the two `process.on` calls.
