# ACK-155: Cache computeMetricsSummary in health server

## Summary

Add a 30-second TTL cache to `computeMetricsSummary()` in `src/health.ts` so that repeated `/healthz` requests don't re-read and re-parse the entire metrics JSONL file on every call.

## Files to modify

### `src/health.ts`

1. Add two module-level variables after the imports:
   ```ts
   let cachedSummary: { totalTasks: number; succeeded: number; failed: number } | null = null;
   let cachedAt = 0;
   ```

2. At the top of `computeMetricsSummary()`, add an early return for cache hits:
   ```ts
   const now = Date.now();
   if (cachedSummary && now - cachedAt < 30_000) {
     return cachedSummary;
   }
   ```

3. Before the return statement, update the cache:
   ```ts
   cachedSummary = { totalTasks, succeeded, failed };
   cachedAt = Date.now();
   return cachedSummary;
   ```

4. Export a `resetMetricsCache()` function for test use:
   ```ts
   export function resetMetricsCache(): void {
     cachedSummary = null;
     cachedAt = 0;
   }
   ```

The full updated function:
```ts
let cachedSummary: { totalTasks: number; succeeded: number; failed: number } | null = null;
let cachedAt = 0;

function computeMetricsSummary(): { totalTasks: number; succeeded: number; failed: number } {
  const now = Date.now();
  if (cachedSummary && now - cachedAt < 30_000) {
    return cachedSummary;
  }
  const all = getRecentMetrics(10000);
  let totalTasks = 0;
  let succeeded = 0;
  let failed = 0;
  for (const m of all) {
    if (m.event === "task_completed") {
      totalTasks++;
      succeeded++;
    } else if (m.event === "task_failed") {
      totalTasks++;
      failed++;
    }
  }
  cachedSummary = { totalTasks, succeeded, failed };
  cachedAt = Date.now();
  return cachedSummary;
}

export function resetMetricsCache(): void {
  cachedSummary = null;
  cachedAt = 0;
}
```

### `src/__tests__/health.test.ts`

1. Import `resetMetricsCache` from `../health.js`.

2. Call `resetMetricsCache()` in the existing `beforeEach` (or `afterEach`) to ensure each test starts with a clean cache. This prevents the cache from leaking state between tests — since multiple tests call `/healthz` and assert on metrics values, a stale cache could cause false passes or failures.

3. Add a new test case in the `GET /healthz` describe block to verify caching behavior:
   ```ts
   test("caches metrics summary across rapid requests", async () => {
     const metricsFile = join(tempDir, "metrics.jsonl");
     initMetrics(metricsFile);
     recordMetric({ timestamp: "", event: "task_completed", issueId: "C-1" });

     const port = 10000 + Math.floor(Math.random() * 50000);
     server = startHealthServer(port, defaultStatus);

     // First request computes fresh
     const res1 = await fetch(`http://localhost:${port}/healthz`);
     const body1 = await res1.json();
     expect(body1.metrics.totalTasks).toBe(1);
     expect(body1.metrics.succeeded).toBe(1);

     // Add another metric — but cache should still return old value
     recordMetric({ timestamp: "", event: "task_failed", issueId: "C-2" });

     const res2 = await fetch(`http://localhost:${port}/healthz`);
     const body2 = await res2.json();
     // Should still be cached (1 task, not 2)
     expect(body2.metrics.totalTasks).toBe(1);
     expect(body2.metrics.succeeded).toBe(1);
     expect(body2.metrics.failed).toBe(0);
   });
   ```

## Dependencies / setup

None — this is a self-contained change within `src/health.ts` and its existing test file.

## Testing approach

1. Run `bun run typecheck` to verify no type errors.
2. Run `bun test` to verify all existing tests pass (the `resetMetricsCache()` call in `beforeEach`/`afterEach` ensures cache doesn't leak between tests).
3. The new test verifies that within the TTL window, the cached value is returned even after new metrics are recorded.
