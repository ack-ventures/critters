# ACK-165: Add a `--version` flag alias for the `version` subcommand

## Summary

Currently `critters version` prints the version, but `critters --version` falls through to the daemon startup (since `--version` starts with `--`, it passes the unknown command guard at line 108). This plan adds `--version` as an alias so both forms work identically.

## Files to Modify

### `src/index.ts`

**Change 1: Expand the `version` subcommand check (line 28)**

Current code:
```ts
if (subcommand === "version") {
```

Change to:
```ts
if (subcommand === "version" || subcommand === "--version") {
```

This is the only code change needed. The `--version` flag will be matched from `Bun.argv[2]`, same as the `version` subcommand, and will execute the identical logic: fetch the latest version, print it, and exit.

**No other changes required.** The unknown-command guard at line 108 (`if (subcommand && !subcommand.startsWith("--"))`) already skips flags starting with `--`, so `--version` was silently falling through to the daemon. After this change, it will be caught before reaching that guard.

## Why this is sufficient

- `--version` is always the first argument after the binary name (`Bun.argv[2]`), matching the same position as all other subcommands.
- The existing `version` handler already does everything needed (fetch latest version, display, exit).
- No changes to the help text are needed since `--version` is a standard CLI convention that users expect to work without it being documented.
- No changes to `--help` are in scope — that's a separate concern.

## Testing Approach

1. Run `bun run src/index.ts --version` and verify it prints the version and exits (same output as `bun run src/index.ts version`).
2. Run `bun run src/index.ts version` to verify existing behavior is unchanged.
3. Run the existing test suite (`bun test`) to check for regressions.
4. Verify the TypeScript compiles cleanly (`bun run typecheck`).
