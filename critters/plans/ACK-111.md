# ACK-111: Add shared retry utility with exponential backoff

## Summary

Create a generic `withRetry<T>()` utility in `src/retry.ts` that provides exponential backoff with jitter, then migrate the two existing inline retry implementations (`shallowClone` in `src/git.ts` and `detectPr` in `src/spawner.ts`) to use it. Add retries to the currently-unretried Linear polling queries (`findCritterIssues`, `findReviewIssues`) and Slack webhook notifications.

## Files to Create

### `src/retry.ts` — New shared retry utility

Export a single generic function:

```typescript
export interface RetryOptions {
  maxRetries: number;
  baseDelayMs: number;
  maxDelayMs?: number;           // default: 30000
  jitter?: boolean;              // default: true — adds 0-25% random jitter
  shouldRetry?: (error: unknown) => boolean;  // default: always retry
  onRetry?: (error: unknown, attempt: number, delayMs: number) => void;  // optional hook for logging
}

export async function withRetry<T>(
  fn: () => Promise<T>,
  options: RetryOptions,
): Promise<T>
```

**Backoff formula:** `delay = min(baseDelayMs * 2^attempt, maxDelayMs)` where `attempt` is 0-indexed (first retry = attempt 0). When jitter is enabled, add `Math.random() * 0.25 * delay` to the computed delay.

**Behavior:**
- Calls `fn()` up to `maxRetries + 1` times total (1 initial + N retries)
- On failure, checks `shouldRetry(error)` — if false, rethrows immediately
- Calls `onRetry` callback if provided before waiting
- Logs retry attempts via `log()` from `src/logger.ts`: `"Retry {attempt}/{maxRetries} in {delayMs}ms..."`
- After exhausting all retries, rethrows the last error
- Uses `sleep()` from `src/utils.ts` for delays

## Files to Modify

### `src/git.ts` — Migrate `shallowClone()` retry logic

**Current:** Inline 3-retry loop with `attempt * 2000`ms delay, ENOENT-specific filter, and directory cleanup between retries.

**Change:** Replace the manual retry loop with `withRetry()`. The tricky part is that `shallowClone` has special behavior:
- It needs to clean up `targetDir` between retries on ENOENT
- The retry condition checks both non-zero exit code and thrown ENOENT errors

**New implementation:**

```typescript
export async function shallowClone(
  repoUrl: string,
  targetDir: string,
  identifier: string,
  cwd?: string,
): Promise<void> {
  await withRetry(
    async () => {
      logTask(identifier, `Cloning ${repoUrl} → ${targetDir}`);
      const { code, stderr } = await runCommand(
        "git",
        ["clone", "--depth", "1", repoUrl, targetDir],
        cwd ? { cwd } : undefined,
      );
      if (code !== 0) {
        throw new Error(`git clone failed: ${stderr}`);
      }
    },
    {
      maxRetries: 3,
      baseDelayMs: 2000,
      maxDelayMs: 8000,
      shouldRetry: (error) => {
        const msg = error instanceof Error ? error.message : String(error);
        return msg.includes("ENOENT");
      },
      onRetry: (error, attempt, delayMs) => {
        logTaskWarn(identifier, `git clone failed (ENOENT), retrying in ${delayMs}ms...`);
        if (existsSync(targetDir)) rmSync(targetDir, { recursive: true, force: true });
      },
    },
  );
}
```

**Import changes:** Add `import { withRetry } from "./retry.js";`

**Note on behavior change:** The original uses `attempt * 2000` (linear: 2s, 4s, 6s). The new version uses exponential: `2000 * 2^attempt` = 2s, 4s, 8s. This is close enough and more robust for real network issues. Also the original has `MAX_RETRIES = 3` which means 3 total attempts (the loop runs `attempt = 1..3`). With `withRetry({ maxRetries: 3 })` we get 1 initial + 3 retries = 4 total attempts — one more than before. To preserve the original behavior exactly, use `maxRetries: 2` (1 initial + 2 retries = 3 total). We'll use `maxRetries: 2` to match.

### `src/spawner.ts` — Migrate `detectPr()` retry logic

**Current:** Inline 5-retry loop with fixed 3000ms delay, no error filtering.

**Change:** Replace with `withRetry()`. The `detectPr` function is a standalone module-level function (not a class method). It returns `null` on exhaustion rather than throwing.

**New implementation:**

```typescript
async function detectPr(
  workDir: string,
  branch: string,
  identifier: string,
): Promise<string | null> {
  try {
    return await withRetry(
      async () => {
        const { code, stdout, stderr } = await runCommand(
          "gh",
          ["pr", "list", "--head", branch, "--json", "url", "--limit", "1"],
          { cwd: workDir },
        );

        if (code !== 0) {
          throw new Error(`gh pr list failed: ${stderr}`);
        }

        const prs = JSON.parse(stdout);
        if (prs.length > 0) {
          return prs[0].url as string;
        }
        throw new Error("PR not found yet");
      },
      {
        maxRetries: 4,
        baseDelayMs: 3000,
        maxDelayMs: 15000,
        onRetry: (_error, attempt, delayMs) => {
          logTask(identifier, `PR not found yet, retrying in ${delayMs}ms... (attempt ${attempt + 1}/4)`);
        },
      },
    );
  } catch {
    logTaskError(identifier, "PR not detected after 5 attempts");
    return null;
  }
}
```

**Import changes:** Add `import { withRetry } from "./retry.js";` — remove `sleep` from utils import since it's no longer directly used (only if `sleep` is no longer used elsewhere in the file — check: `sleep` is used in `spawner.ts` only by `detectPr`, so it can be removed from the import).

**Note:** `maxRetries: 4` gives 5 total attempts, matching the original `MAX_RETRIES = 5`. The original used fixed 3s delay; the new version starts at 3s and grows exponentially (3s, 6s, 12s, 15s cap), which is better for PR detection where GitHub may need more time.

### `src/slack.ts` — Add retries to webhook notification

**Change `sendSlackNotification()`:**

Wrap the `fetch()` call with `withRetry`. The existing try/catch should be preserved as the outer error handler so the daemon never crashes from Slack failures.

```typescript
export async function sendSlackNotification(
  webhookUrl: string | undefined,
  message: string,
): Promise<void> {
  if (!webhookUrl) return;

  try {
    await withRetry(
      async () => {
        const response = await fetch(webhookUrl, {
          method: "POST",
          headers: { "Content-Type": "application/json" },
          body: JSON.stringify({ text: message }),
        });

        if (!response.ok) {
          throw new Error(`Slack webhook returned ${response.status}`);
        }
      },
      {
        maxRetries: 2,
        baseDelayMs: 1000,
        onRetry: (error, attempt, delayMs) => {
          logError(`Slack notification failed, retrying in ${delayMs}ms... (attempt ${attempt + 1}/2)`);
        },
      },
    );
  } catch (err) {
    logError(`Slack notification failed: ${err}`);
  }
}
```

**Import changes:** Add `import { withRetry } from "./retry.js";`

## Files to Create — Tests

### `src/__tests__/retry.test.ts`

Test the `withRetry` utility using `bun:test`. Follow existing patterns from `src/__tests__/utils.test.ts`.

**Test cases:**

1. **Succeeds on first try** — `fn` succeeds, no retries happen
2. **Succeeds after retries** — `fn` fails twice then succeeds, verify 3 total calls
3. **Exhausts all retries** — `fn` always fails, verify it throws the last error, verify `maxRetries + 1` total calls
4. **`shouldRetry` returns false** — `fn` fails with non-retryable error, verify immediate rethrow after 1 call
5. **`shouldRetry` returns true** — `fn` fails with retryable error, verify retries proceed
6. **`onRetry` callback** — verify `onRetry` is called with correct `(error, attempt, delayMs)` args
7. **Exponential backoff delays** — mock `sleep` to capture delays, verify `baseDelayMs * 2^attempt` pattern
8. **`maxDelayMs` caps the delay** — verify delay never exceeds `maxDelayMs`
9. **Jitter** — verify delay is within expected range (baseDelay to baseDelay * 1.25) when jitter is enabled
10. **Jitter disabled** — verify exact delay when `jitter: false`
11. **Return value preserved** — verify `withRetry` returns the value from `fn`

**Testing approach:** Mock `sleep` from `src/utils.ts` using `bun:test`'s `mock()` to avoid real delays and capture timing. Use `vi.fn()` / `mock()` for `fn` to control success/failure sequence.

- The `shallowClone` retry count changes from 3 total attempts to 3 total (maxRetries: 2) to preserve behavior
