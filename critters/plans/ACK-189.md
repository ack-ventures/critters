# ACK-189: Add metrics retention with automatic pruning

## Summary

The `~/.critters/metrics.jsonl` file grows indefinitely. This change adds a `metricsRetentionDays` config option (default: 90) and a `pruneMetrics()` function that removes old entries on daemon startup.

## Files to modify

### 1. `src/types.ts` — Add config field

Add `metricsRetentionDays: number` to the `Config` interface (after `healthPort`).

### 2. `src/config.ts` — Parse and validate the new field

In `loadConfig()`, add to the config object:
```typescript
metricsRetentionDays: (yaml.metricsRetentionDays as number) ?? 90,
```

In `validateConfig()`, add validation:
```typescript
if (config.metricsRetentionDays < 1) {
  throw new Error(`Invalid config: metricsRetentionDays must be >= 1, got ${config.metricsRetentionDays}`);
}
```

### 3. `src/metrics.ts` — Add `pruneMetrics()` function

Add a new exported function `pruneMetrics(retentionDays: number)`:

1. If `metricsFile` is not initialized, return early
2. Read the file content. If file doesn't exist or is empty, return early
3. Parse each line as JSON, filter out entries where `timestamp` is older than `retentionDays` ago
4. If nothing was pruned (all entries are within retention), return early (skip write)
5. Write surviving entries to a temp file (`${metricsFile}.tmp`) using `writeFileSync`
6. Rename temp file to the original using `renameSync` (atomic on same filesystem)
7. Log: `"Pruned X metrics older than Y days (Z remaining)"`

Handle edge cases:
- If the file doesn't exist (`ENOENT`), silently return
- If a line fails to parse, keep it (don't silently drop corrupted lines during pruning — only drop lines that are both parseable and expired)
- Clean up temp file in a `finally` block if rename fails

Imports to add: `existsSync`, `writeFileSync`, `renameSync`, `unlinkSync` from `node:fs`.

### 4. `src/index.ts` — Call `pruneMetrics()` on startup

After `initMetrics()` on line 283, add:
```typescript
import { initMetrics, pruneMetrics } from "./metrics.js";
// ...
initMetrics();
pruneMetrics(config.metricsRetentionDays);
```

Update the existing import to include `pruneMetrics`.

## Testing approach

- **Unit test** for `pruneMetrics()`: Create a temp metrics file with entries at various ages, call `pruneMetrics(30)`, verify only entries within 30 days remain
- **Edge cases to test**:
  - Empty file — no error, no write
  - File doesn't exist — no error
  - All entries within retention — file not rewritten
  - All entries expired — file is emptied
  - Corrupted lines — preserved (not silently dropped)
- **Config validation**: Verify `metricsRetentionDays < 1` throws

## Dependencies

No new dependencies needed. Uses only `node:fs` builtins already imported in `src/metrics.ts`.
