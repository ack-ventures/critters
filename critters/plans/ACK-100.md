# ACK-100: Randomly assign pane colors and expand to 10 colors

## Summary

Two changes to `src/claude.ts`:
1. Expand `PANE_COLORS` from 5 entries to 10 visually distinguishable colors.
2. Replace the sequential `colorIndex++` rotation with random selection from the unused color pool, tracking which colors are currently in use by active critter panes.

## Files to modify

### `src/claude.ts`

#### 1. Expand `PANE_COLORS` to 10 entries (lines 8–14)

Replace the current 5-entry array with 10 entries. Keep the existing 5 (cyan, yellow, green, magenta, white) and add 5 new colors (red, blue, teal, pink, orange):

```typescript
const PANE_COLORS = [
  { bg: "colour17",  fg: "colour39",  label: "\x1b[1;36m", toolColor: "\x1b[36m"  },  // cyan
  { bg: "colour52",  fg: "colour209", label: "\x1b[1;33m", toolColor: "\x1b[33m"  },  // yellow
  { bg: "colour22",  fg: "colour119", label: "\x1b[1;32m", toolColor: "\x1b[32m"  },  // green
  { bg: "colour53",  fg: "colour177", label: "\x1b[1;35m", toolColor: "\x1b[35m"  },  // magenta
  { bg: "colour234", fg: "colour255", label: "\x1b[1;37m", toolColor: "\x1b[37m"  },  // white
  { bg: "colour52",  fg: "colour196", label: "\x1b[1;31m", toolColor: "\x1b[31m"  },  // red
  { bg: "colour18",  fg: "colour75",  label: "\x1b[1;34m", toolColor: "\x1b[34m"  },  // blue
  { bg: "colour23",  fg: "colour44",  label: "\x1b[38;5;44m", toolColor: "\x1b[38;5;44m" },  // teal
  { bg: "colour53",  fg: "colour213", label: "\x1b[38;5;213m", toolColor: "\x1b[38;5;213m" },  // pink

```

Color rationale:
- **Red** (`colour196`): bright red fg on dark red bg — distinct from all existing warm tones
- **Blue** (`colour75`): medium blue fg on dark blue bg — fills the obvious gap in the palette
- **Teal** (`colour44`): teal/dark cyan fg on dark teal bg — distinguishable from cyan (brighter, greener)
- **Pink** (`colour213`): hot pink fg on purple bg — distinguishable from magenta (lighter, pinker)
- **Orange** (`colour214`): orange fg on olive/brown bg — distinguishable from yellow (darker, warmer)

Note: red and yellow share `bg: "colour52"` — this is fine since `bg` is a tmux pane style attribute and both have very different `fg` values (colour196 red vs colour209 orange/yellow), making them visually distinct. However, if the reviewer flags this as a concern, a simple fix is to use `colour88` for red's bg instead (a slightly different dark red).

Similarly, pink and magenta share `bg: "colour53"` but have different fg values (colour213 pink vs colour177 magenta).

#### 2. Replace sequential rotation with random selection (lines 15–39)

**Remove:**
```typescript
let colorIndex = 0;
```

**Add:**
```typescript
const activeColors = new Set<number>();
```

**Replace** the color assignment block in `spawnClaude` (lines 38–39):
```typescript
const color = PANE_COLORS[colorIndex % PANE_COLORS.length];
colorIndex++;
```

**With** (select color but don't reserve yet — early returns below could leak it):
```typescript
const available = PANE_COLORS.map((_, i) => i).filter(i => !activeColors.has(i));
const idx = available.length > 0
  ? available[Math.floor(Math.random() * available.length)]
  : Math.floor(Math.random() * PANE_COLORS.length);
const color = PANE_COLORS[idx];
```

Note: `activeColors.add(idx)` is intentionally **not** called here. It is deferred until after the pane is successfully created (see step 3 below). This avoids a color leak if either early return path (lines 85 or 98) fires before the pane is alive.

#### 3. Reserve color after successful pane creation, release after pane completes

**Reserve:** Add `activeColors.add(idx);` immediately after the successful pane creation — after line 99 (the early return if `tmuxResult.code !== 0`), before the layout adjustment at line 102. This ensures the color is only marked as "in use" once the pane is confirmed alive:

```typescript
  // (after the early return at line 98-99)

  activeColors.add(idx);

  // Apply main-horizontal layout so the watcher stays on top
  await runCommand("tmux", ["select-layout", "-t", tmuxSession, "main-horizontal"]).catch(() => {});
```

**Release:** The `spawnClaude` function runs until the pane exits (the polling loop at lines 111–121 blocks until the exit code file is written or the signal is aborted). After the polling loop completes and results are read, add `activeColors.delete(idx)` to release the color.

Insert `activeColors.delete(idx);` after the pane cleanup (lines 133–136) and before `parseClaudeJsonLog`:

```typescript
  // Clean up the pane (it may already be gone after the script exits)
  const cleanupResult = await runCommand("tmux", ["kill-pane", "-t", paneId]);
  if (cleanupResult.code !== 0) {
    logTaskWarn(identifier, `Failed to kill tmux pane during cleanup: ${cleanupResult.stderr}`);
  }

  activeColors.delete(idx);

  const { numTurns, inputTokens, outputTokens, cacheReadTokens, costUsd } = parseClaudeJsonLog(jsonLogFile, identifier);
```

**Edge case — early returns:** The two early return paths (lines 85 and 98) fire *before* `activeColors.add(idx)` is called, so they cannot leak a color. The `add` only runs after the pane is successfully created, and the `delete` runs in the shared cleanup path that both normal exit and abort/timeout flow through.

## No other files need changes

- `PANE_COLORS` and `colorIndex` are only used within `src/claude.ts`.
- `spawnClaudeSubprocess` does not use colors (it runs headless, no tmux pane), so it's unaffected.
- The `Spawner` class in `src/spawner.ts` calls `spawnClaude` but doesn't interact with color assignment.

## Dependencies / setup

None. This is a self-contained change to a single file.

## Testing approach

1. **Type check:** Run `bunx tsc --noEmit` to confirm no TypeScript errors.
2. **Static verification:** Confirm `PANE_COLORS` has exactly 10 entries, each with all 4 required properties (`bg`, `fg`, `label`, `toolColor`).
3. **Color uniqueness:** Verify all 10 `fg` values are distinct (they are the primary visual differentiator).
4. **Random assignment logic:**
   - With <10 active critters, each should get a unique color (drawn from unused pool).
   - With 10+ active critters, colors may repeat (drawn randomly from full set).
   - After a critter finishes, its color returns to the available pool.
5. **No color leak:** Verify `activeColors.add(idx)` only runs after pane creation succeeds, and `activeColors.delete(idx)` runs in the shared cleanup path for both normal exit and abort/timeout. Early return paths (lines 85, 98) exit before `add` is called, so no leak is possible.
6. **Runtime check:** Run 2–3 critters and observe they get different (non-sequential) colors in their tmux panes.
