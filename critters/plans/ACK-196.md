# ACK-196: Add Per-Type Breakdown to Dashboard Charts and Stats

## Summary

Add per-type filtering to the Critters dashboard so users can view stats for specific critter types (e.g., `create`, `review`, or custom types). This involves adding filter buttons to the dashboard UI, filtering metrics data by type, and passing the filter from the health server's query parameter.

## Files to Modify

### 1. `src/dashboard.ts`

#### Signature change

- Add `typeFilter?: string` parameter to `renderDashboard`:
  ```ts
  export function renderDashboard(metricsPath: string, status: HealthStatus, uptime: number, typeFilter?: string): string
  ```

#### Extract unique types from metrics

- After loading `allMetrics`, extract unique `critterType` values:
  ```ts
  const allTypes = [...new Set(allMetrics
    .map(m => m.critterType ?? (m.event.startsWith("review_") ? "review" : "create"))
    .filter(Boolean)
  )].sort();
  ```

#### Filter metrics when typeFilter is set

- After extracting `allMetrics` and before computing stats, apply the filter:
  ```ts
  const filteredMetrics = typeFilter
    ? allMetrics.filter(m => (m.critterType ?? (m.event.startsWith("review_") ? "review" : "create")) === typeFilter)
    : allMetrics;
  ```
- Use `filteredMetrics` instead of `allMetrics` for computing `taskMetrics`, summary stats, daily stats, today stats, and the activity table.
- Do NOT filter `status.activeCritterDetails` or the Active Critters section — always show all active critters.

#### Type filter buttons (HTML)

- Add a row of filter buttons between the header and summary cards:
  ```html
  <div class="type-filters">
    <a href="/dashboard" class="filter-btn active">All</a>
    <a href="/dashboard?type=create" class="filter-btn">create</a>
    <a href="/dashboard?type=review" class="filter-btn">review</a>
  </div>
  ```
- The `active` class is applied to the button matching the current `typeFilter` (or "All" when no filter).
- Only render type buttons if there are at least 2 distinct types (otherwise the filter is pointless).

#### Auto-refresh preserves filter

- Update the `<meta http-equiv="refresh">` tag to include the query param:
  ```ts
  const refreshUrl = typeFilter ? `/dashboard?type=${encodeURIComponent(typeFilter)}` : `/dashboard`;
  // In <head>:
  `<meta http-equiv="refresh" content="30;url=${refreshUrl}">`
  ```

#### Per-type chart colors (optional enhancement)

- Update the `DayStat` type to include per-type counts:
  ```ts
  type DayStat = { date: string; completed: number; failed: number; cost: number; avgDuration: number; perType: Record<string, { completed: number; failed: number }> };
  ```
- In `computeDailyStats`, accumulate per-type counts in `perType`.
- In the "Tasks per Day" chart, when viewing "All" (no filter), render stacked bars with different colors per type:
  - `create`: green (existing `--success`)
  - `review`: blue (`#5dade2`)
  - Other custom types: cycle through purple (`#8B5CF6`), gold (`#e2b93d`), etc.
- When a specific type filter is active, use a single color (green for success, red for failure) as currently done.

### 2. `src/health.ts`

#### Parse query parameter

- In the dashboard route handler (where `url.pathname === "/" || url.pathname === "/dashboard"`), extract the type filter:
  ```ts
  const typeFilter = url.searchParams.get("type") || undefined;
  ```
- Pass it to `renderDashboard`:
  ```ts
  const html = renderDashboard(metricsPath ?? "", status, uptime, typeFilter);
  ```

## Backward Compatibility

- The `critterType` field on `MetricEvent` was added recently. Older metrics may not have it.
- When `critterType` is missing, infer from the event name: events starting with `review_` default to `"review"`, others default to `"create"`.
- This inference is used consistently in both the filter logic and the type extraction.

## Edge Cases

- If `typeFilter` is set to a value that doesn't match any metrics, all stats will show zero/empty — this is acceptable (shows "no data" states).
- If there's only one type in the metrics, the filter buttons are not rendered (no point filtering).
- The `poll_completed` and `task_started`/`review_started` events don't affect summary stats (they're already filtered out by the existing `taskMetrics` filter), but they should still be filtered by type when computing `allMetrics` for `computeDailyStats`.

## Testing Approach

1. **Manual testing**: Start the daemon, generate some metrics with different critter types, and verify:
   - Filter buttons appear when multiple types exist
   - Clicking a filter updates the URL and shows filtered stats
   - Auto-refresh preserves the filter
   - Active critters section is unaffected by filtering
   - Charts show per-type colors when viewing "All"
2. **Edge case testing**:
   - Dashboard with no metrics (empty state)
   - Dashboard with only one type (no filter buttons)
   - Dashboard with `?type=nonexistent` (shows empty/zero stats)
   - Metrics without `critterType` field (backward compat fallback)
3. **CI**: Existing `bun run typecheck` and `bun run lint` should pass since changes are additive.
