# ACK-126: Add Shell Hooks for Post-Task Events

## Summary

Add a shell hooks system that runs user-defined commands on critter lifecycle events. Hooks are configured in `critters.config.yaml`, run via `child_process.exec()` (fire-and-forget), receive context as environment variables, and never block or crash the main process on failure.

## Files to Create

### 1. `src/hooks.ts` — Hook execution module

Two exported functions:

#### `runHook(hookName: string, command: string, env: Record<string, string>, identifier?: string): void`
- Uses `child_process.exec(command, { env: { ...process.env, ...env }, timeout: 30_000 })` to run the command
- Fire-and-forget — does **not** return a promise, does **not** block
- Logs on start: `logTask(identifier, "Running hook ${hookName}: ${command}")` (or `log()` if no identifier)
- On error (stderr output or non-zero exit code): `logTaskWarn(identifier, "Hook ${hookName} failed: ...")` — log a warning, never throw
- On timeout (30s): child_process.exec handles this via `timeout` option — the process is killed and an error event fires, which we log as a warning
- Uses `logTask`/`logTaskWarn` from `src/logger.ts` when identifier is provided, `log`/`logError` otherwise

#### `triggerHook(config: Config, hookName: keyof NonNullable<Config["hooks"]>, env: Record<string, string>, identifier?: string): void`
- Checks if `config.hooks?.[hookName]` exists and is a non-empty string
- If so, calls `runHook(hookName, config.hooks[hookName], env, identifier)`
- If not, no-op (silent, no logging)

### 2. `src/__tests__/hooks.test.ts` — Tests

Using `bun:test` with the project's existing patterns (`createTempDir()` from `./helpers.ts`):

1. **`runHook` runs command with correct env vars** — Execute `echo $CRITTER_ISSUE_ID > <tempfile>`, wait briefly, verify file content
2. **`runHook` logs warning on non-zero exit** — Mock or spy on logger, run a failing command (`exit 1`), verify warning was logged
3. **`runHook` does not throw on failure** — Run `exit 1`, verify no exception propagates
4. **`triggerHook` calls runHook when hook exists** — Pass config with hooks set, verify command executes
5. **`triggerHook` is a no-op when hook is missing** — Pass config without hooks, verify nothing happens
6. **`triggerHook` is a no-op when hook is empty string** — Pass config with `onPrCreated: ""`, verify nothing happens
7. **Timeout test** — Run `sleep 60`, verify process is killed (logged warning) within reasonable time

## Design Decisions

1. **`child_process.exec()` not `Bun.spawn()`** — Hooks may use shell features (pipes, redirects, subshells). `exec()` runs through the shell.
2. **Fire-and-forget** — Hooks should not delay the main lifecycle. We call `exec()` without awaiting. Errors are logged but never thrown.
3. **30-second timeout** — Prevents runaway hooks from leaking resources. `exec()` supports `timeout` natively.
4. **Environment variables** — All context is passed via env vars, not CLI arguments. This is cleaner and avoids shell quoting issues.
5. **Optional `identifier` parameter** — `runHook`/`triggerHook` accept an optional identifier for task-prefixed logging. All call sites in spawner/review-spawner pass the task identifier.
6. **No `CRITTER_PR_URL` on task started/failed** — PR doesn't exist yet at task start, and may not exist on failure. Only set when available.

## Dependencies

None — `child_process.exec` is a Node built-in available in Bun.

## Testing Approach

- Unit tests for `runHook` and `triggerHook` in `src/__tests__/hooks.test.ts`
- Use real shell commands (echo, exit) rather than mocks for `runHook` — this tests the actual exec behavior
- Use `createTempDir()` helper for temp files
- For `triggerHook`, test with both populated and empty/missing config
- Integration with spawner/review-spawner is verified by code review — the hook calls are simple one-liners with no branching logic
