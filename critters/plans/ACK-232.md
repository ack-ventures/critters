# ACK-232: Add disk space check before cloning repos

## Summary

Add a pre-clone disk space check to prevent confusing `git clone` failures when disk space is low. Introduces a new `minDiskSpaceMb` config field (default 1024 MB). The check runs before every clone in `shallowClone()` and at daemon startup as a warning.

### 3. `src/git.ts` — Add disk space check before clone

Add a new exported function `checkDiskSpace()`:

```ts
import { statfsSync } from "node:fs";

export function checkDiskSpace(workDir: string, minDiskSpaceMb: number): void {
  const stats = statfsSync(workDir);
  const availableMb = Math.floor((stats.bsize * stats.bavail) / (1024 * 1024));
  if (availableMb < minDiskSpaceMb) {
    throw new Error(
      `Insufficient disk space: ${availableMb}MB available, ${minDiskSpaceMb}MB required on ${workDir}`
    );
  }
}
```

Key design decisions:
- Uses `statfsSync` (synchronous) since it's a quick filesystem stat call — no benefit to async
- Uses `bavail` (available to unprivileged users) not `bfree` (total free including reserved blocks)
- The function is exported so it can be called from both `shallowClone()` and startup
- The error message exactly matches the format specified in requirements
- Takes `workDir` as the path to stat (the parent directory that must exist before clone)

Modify `shallowClone()` to accept `minDiskSpaceMb` as an optional parameter and call `checkDiskSpace()` before the retry wrapper. Use `path.dirname()` for safe parent-directory derivation:

```ts
import { dirname } from "node:path";

export async function shallowClone(
  repoUrl: string,
  targetDir: string,
  identifier: string,
  cwd?: string,
  depth: number = 1,
  localPath?: string,
  minDiskSpaceMb?: number,
): Promise<void> {
  // Check disk space before attempting clone
  if (minDiskSpaceMb != null) {
    const checkDir = cwd ?? dirname(targetDir);
    checkDiskSpace(checkDir, minDiskSpaceMb);
  }

  await withRetry(
    // ... existing clone logic unchanged
  );
}
```

The disk space check runs **before** the `withRetry` wrapper so it fails immediately rather than retrying a space issue. The `checkDir` uses `cwd` when provided (which is always the case from `unified-spawner.ts`), and falls back to `path.dirname(targetDir)` for safety — this correctly handles relative paths and paths without slashes.

## Hot-reload compatibility

The `minDiskSpaceMb` field is a simple numeric config value read from `this.config` at clone time. Since `unified-spawner.ts` already receives updated config via `updateConfig()` and the spawner reads `this.config.minDiskSpaceMb` on each clone, hot-reload works automatically — no special handling needed.

## Edge Cases

- **workDir doesn't exist yet**: `shallowClone()` is called after `mkdirSync(workDir, { recursive: true })` in `runTask()`, so the directory exists by the time we stat it
- **Very large disks**: `bsize * bavail` could overflow JavaScript's safe integer range on extremely large filesystems. In practice, `bavail` is a 64-bit value and `bsize` is typically 4096, so even a 1 PB filesystem stays well within `Number.MAX_SAFE_INTEGER` (~9 PB)
- **Network filesystems**: `statfsSync` works on NFS/CIFS mounts and reports the remote filesystem's available space, which is the correct behavior
- **Config value of 0**: Blocked by validation (`must be > 0`)
- **Non-numeric config value**: Handled by the `typeof` guard in `loadConfig()` — falls back to default 1024
- **Relative targetDir in shallowClone**: Using `path.dirname()` instead of manual string slicing handles relative paths correctly (e.g., `dirname("subdir")` returns `"."`)
