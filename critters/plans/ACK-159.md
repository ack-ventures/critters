# ACK-159: Show repo, branch, and phase metadata across all critter surfaces

## Summary

Add visibility into what repo, branch, and phase each critter is working on across five surfaces: console logs, tmux pane titles, the web dashboard, the `/healthz` endpoint, and the `critters status` CLI command. This requires:

1. A new utility to extract short repo names from SSH/HTTPS URLs
2. Enhanced console logging at pickup and phase transitions
3. Repo name in tmux pane titles
4. An "Active Critters" detail table in the dashboard
5. Per-critter detail in the `/healthz` response
6. Active critter detail display in `critters status`

### 1. `src/utils.ts` — Add `shortRepoName()` utility

Add a new exported function using a simple string manipulation approach (avoids regex pitfalls with lazy quantifiers and optional groups):

```typescript
export function shortRepoName(repoUrl: string): string {
  // Strip trailing .git if present
  const cleaned = repoUrl.replace(/\.git$/, "");
  // SSH: git@github.com:org/repo → extract after ':'
  const colonIdx = cleaned.indexOf(":");
  if (colonIdx !== -1 && !cleaned.includes("://")) {
    const afterColon = cleaned.slice(colonIdx + 1);
    return afterColon;
  }
  // HTTPS: https://github.com/org/repo → extract last two path segments
  const parts = cleaned.split("/");
  if (parts.length >= 2) {
    return `${parts[parts.length - 2]}/${parts[parts.length - 1]}`;
  }
  return repoUrl; // fallback: return as-is
}
```

This handles:
- SSH: `git@github.com:org/repo.git` → `org/repo`
- HTTPS: `https://github.com/org/repo.git` → `org/repo`
- No `.git` suffix: `git@github.com:org/repo` → `org/repo`
- Edge cases: returns input as-is if parsing fails

## Testing approach

1. **Unit test for `shortRepoName`**: Test SSH URLs, HTTPS URLs, URLs without `.git` suffix, edge cases.

2. **TypeScript compilation**: Run `bun run typecheck` to verify all type changes are compatible across the codebase (including test files).

3. **Lint**: Run `bun run lint` to verify code style compliance.

4. **Existing tests**: Run `bun test` to verify no regressions. The updated `defaultStatus()` helpers in test files ensure existing tests still pass.

5. **Manual verification**: Start the daemon with a test issue and verify:
   - Console logs show repo + branch at pickup and phase transitions
   - Tmux pane titles show short repo name
   - Dashboard shows active critters table with correct columns
   - `/healthz` response includes `activeCritterDetails` array
   - `critters status` shows active critter detail lines

6. **Edge cases to verify**:
   - Zero active critters: dashboard should not show the detail table, `/healthz` returns empty array, `critters status` shows no extra lines
   - Multiple concurrent critters: each should have its own entry with correct phase tracking
   - Review critters: `prBranch` starts empty, gets updated after resolution — both states render correctly
   - Backward compat: `critters status` works against an older daemon that doesn't include `activeCritterDetails` (field is optional)
