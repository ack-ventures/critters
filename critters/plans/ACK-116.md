# ACK-116: Add Structured JSONL Metrics Logging

## Summary

Add a metrics module that records structured events to a JSONL file (`~/.critters/metrics.jsonl`), enabling tracking of critter performance, costs, and success rates over time. The module integrates into the existing task and review lifecycles at key lifecycle points (start, complete, fail) and into the poll loops.

## Files to Create

### `src/metrics.ts`

New module providing three named exports:

```typescript
export function initMetrics(filePath?: string): void
export function recordMetric(event: MetricEvent): void
export function getRecentMetrics(n: number): MetricEvent[]
```

**Type definition:**

```typescript
export type MetricEvent = {
  timestamp: string;        // ISO-8601, always set by recordMetric
  event: "task_started" | "task_completed" | "task_failed" | "review_started" | "review_completed" | "review_failed" | "poll_completed";
  issueId?: string;
  identifier?: string;
  repoUrl?: string;
  duration?: number;        // ms
  phase?: "planning" | "execution" | "review";
  numTurns?: number;
  inputTokens?: number;
  outputTokens?: number;
  cacheReadTokens?: number;
  costUsd?: number;
  prUrl?: string;
  outcome?: string;         // "merged", "needs_changes", "partial_progress", etc.
  error?: string;           // error message on failure
};
```

**Implementation details:**

- **`initMetrics(filePath?)`**: Sets the module-level `metricsFile` variable. Defaults to `join(homedir(), ".critters", "metrics.jsonl")`. Ensures the parent directory exists with `mkdirSync(dir, { recursive: true })`. This mirrors the pattern in `src/logger.ts:7-11`.
- **`recordMetric(event)`**: Sets `event.timestamp = new Date().toISOString()` if not already set. Appends `JSON.stringify(event) + "\n"` to the metrics file using `appendFileSync`. If `metricsFile` is not set (initMetrics not called), silently returns (no-op) — same graceful degradation as logger.ts. Wraps the write in a try-catch so metrics failures never crash the daemon; logs errors via `logError()`.
- **`getRecentMetrics(n)`**: Reads the file with `readFileSync`, splits by newline, takes the last `n` non-empty lines, parses each as JSON. Returns an empty array if the file doesn't exist or on any error.

### `src/__tests__/metrics.test.ts`

Tests covering:

1. **`initMetrics` creates directory** — uses `createTempDir()`, passes a custom path, verifies the parent directory is created.
2. **`recordMetric` writes valid JSONL** — init with temp file, record 3 events, read file back, verify each line is valid JSON with correct fields.
3. **`recordMetric` sets timestamp automatically** — record an event without timestamp, verify it's set to a valid ISO-8601 string.
4. **`recordMetric` is a no-op before init** — call `recordMetric` without `initMetrics`, verify no errors thrown and no file created.
5. **`recordMetric` writes atomically** — record an event, verify the file contains exactly one complete JSON line ending with `\n`.
6. **`getRecentMetrics` returns last N entries** — write 5 events, request last 3, verify correct 3 returned in order.

**Test pattern**: Uses `beforeEach`/`afterEach` with `createTempDir()` for cleanup, following the pattern in `config.test.ts`. Need to reset the module-level `metricsFile` between tests — `initMetrics()` with a fresh temp path in each test.

None — uses only Node.js/Bun built-ins (`fs`, `os`, `path`).

## Testing Approach

**Unit tests** (`src/__tests__/metrics.test.ts`):
- Test `initMetrics`, `recordMetric`, and `getRecentMetrics` in isolation using temp directories
- Verify JSONL format (each line is valid JSON, proper newline termination)
- Verify graceful degradation (no-op before init, no crash on write errors)
- Verify `getRecentMetrics` correctly returns the last N entries

**Integration verification**:
- Run existing tests to ensure no regressions from the spawner/watcher changes
- The new `recordMetric` calls are fire-and-forget (synchronous append), so they can't break the existing async flows
- `recordMetric` wraps writes in try-catch, so even if the metrics file is inaccessible, the daemon continues normally

## Risks & Edge Cases

1. **File permissions**: `~/.critters/` may not be writable. Mitigated by try-catch in `recordMetric` — metrics failure is logged but never crashes the daemon.
2. **File growth**: JSONL files grow unboundedly. This is acceptable for v1; a future enhancement could add log rotation. A typical critter generates ~3 events per task, so even hundreds of tasks produce a small file.
3. **Concurrent writes**: Multiple critters run concurrently, but `appendFileSync` with small payloads (single JSON lines) is atomic on POSIX for writes under the pipe buffer size (typically 4KB). Each metric line will be well under this limit.
4. **Module state reset in tests**: The module uses a file-level `metricsFile` variable. Tests must call `initMetrics(tempPath)` in `beforeEach` to avoid state leaking between tests.
