# ACK-221: Add large file reading guidance to critter prompts

## Summary

When critters encounter files that exceed the token limit, they sometimes fall back to spawning python to read chunks — an unreliable workaround since python may not be in the allowed tools. The Read tool already supports `offset` and `limit` parameters for chunked reading. We need to add brief guidance to all three prompt builders so critters reach for these parameters naturally.

## Files to Modify

### 1. `src/prompt.ts` — `buildPlanningPrompt` (line 99)

Add a short "Reading Large Files" note after the "Tool Restrictions" section (before the custom prompt appendage). Insert after line 155 (the closing of the tool restrictions block), before the custom prompt logic:

```
## Reading Large Files
The Read tool supports \`offset\` and \`limit\` parameters — use these to read large files in chunks rather than attempting to read the entire file at once.
```

### 2. `src/prompt.ts` — `buildExecutionPrompt` (line 176)

Add the same guidance in the execution prompt. Insert it after the "Editing Files" section (after line 206) since it's related to file operations:

```
## Reading Large Files
The Read tool supports \`offset\` and \`limit\` parameters — use these to read large files in chunks rather than attempting to read the entire file at once.
```

### 3. `src/review-prompt.ts` — `buildReviewPrompt` (line 12)

Add the guidance in the review prompt. Insert it after the "Rules" section (after line 72), before custom prompt appendage:

```
## Reading Large Files
The Read tool supports \`offset\` and \`limit\` parameters — use these to read large files in chunks rather than attempting to read the entire file at once.
```

## Approach Details

- The guidance is identical across all three prompts — one sentence explaining the capability, keeping it brief and non-prescriptive.
- Placement is after tool/file operation sections in each prompt so it reads naturally as related guidance.
- No new dependencies or setup needed.
