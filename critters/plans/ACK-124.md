# ACK-124: Add `critters --dry-run` mode

## Summary

Add a `--dry-run` flag that polls Linear once, logs what the daemon *would* do (which critter issues would be picked up, which review issues would be dispatched), prints a summary, and exits. No critters are spawned, no Linear statuses are changed, no comments are posted.

## Files to Modify

### 1. `src/index.ts`

**Changes:**

- Add `--dry-run` to the help text under Flags.
- Parse `--dry-run` from `Bun.argv` (same pattern as `--no-tmux` / `--skip-update`):
  ```ts
  const dryRun = Bun.argv.includes("--dry-run");
  ```
- When `dryRun` is true, skip non-essential initialization that would fail or be wasteful:
  - Still load config, init Linear, load team statuses (needed for polling).
  - Skip: `ensureLabel`, `ensureCritterFailedStatus`, `ensureHumanReviewStatus` (these mutate Linear).
  - Skip: creating `Spawner`/`ReviewSpawner`, cleanup, health server, tmux pane setup, periodic cleanup.
  - Skip: signal handlers and the long-running `Promise.all([watcher.start(), reviewWatcher.start()])`.
- Instead, construct `Watcher` and `ReviewWatcher` with `dryRun: true`, call a new one-shot method on each (e.g., `watcher.dryRunPoll()` and `reviewWatcher.dryRunPoll()`), print the summary, and `process.exit(0)`.
- When `dryRun` is true, also imply `--no-tmux` behavior (no tmux re-launch) since this is a one-shot CLI tool.

**Sketch of the dry-run path in `main()`:**

```ts
if (dryRun) {
  // Skip tmux auto-launch, skip ensureLabel/ensureStatus, skip spawner creation
  log(`Critters v${VERSION} — dry run`);
  // Still: loadConfig, initLinear, loadTeamStatuses (read-only)
  const config = loadConfig(configPath);
  config.noTmux = true;
  initLinear(config);
  const teamStatuses = await loadTeamStatuses();

  const watcher = new Watcher(config, null as any, undefined, true);
  const reviewWatcher = new ReviewWatcher(config, null as any, undefined, true);

  const critterSummary = await watcher.dryRunPoll();
  const reviewSummary = await reviewWatcher.dryRunPoll();

  log("");
  log(`Dry run complete: ${critterSummary.total} critter issues found, ${critterSummary.wouldPickUp} would be picked up, ${critterSummary.blocked} blocked, ${critterSummary.skipped} skipped (no repo)`);
  log(`Review: ${reviewSummary.total} review issues found, ${reviewSummary.wouldPickUp} would be picked up, ${reviewSummary.skipped} skipped`);
  process.exit(0);
}
```

### 2. `src/watcher.ts`

**Changes:**

- Add optional `dryRun` parameter to the constructor (4th parameter, defaults to `false`). Store as `private dryRun: boolean`.
- Add a new public method `dryRunPoll()` that:
  1. Calls `findCritterIssues(this.config.triggerLabel)` (existing Linear query).
  2. Iterates over the issues, performing the same filtering logic as `poll()` (dedup check is not needed since this is one-shot, but we keep blocker checking and repo resolution).
  3. For each issue, logs dry-run output showing:
     - Issue identifier and title
     - Resolved repo URL and its source (description, project config, or team config)
     - Blocker status
  4. Returns a summary object: `{ total: number, wouldPickUp: number, blocked: number, skipped: number }`.

- Add a new helper `resolveRepoUrlWithSource(task, config)` that returns both the URL and the source string. This is a thin wrapper around the existing `resolveRepoUrl` logic in `prompt.ts`. Rather than modifying `prompt.ts`, we'll add a local function in `watcher.ts` that duplicates the resolution logic with source tracking (the logic is only 3 conditions and doesn't warrant modifying the shared function's return type).

  Actually, a cleaner approach: add a new exported function `resolveRepoUrlWithSource` in `src/prompt.ts` that returns `{ url: string; source: string } | null`. This avoids duplication and keeps repo resolution centralized. The existing `resolveRepoUrl` can delegate to it for backward compatibility.

**`resolveRepoUrlWithSource` in `src/prompt.ts`:**

```ts
export function resolveRepoUrlWithSource(
  task: CritterTask,
  config: Config,
): { url: string; source: string } | null {
  const fromDescription = parseRepoUrl(task.description);
  if (fromDescription) return { url: fromDescription, source: "from description" };

  if (task.projectId && config.repos[task.projectId]) {
    return { url: config.repos[task.projectId].url, source: "from project config" };
  }

  if (config.teamRepos[task.teamId]) {
    return { url: config.teamRepos[task.teamId], source: "from team config" };
  }

  return null;
}
```

Then update `resolveRepoUrl` to delegate:

```ts
export function resolveRepoUrl(task: CritterTask, config: Config): string | null {
  const result = resolveRepoUrlWithSource(task, config);
  return result ? result.url : null;
}
```

**`dryRunPoll()` method in `Watcher`:**

```ts
async dryRunPoll(): Promise<{ total: number; wouldPickUp: number; blocked: number; skipped: number }> {
  const issues = await findCritterIssues(this.config.triggerLabel);
  let wouldPickUp = 0;
  let blocked = 0;
  let skipped = 0;

  for (const task of issues) {
    const resolved = resolveRepoUrlWithSource(task, this.config);
    const blockerList = task.blockedBy?.map(b => `${b.identifier} (${b.status})`).join(", ");

    if (!resolved) {
      log(`[DRY RUN] Skipping ${task.identifier} "${task.title}" — no repo URL found`);
      skipped++;
      continue;
    }

    if (task.blockedBy && task.blockedBy.length > 0) {
      log(`[DRY RUN] Would pick up ${task.identifier} "${task.title}"`);
      log(`  repo: ${resolved.url} (${resolved.source})`);
      log(`  blocked by: ${blockerList}`);
      blocked++;
      continue;
    }

    log(`[DRY RUN] Would pick up ${task.identifier} "${task.title}"`);
    log(`  repo: ${resolved.url} (${resolved.source})`);
    log(`  blocked by: (none)`);
    wouldPickUp++;
  }

  return { total: issues.length, wouldPickUp, blocked, skipped };
}
```

### 3. `src/review-watcher.ts`

**Changes:**

- Add optional `dryRun` parameter to the constructor (4th parameter, defaults to `false`). Store as `private dryRun: boolean`.
- Add a new public method `dryRunPoll()` that:
  1. Calls `findReviewIssues(this.config.reviewTriggerLabel)`.
  2. For each issue, resolves repo URL and extracts PR info from comments.
  3. Logs dry-run output:
     - Issue identifier and title
     - PR URL (if found) or "(no PR URL found)"
     - Repo URL and source
  4. Returns `{ total: number, wouldPickUp: number, skipped: number }`.

**`dryRunPoll()` method:**

```ts
async dryRunPoll(): Promise<{ total: number; wouldPickUp: number; skipped: number }> {
  const issues = await findReviewIssues(this.config.reviewTriggerLabel);
  let wouldPickUp = 0;
  let skipped = 0;

  for (const issue of issues) {
    const resolved = resolveRepoUrlWithSource(issue, this.config);
    if (!resolved) {
      log(`[DRY RUN] Skipping review ${issue.identifier} "${issue.title}" — no repo URL found`);
      skipped++;
      continue;
    }

    let comments: string[];
    try {
      comments = await getIssueComments(issue.issueId);
    } catch (err) {
      log(`[DRY RUN] Skipping review ${issue.identifier} "${issue.title}" — failed to fetch comments`);
      skipped++;
      continue;
    }

    const prInfo = extractPrFromComments(comments);
    if (!prInfo) {
      log(`[DRY RUN] Skipping review ${issue.identifier} "${issue.title}" — no PR URL in comments`);
      skipped++;
      continue;
    }

    log(`[DRY RUN] Would pick up review ${issue.identifier} "${issue.title}"`);
    log(`  repo: ${resolved.url} (${resolved.source})`);
    log(`  PR: ${prInfo.prUrl}`);
    wouldPickUp++;
  }

  return { total: issues.length, wouldPickUp, skipped };
}
```

## Behavioral Details

1. **One-shot execution**: `--dry-run` polls once and exits. No interval loop, no signal handlers, no long-running processes.
2. **Read-only**: No Linear mutations (no status updates, no comments, no label creation). The only Linear calls are read-only queries (`findCritterIssues`, `findReviewIssues`, `getIssueComments`, `loadTeamStatuses`).
3. **No tmux**: Dry run implies `--no-tmux` since there's no long-running daemon to manage.
4. **Spawner not needed**: The `Watcher` and `ReviewWatcher` constructors accept `spawner` as a parameter but `dryRunPoll()` doesn't use it. We pass `null` and use the `dryRun` flag to ensure `spawner` is never accessed. Alternatively, make `spawner` optional in the constructor when `dryRun` is true — but since TypeScript allows `null as any` and `dryRunPoll` never touches `spawner`, the simplest approach is to make the `spawner` parameter's type include `null` when `dryRun` is true. The cleanest approach: make `spawner` type `Spawner | null` and guard access in `stop()`.
5. **Skip prerequisites check**: `checkPrerequisites()` validates tools like `claude`, `gh`, `tmux` etc. In dry-run mode, we don't need `claude`, `tmux`, or `gh` — only the Linear API key. We should skip `checkPrerequisites()` in dry-run mode.
6. **Skip auto-update check**: Not needed for a quick validation run.

## Testing Approach

1. **Manual test**: Run `bun run src/index.ts --dry-run` against a real Linear workspace. Verify:
   - Issues are listed with correct repo URLs and sources
   - Blockers are shown correctly
   - Summary counts match
   - Process exits after one poll cycle
   - No Linear statuses/comments are modified (check Linear UI)

2. **Unit tests** (if test infrastructure exists): Test `resolveRepoUrlWithSource` returns correct source strings for each resolution path. Test `dryRunPoll` methods with mocked Linear data.

3. **Edge cases to verify**:
   - No matching issues → summary shows "0 critter issues found, 0 would be picked up, 0 blocked"
   - Issue with no repo URL → logged as skipped
   - Issue with blockers → logged as blocked (not counted in "would be picked up")
   - Review issue with no PR comment → logged as skipped
   - `--dry-run` combined with `--config PATH` → custom config is loaded correctly
   - `LINEAR_API_KEY` missing → error message as usual (config loading still validates this)
