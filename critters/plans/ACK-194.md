# ACK-194: Add cost threshold alerts via Slack

## Summary

Add a configurable `costAlertThreshold` (USD) that triggers a Slack warning when a single critter's accumulated cost exceeds the threshold mid-run. The alert is informational only — it does not stop the critter. Alerts are sent once per critter to avoid spam.

## Files to modify

### 1. `src/types.ts` — Add `costAlertThreshold` to Config

Add an optional field to the `Config` interface:

```typescript
costAlertThreshold?: number; // USD, e.g. 5.00
```

Add after line 49 (after `slackChannel`), keeping it grouped with other optional config fields.

### 2. `src/config.ts` — Load `costAlertThreshold` from YAML

In `loadConfig()`, parse the new field from the YAML config object and add it to the `config` object:

```typescript
costAlertThreshold: (yaml.costAlertThreshold as number) ?? undefined,
```

Add after the `slackChannel` assignment (around line 145). No validation needed beyond what TypeScript provides — `undefined` means disabled, any positive number is a valid threshold.

Add validation in `validateConfig()` to reject non-positive values if the field is set:

```typescript
if (config.costAlertThreshold != null && config.costAlertThreshold <= 0) {
  throw new Error(`Invalid config: costAlertThreshold must be > 0, got ${config.costAlertThreshold}`);
}
```

### 3. `src/slack.ts` — Add `formatCostAlert` function

Add a new formatting function following the existing pattern:

```typescript
export function formatCostAlert(
  identifier: string,
  title: string,
  costUsd: number,
  threshold: number,
  currentPhase: string,
): string {
  return `*${identifier}* — ${title}\n⚠️ Cost alert: spent *$${costUsd.toFixed(2)}* (threshold: $${threshold.toFixed(2)}) — currently in phase: ${currentPhase}`;
}
```

This follows the exact message format from the task spec and uses the ⚠️ emoji as specified. Place it after the existing `formatTimeoutWarning` function.

### 4. `src/unified-spawner.ts` — Check cost after each phase

In the `runTask` method, after each phase completes in the phase loop (after `phaseResults.push(phaseResult.spawn)` on line 375):

1. Declare a `costAlertSent` boolean flag before the phase loop (around line 340, near `phaseDataList`):
   ```typescript
   let costAlertSent = false;
   ```

2. After pushing the phase result (line 375), add cost threshold checking:
   ```typescript
   // Cost threshold check
   if (!costAlertSent && this.config.costAlertThreshold != null) {
     const accumulatedCost = phaseResults.reduce((sum, r) => sum + (r.costUsd ?? 0), 0);
     if (accumulatedCost > this.config.costAlertThreshold) {
       costAlertSent = true;
       logTask(task.identifier, `Cost alert: ${task.identifier} has spent $${accumulatedCost.toFixed(2)} (threshold: $${this.config.costAlertThreshold.toFixed(2)})`);
       await this.slackNotifier.notify(
         task.id,
         formatCostAlert(task.identifier, task.title, accumulatedCost, this.config.costAlertThreshold, phase.name),
       );
     }
   }
   ```

3. Add `formatCostAlert` to the imports from `./slack.js` (line 27).

Key behaviors:
- `costAlertSent` flag ensures only one alert per critter run
- Uses `>` (strict greater than) for the threshold comparison
- Skips the check entirely if `costAlertThreshold` is not configured
- If `costUsd` is `undefined`/`null` for a phase, the `?? 0` fallback means that phase simply contributes 0 to the sum — no special handling needed
- The alert threads under the existing Slack thread for the issue (handled automatically by `SlackNotifier.notify()` which uses the `threadMap`)
- The log message matches the format specified in the task: "Cost alert: ACK-123 has spent $X.XX (threshold: $Y.YY)"

## Config example

```yaml
costAlertThreshold: 5.00  # Alert if a single critter spends more than $5
```

## Testing approach

1. **Unit test for `formatCostAlert`**: Verify the output string matches expected format with known inputs
2. **Unit test for config validation**: Verify that `costAlertThreshold: -1` throws, `costAlertThreshold: 5` passes, and omitting it results in `undefined`
3. **Integration check**: The cost check logic is straightforward (accumulate + compare + flag) and sits inline in the existing phase loop. It can be verified by reading the code path — no mock-heavy integration test is warranted for this change.

## Dependencies

None. All required infrastructure (SlackNotifier, PhaseResult with costUsd, config loading) already exists.

## Risk assessment

- **Low risk**: The feature is purely additive and informational. No existing behavior changes.
- **No breaking changes**: `costAlertThreshold` is optional and defaults to disabled.
- **Slack threading**: The alert automatically threads under the existing issue thread via `SlackNotifier.notify()` — no special threading logic needed.
