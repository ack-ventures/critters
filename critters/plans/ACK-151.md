# ACK-151: Add elapsed time to critter pane titles

## Summary

Add periodic title updates to individual critter tmux panes showing elapsed time, matching the pattern used for the main watcher pane in `src/index.ts` (lines 262–272). Currently pane titles are static (e.g. `ACK-123: Fix bug / plan`). After this change they'll update every 10 seconds to include elapsed time (e.g. `ACK-123: Fix bug / plan | 2m 15s`).

## Files to modify

### `src/claude.ts`

Add `formatDuration` to the existing import from `./utils.js` on line 5:

```ts

// After
```

**Change 2: Add elapsed time interval in `spawnClaude()`**

After the pane title is set (line 128: `await runCommand("tmux", ["select-pane", "-t", paneId, "-T", windowName]);`), and before the polling loop (line 132: `let timedOut = false;`), add an interval that periodically updates the pane title with elapsed time:

```ts
// Start periodic pane title update with elapsed time
const startTime = Date.now();
const titleInterval = setInterval(() => {
  const elapsed = formatDuration(Date.now() - startTime);
  const updatedTitle = `${buildPaneLabel(identifier, title, phase)} | ${elapsed}`;
  runCommand("tmux", ["select-pane", "-t", paneId, "-T", updatedTitle]).catch(() => {});
}, 10_000);
titleInterval.unref();
```

**Change 3: Clear the interval before returning**

The interval must be cleared when the claude process exits, regardless of how it exits (normal completion or abort). Insert `clearInterval(titleInterval)` immediately after the polling loop exits (after line 143, the closing `}` of the `while` loop), before the exit code reading:

```ts
  // ... end of while loop
  }

  clearInterval(titleInterval);

  // Read results
  let exitCode = 1;
  // ...
```

This placement ensures the interval is cleared in all paths — both normal completion (exit code file appears) and abort (signal fires). There is no need for a `try/finally` block because the polling loop cannot throw (it only awaits `sleep()` and checks `existsSync()`), and `clearInterval` is safe to call on an already-cleared interval.

## Design decisions

1. **No `try/finally`**: The task description mentions using a finally block, but examining the code structure shows the polling loop (`while (!existsSync(exitCodeFile))`) cannot throw — it only does `sleep()` and `existsSync()`. Placing `clearInterval()` after the loop is simpler and handles both the normal and abort paths equally well. The interval is also `.unref()`'d so even if cleanup were somehow missed, it wouldn't prevent process exit.

2. **Reuse `buildPaneLabel()`**: The updated title reuses the same `buildPaneLabel()` helper to build the base label, then appends ` | ${elapsed}`. This keeps the format consistent.

3. **`.unref()` on the interval**: Matches the pattern from `src/index.ts:271` and ensures the interval doesn't prevent Node/Bun from exiting cleanly.

4. **10-second interval**: Matches the main watcher pane update interval from `src/index.ts:270`.

## Testing approach

1. **Manual test**: Run the daemon, trigger a critter, and observe the tmux pane title updating every 10 seconds with increasing elapsed time.
2. **Verify cleanup**: Confirm that after a critter completes (or is aborted), the interval stops and the pane is cleaned up normally.
3. **Type check**: Run `bunx tsc --noEmit` to verify no type errors.
