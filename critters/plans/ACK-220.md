# ACK-220: Add restart command and /restart health endpoint

## Summary

Add a `critters restart` CLI command and a `POST /restart` endpoint on the health server so the daemon can be restarted remotely without needing direct tmux access. Also enhance `critters update` to auto-restart after applying an update.

## Files to Create

### 1. `src/cli-restart.ts` — CLI command

New file following the pattern of `src/cli-kickoff.ts`.

```typescript
import { existsSync, readFileSync } from "node:fs";
import { homedir } from "node:os";
import { parse as parseYaml } from "yaml";

function getRestartConfig(): { healthPort: number; dashboardToken?: string } {
  // Same config-reading pattern as cli-kickoff.ts
  const candidates = [
    "./critters.config.yaml",
    `${homedir()}/.critters/config.yaml`,
  ];

  for (const candidate of candidates) {
    if (existsSync(candidate)) {
      try {
        const raw = readFileSync(candidate, "utf-8");
        const yaml = parseYaml(raw) as Record<string, unknown>;
        return {
          healthPort: (yaml.healthPort as number) ?? 3847,
          dashboardToken: (yaml.dashboardToken as string) ?? process.env.DASHBOARD_TOKEN ?? undefined,
        };
      } catch {
        // Fall through to defaults
      }
    }
  }

  return { healthPort: 3847 };
}

export async function runRestart(): Promise<void> {
  const config = getRestartConfig();
  const baseUrl = `http://localhost:${config.healthPort}`;

  const headers: Record<string, string> = {};
  if (config.dashboardToken) {
    headers["Authorization"] = `Bearer ${config.dashboardToken}`;
  }

  try {
    const resp = await fetch(`${baseUrl}/restart`, { method: "POST", headers });
    if (!resp.ok) {
      const text = await resp.text();
      console.error(`Restart failed: ${resp.status} ${text}`);
      process.exit(1);
    }
    console.log("Restarting critters daemon...");
  } catch {
    console.error("Critters daemon is not running (or health endpoint is disabled)");
    process.exit(1);
  }
}
```

Key decisions:
- Follows `cli-kickoff.ts` pattern exactly: read config, build headers with auth, POST to endpoint
- Prints user-friendly messages for success and failure (unreachable daemon)

  if (req.method !== "POST") {
    return new Response("Method Not Allowed", { status: 405 });
  }
  const authResp = checkAuth(req, dashboardToken);
  if (authResp) return authResp;
  if (!triggers?.triggerRestart) {
    return Response.json({ error: "Restart not available" }, { status: 503 });
  }

  // Use setTimeout to let the HTTP response flush before process replacement

```typescript
function restartDaemon(): void {
  log("Restarting daemon...");

  try {
    // Clean up resources
    tunnelHandle?.stop();
    configWatcher.stop();
    if (titleInterval) clearInterval(titleInterval);
    healthServer?.stop();
    watcher.stop();

    // Re-exec: filter out Bun virtual paths (/$bunfs/) from argv
    const args = process.argv.slice(1).filter((a) => !a.startsWith("/$bunfs/"));
    const argv = [process.execPath, ...args];

    // Use Bun.spawn with stdio: "inherit" to replace the process.
    // The new process inherits the tmux pane terminal.
    const child = Bun.spawn(argv, {
      stdio: ["inherit", "inherit", "inherit"],
      env: process.env,
    });
    child.unref();
    process.exit(0);
  } catch (err) {
    logError(`Restart failed: ${err instanceof Error ? err.message : String(err)}`);
    // Fatal — resources are already torn down, cannot recover
    process.exit(1);
  }
}
```

Pass it to `startHealthServer` via the triggers parameter:

### 4. `src/updater.ts` — Auto-restart after update

At the end of `checkForUpdate()`, immediately after the `renameSync` and `print("Update applied ...")` line (line ~293), and still inside the try block (so it only runs on successful update), add auto-restart logic:

```typescript
// After successful update, try to restart the daemon if it's running
// Only in CLI mode (force=true means `critters update` command)
if (force) {
  try {
    const { existsSync: exists, readFileSync: readFile } = await import("node:fs");
    const { homedir: home } = await import("node:os");
    const { parse: parseYaml } = await import("yaml");

    let healthPort = 3847;
    let dashboardToken: string | undefined;
    const candidates = ["./critters.config.yaml", `${home()}/.critters/config.yaml`];
    for (const candidate of candidates) {
      if (exists(candidate)) {
        try {
          const raw = readFile(candidate, "utf-8");
          const yaml = parseYaml(raw) as Record<string, unknown>;
          healthPort = (yaml.healthPort as number) ?? 3847;
          dashboardToken = (yaml.dashboardToken as string) ?? process.env.DASHBOARD_TOKEN;
          break;
        } catch {}
      }
    }

    const headers: Record<string, string> = {};
    if (dashboardToken) {
      headers["Authorization"] = `Bearer ${dashboardToken}`;
    }

    const resp = await fetch(`http://localhost:${healthPort}/restart`, {
      method: "POST",
      headers,
      signal: AbortSignal.timeout(5_000),
    });
    if (resp.ok) {
      print("Daemon restart triggered.");
    }
  } catch {
    print("Restart the daemon manually to use the new version.");
  }
}
```

This is placed after the `renameSync` succeeds, so it only triggers on actual successful update application — not when already up to date, checksum failure, or download failure.

## Restart Strategy

The restart uses `Bun.spawn` + `process.exit(0)`:
- Bun doesn't expose a direct `execv` syscall
- `Bun.spawn` with `stdio: "inherit"` ensures the new process inherits the same tmux pane terminal
- `child.unref()` + `process.exit(0)` ensures the old process exits cleanly while the new process continues
- The 250ms `setTimeout` in the health endpoint gives Bun time to flush the HTTP response before the process exits
- Resources (health server, watcher, tunnel, config watcher, timers) are cleaned up before spawning the new process
- Port binding: `healthServer?.stop()` is called before spawn, releasing the port. The new process has a startup sequence (config loading, tracker init, etc.) that takes well over the time needed for the OS to release the socket. If binding still fails, the new process will log the error naturally (Bun throws on port conflict)
- Error handling: if `Bun.spawn` throws, we log the error and exit with code 1. Since resources are already torn down, there's no way to recover — a clean exit with error is the safest option

## Previous Review Items

> [MUST_FIX] The `Bun.spawn` + `child.unref()` + `process.exit(0)` approach has a race condition: the old health server may not have fully released the port before the new process tries to bind.

Addressed: The new process has a non-trivial startup sequence (loading config, initializing trackers, ensuring labels/statuses) that takes several hundred milliseconds to seconds before it calls `startHealthServer`. By the time it attempts to bind the port, the old process has long exited and the OS has released the socket. Additionally, `healthServer?.stop()` is called synchronously before spawn. This is the same pattern used by other daemon restart mechanisms.
