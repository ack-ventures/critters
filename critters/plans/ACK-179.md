# ACK-179: Add PR Link to Active Critters Dashboard Table

## Summary

Add a `prUrl` field to the active critters tracking so that when a PR is created during the execution phase, it appears as a clickable link in the dashboard's active critters table and in the `/healthz` JSON response.

## Files to Modify

### 1. `src/types.ts` — Add `prUrl` to `ActiveCritterDetail`

Add an optional `prUrl` field to the `ActiveCritterDetail` interface:

```typescript
export interface ActiveCritterDetail {
  identifier: string;
  title: string;
  phase: string;
  repo: string;
  branch: string;
  startedAt: number;
  prUrl?: string;  // <-- add this
}
```

### 2. `src/unified-spawner.ts` — Populate `prUrl` when known

Two places need changes:

**a. Initial population from `task.prUrl` (line 156–163)**

When a task already has a `prUrl` (e.g., review types where `extractPrUrl` enrichment populates it), include it in the initial `ActiveCritterDetail`:

```typescript
this.activeCritterMap.set(item.task.id, {
  identifier: item.task.identifier,
  title: item.task.title,
  phase: item.critterType.phases[0]?.name ?? typeName,
  repo: shortRepoName(item.task.repoUrl),
  branch: item.task.prBranch ?? branchName(item.task.identifier, item.task.title),
  startedAt: Date.now(),
  prUrl: item.task.prUrl,  // <-- add this
});
```

**b. After execution phase creates a PR (line 374–378)**

When the execution phase completes and returns a `prUrl`, update the active critter detail before calling `handleCreateSuccess`:

```typescript
if (phase.prompt === "builtin:execution") {
  const prUrl = phaseResult.data.prUrl as string | null;
  if (prUrl) {
    const detail = this.activeCritterMap.get(task.id);
    if (detail) detail.prUrl = prUrl;  // <-- add this
    return this.handleCreateSuccess(task, critterType, prUrl, branch, phaseResults, taskStart, tracker);
  }
  // ...
}
```

### 3. `src/health.ts` — Include `prUrl` in `/healthz` JSON response

In the `/healthz` endpoint (line 59–66), add `prUrl` to the mapped details:

```typescript
activeCritterDetails: status.activeCritterDetails.map((d) => ({
  identifier: d.identifier,
  title: d.title,
  phase: d.phase,
  repo: d.repo,
  branch: d.branch,
  elapsed: formatDuration(now - d.startedAt),
  prUrl: d.prUrl ?? null,  // <-- add this
})),
```

### 4. `src/dashboard.ts` — Render PR link in active critters table

**a. Add "PR" column header (line 329–334)**

Add a `<th>PR</th>` column after `Branch`:

```html
<th>Identifier</th>
<th>Phase</th>
<th>Repo</th>
<th>Branch</th>
<th>PR</th>        <!-- add this -->
<th>Elapsed</th>
```

**b. Add PR cell to each row (line 337–347)**

In the `.map()` for `activeCritterDetails`, add a `<td>` with a clickable link when `prUrl` is present, or an em-dash otherwise:

```typescript
const prCell = d.prUrl
  ? `<a href="${escapeHtml(d.prUrl)}" target="_blank" rel="noopener">PR</a>`
  : "\u2014";
```

Then add `<td>${prCell}</td>` after the branch cell.

## Dependencies / Setup

None — all changes are in existing files with no new dependencies.

## Testing Approach

1. **Type checking**: Run `bun run typecheck` to verify the `ActiveCritterDetail` interface change propagates correctly.
2. **Lint**: Run `bun run lint` to ensure no style issues.
3. **Unit tests**: Run `bun test` to verify no regressions.
4. **Manual verification**: Start the daemon with an active critter that creates a PR and verify:
   - The dashboard table shows a "PR" column with a clickable link once execution completes.
   - The `/healthz` endpoint includes `prUrl` in `activeCritterDetails`.
   - Review-type critters show the PR link immediately (from `task.prUrl`).
   - Critters without a PR show an em-dash in the PR column.
