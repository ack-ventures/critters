# ACK-134: Validate download URL domain in updater

## Summary

The updater (`src/updater.ts`) fetches `asset.browser_download_url` from the GitHub API without validating the domain. A compromised or tampered API response could redirect the download to an arbitrary URL. This plan adds domain and protocol validation before downloading, plus defense-in-depth validation on the releases API URL itself.

## Files to modify

### 1. `src/updater.ts`

#### Add `isAllowedDownloadUrl` helper (exported, for testability)

Insert a new exported function after the `compareSemver` function (after line 15):

```typescript
export function isAllowedDownloadUrl(url: string): boolean {
  try {
    const parsed = new URL(url);
    if (parsed.protocol !== "https:") return false;
    const host = parsed.hostname;
    return (
      host === "github.com" ||
      host === "objects.githubusercontent.com" ||
      host.endsWith(".githubusercontent.com")
    );
  } catch {
    return false;
  }
}
```

Key design decisions:
- Uses `new URL()` for robust parsing — invalid URLs return `false` via the catch block
- Checks `protocol` is exactly `"https:"`
- Allows `github.com`, `objects.githubusercontent.com`, and any subdomain of `githubusercontent.com`
- The `.endsWith(".githubusercontent.com")` check handles future subdomains without being overly permissive

#### Add `isAllowedApiUrl` helper (exported, for testability)

Insert alongside `isAllowedDownloadUrl`:

```typescript
export function isAllowedApiUrl(url: string): boolean {
  try {
    const parsed = new URL(url);
    return parsed.protocol === "https:" && parsed.hostname === "api.github.com";
  } catch {
    return false;
  }
}
```

#### Validate `RELEASES_URL` at the start of `checkForUpdate`

After the `execName` and `currentVersion` guard clauses (around line 93), add:

```typescript
if (!isAllowedApiUrl(RELEASES_URL)) {
  printError(`Update aborted: releases URL points to unexpected domain`);
  return;
}
```

This is defense-in-depth — the URL is currently hardcoded to `api.github.com`, but this protects against future changes making it configurable.

#### Validate `asset.browser_download_url` before fetching

After the existing `asset` null-check (line 132-135), before the `fetch` on line 137, add:

```typescript
if (!isAllowedDownloadUrl(asset.browser_download_url)) {
  printError(
    `Update aborted: download URL points to unexpected domain: ${new URL(asset.browser_download_url).hostname}`,
  );
  return;
}
```

Note: Since `asset.browser_download_url` is already confirmed to be a string at this point (line 132 guard), and we know `isAllowedDownloadUrl` returned `false`, we should handle the case where `new URL()` might throw for the error message. Safer approach:

```typescript
if (!isAllowedDownloadUrl(asset.browser_download_url)) {
  let hostname = "unknown";
  try { hostname = new URL(asset.browser_download_url).hostname; } catch {}
  printError(`Update aborted: download URL points to unexpected domain: ${hostname}`);
  return;
}
```

### 2. `src/__tests__/updater.test.ts` (new file)

Create a dedicated test file for the updater URL validation helpers. Following the project convention (tests use `bun:test`, named exports, descriptive test names):

```typescript
import { describe, expect, test } from "bun:test";
import { isAllowedDownloadUrl, isAllowedApiUrl } from "../updater.js";

describe("src/updater.ts", () => {
  describe("isAllowedDownloadUrl", () => {
    // Allowed domains
    test("allows github.com", () => {
      expect(isAllowedDownloadUrl("https://github.com/org/repo/releases/download/v1.0/binary")).toBe(true);
    });

    test("allows objects.githubusercontent.com", () => {
      expect(isAllowedDownloadUrl("https://objects.githubusercontent.com/some/path")).toBe(true);
    });

    test("allows subdomains of githubusercontent.com", () => {
      expect(isAllowedDownloadUrl("https://foo.githubusercontent.com/path")).toBe(true);
    });

    // Rejected domains
    test("rejects evil.com", () => {
      expect(isAllowedDownloadUrl("https://evil.com/binary")).toBe(false);
    });

    test("rejects attacker-githubusercontent.com (suffix match bypass attempt)", () => {
      expect(isAllowedDownloadUrl("https://attacker-githubusercontent.com/binary")).toBe(false);
    });

    test("rejects githubusercontent.com.evil.com", () => {
      expect(isAllowedDownloadUrl("https://githubusercontent.com.evil.com/binary")).toBe(false);
    });

    // Protocol checks
    test("rejects http (non-https)", () => {
      expect(isAllowedDownloadUrl("http://github.com/org/repo/releases/download/v1.0/binary")).toBe(false);
    });

    test("rejects ftp protocol", () => {
      expect(isAllowedDownloadUrl("ftp://github.com/file")).toBe(false);
    });

    // Edge cases
    test("rejects empty string", () => {
      expect(isAllowedDownloadUrl("")).toBe(false);
    });

    test("rejects invalid URL", () => {
      expect(isAllowedDownloadUrl("not-a-url")).toBe(false);
    });

    test("rejects bare githubusercontent.com (not a subdomain)", () => {
      expect(isAllowedDownloadUrl("https://githubusercontent.com/path")).toBe(false);
    });
  });

  describe("isAllowedApiUrl", () => {
    test("allows api.github.com", () => {
      expect(isAllowedApiUrl("https://api.github.com/repos/org/repo/releases/latest")).toBe(true);
    });

    test("rejects non-https", () => {
      expect(isAllowedApiUrl("http://api.github.com/repos/org/repo")).toBe(false);
    });

    test("rejects other domains", () => {
      expect(isAllowedApiUrl("https://evil.com/api")).toBe(false);
    });

    test("rejects api.github.com.evil.com", () => {
      expect(isAllowedApiUrl("https://api.github.com.evil.com/repos")).toBe(false);
    });

    test("rejects empty string", () => {
      expect(isAllowedApiUrl("")).toBe(false);
    });
  });
});
```

### 3. `src/__tests__/utils.test.ts` (modify)

Move the existing `compareSemver` tests from `utils.test.ts` (lines 471-505) into the new `src/__tests__/updater.test.ts` file and remove them from `utils.test.ts`, since they belong with the updater module. Remove the `compareSemver` import from `utils.test.ts`.

**Alternative**: Keep `compareSemver` tests in `utils.test.ts` to minimize churn and add URL validation tests only in the new file. This is the simpler approach and preferred — no need to move existing passing tests.

**Decision**: Keep `compareSemver` tests where they are. Only create the new test file for URL validation.

## Testing approach

- Unit tests for `isAllowedDownloadUrl`: test all allowed domains, rejected domains, non-https protocols, invalid URLs, and edge cases (suffix-match bypass attempts like `attacker-githubusercontent.com`)
- Unit tests for `isAllowedApiUrl`: test `api.github.com` allowed, other domains rejected, non-https rejected
- Existing `compareSemver` tests remain untouched
- Run `bun test` to verify all tests pass

## Dependencies

None — uses only the built-in `URL` constructor (available in all modern runtimes including Bun).
