# ACK-256: Daemonize process when using --no-tmux flag

## Summary

When `--no-tmux` is used (and not `--dry-run`), the daemon should fork into the background so the user gets their terminal back immediately. The parent process spawns a detached child, writes the child PID to `~/.critters/critters.pid`, logs a startup message, and exits. The child re-execs with `--daemonized` to skip re-forking and runs the normal daemon loop. `critters stop` gains a PID file fallback when the health endpoint is unreachable.

const daemonized = Bun.argv.includes("--daemonized");

// Daemonize when --no-tmux is used (unless dry-run or already daemonized)
if (noTmux && !dryRun && !daemonized) {
  const pidDir = join(homedir(), ".critters");
  mkdirSync(pidDir, { recursive: true });

  const args = Bun.argv.slice(1).filter((a) => !a.startsWith("/$bunfs/"));
  args.push("--daemonized");

  const child = spawn(process.execPath, args, {
    detached: true,
    stdio: "ignore",
    env: process.env,
  });
  child.unref();

  writeFileSync(join(pidDir, "critters.pid"), String(child.pid));

  process.exit(0);

// Clean up stale PID file on startup (only relevant for --no-tmux mode)
const pidFile = join(homedir(), ".critters", "critters.pid");
if (noTmux && existsSync(pidFile)) {
  try {
    const oldPid = parseInt(readFileSync(pidFile, "utf-8").trim(), 10);
    if (!isNaN(oldPid) && oldPid !== process.pid) {
      try {
        process.kill(oldPid, 0); // Check if process exists
        // Process exists — another daemon may be running
        logError(`Another critters daemon may be running (PID ${oldPid}). Remove ${pidFile} if this is stale.`);
        process.exit(1);
      } catch {
        // Process doesn't exist — stale PID file, clean it up
        unlinkSync(pidFile);
      }
    }
  } catch {
    // PID file unreadable, remove it
    try { unlinkSync(pidFile); } catch {}
  }

  // Write our own PID file
  mkdirSync(join(homedir(), ".critters"), { recursive: true });
  writeFileSync(pidFile, String(process.pid));
}
```

catch {
  // Health endpoint unreachable — try PID file fallback
  const pidFile = join(homedir(), ".critters", "critters.pid");
  if (existsSync(pidFile)) {
    try {
      const pid = parseInt(readFileSync(pidFile, "utf-8").trim(), 10);
      if (!isNaN(pid)) {
        process.kill(pid, "SIGTERM");
        // Clean up PID file — the daemon's shutdown handler will also try,
        // but it may not run if the process was stuck. Double-delete is safe.
        try { unlinkSync(pidFile); } catch {}
        console.log(`Sent SIGTERM to critters daemon (PID ${pid})`);
        return;
      }
    } catch {
      // PID file exists but process can't be killed
    }
  }
  console.error("Critters daemon is not running (or health endpoint is disabled)");
  process.exit(1);
}
```

## Edge cases handled

1. **Stale PID file**: On startup (in `--no-tmux` mode only), checks if the PID in the file is still alive. If not, removes the file and continues. If alive, exits with an error to prevent duplicate daemons.
2. **Clean shutdown**: PID file is removed in the shutdown handler (unless restarting).
3. **Restart race condition**: `restartDaemon()` sets a `restarting` flag and writes the new child's PID to the file before the parent exits, preventing the shutdown handler from deleting it.
4. **`critters stop` with dead health server**: Falls back to reading PID file and sending SIGTERM directly. Double-delete of PID file (by stop command + daemon shutdown handler) is harmless.
5. **`--dry-run` with `--no-tmux`**: Does NOT daemonize (dry-run runs in foreground and exits immediately).
6. **Re-exec safety**: `--daemonized` flag prevents the child from forking again.
7. **Bun compiled binary**: Filters `/$bunfs/` virtual paths from argv. Uses `Bun.argv` consistently (matching codebase convention).
8. **Tmux mode unaffected**: PID file check/write is scoped to `noTmux` mode, so tmux-mode startup is never blocked by an existing PID file from a `--no-tmux` daemon.
9. **Bun.spawn vs child_process.spawn**: All detached spawning uses `node:child_process` `spawn` (not `Bun.spawn`) because `Bun.spawn` does not support the `detached` option.

## Testing approach

1. **Manual test**: Run `critters --no-tmux`, verify terminal returns immediately, `~/.critters/critters.pid` exists with correct PID, daemon is running in background, and `~/.critters/critters.log` is being written to.
2. **Stop test**: Run `critters stop` — verify it stops the daemon (via health endpoint). Then test with health port disabled (set `healthPort: 0`): verify `critters stop` falls back to PID file and sends SIGTERM.
3. **Stale PID test**: Create a fake PID file with a non-existent PID, start daemon, verify it cleans up the stale file and starts normally.
4. **Duplicate prevention**: Start daemon, try starting again — verify it detects the running daemon and refuses to start.
5. **Dry-run test**: Run `critters --no-tmux --dry-run` — verify it runs in foreground (no daemonization).
6. **Restart test**: Start daemon with `--no-tmux`, run `critters restart` — verify daemon restarts and PID file is updated.
7. **Tmux + PID file coexistence**: Start a `--no-tmux` daemon, then start a tmux-mode daemon — verify the tmux daemon is not blocked by the PID file.

## Dependencies

None — uses only Node.js built-in `child_process.spawn` and `fs` APIs, both available in Bun.
