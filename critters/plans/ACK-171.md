# ACK-171: Add `critters validate` command

## Summary

Add a `critters validate` CLI command that validates the config file and environment without starting the daemon. It collects all errors (not just the first) and reports them clearly, exiting 0 on success and non-zero on failure.

**Important constraint**: The validate command must NOT create directories or have other side effects. `loadConfig()` calls `mkdirSync(workDir, ...)` so it cannot be used directly — the validate command must parse and validate independently.

## Files to Create

### `src/validate.ts`

New CLI command module, following the pattern of `src/status.ts` and other CLI commands.

**Exported functions:**
- `runValidate(configPath?: string): Promise<void>` — CLI entry point, handles output and `process.exit`
- `validateConfigFile(configPath?: string): { errors: string[]; summary?: string }` — testable inner function that returns errors without side effects

**Implementation:**

1. **Load env vars** — Call `loadEnvFallback()` (imported from `src/env.ts`, see below) to load `~/.critters/.env` as fallback, mirroring daemon behavior so env var checks are accurate.

2. **Resolve config path** — Call `resolveConfigPath(configPath)` (imported from `src/config.ts`). If this throws, it's a fatal error (no config file found) — report and exit 1.

3. **Parse YAML** — Read the file and parse with `yaml` package. If parsing fails, it's a fatal YAML syntax error — report and exit 1.

4. **Validate config fields** (collect errors into `errors[]`):
   - Validate workDir safety via `validateWorkDir()` (imported from `src/config.ts`), wrapped in try/catch
   - Check numeric ranges: concurrency >= 1, timeoutMinutes > 0, pollIntervalSeconds >= 5, maxPlanningTurns > 0, maxExecutionTurns > 0, reviewConcurrency >= 1, reviewTimeoutMinutes > 0, maxReviewTurns > 0, maxLogSizeMb > 0, healthPort 0 or 1024-65535
   - Check `defaultAllowedTools` is a non-empty array
   - Validate repo URLs via `validateRepoUrls()` (imported from `src/config.ts`), wrapped in try/catch
   - Validate team repo URLs similarly

5. **Validate critter types** — If `critterTypes` is present in YAML:
   - For each type entry, call `parseCritterTypes()` / `validateCritterType()` (from `src/critter-type.ts`) wrapped in try/catch, collecting errors
   - If `critterTypes` is absent, validate that synthesized defaults would work by calling `synthesizeDefaultTypes()` with a partial config

6. **Check provider credentials** — Determine which providers are needed from the parsed critter types. Use `checkProviderCredentials()` (imported from `src/config.ts`) which returns an array of missing env var errors rather than throwing:
   - Linear: check `LINEAR_API_KEY` env var
   - Jira: check `JIRA_HOST`, `JIRA_EMAIL`, `JIRA_API_TOKEN` env vars
   - Collect all missing vars as separate errors

7. **Report results:**
   - If no errors: print success message with summary (e.g., "Config valid: 3 critter types, provider: linear") and exit 0
   - If errors: print all errors in a numbered list, then exit 1

**Code sketch:**

```typescript
import { readFileSync } from "node:fs";
import { parse as parseYaml } from "yaml";
import { resolveConfigPath, validateWorkDir, validateRepoUrls, checkProviderCredentials } from "./config.js";
import { parseCritterTypes, synthesizeDefaultTypes } from "./critter-type.js";
import { loadEnvFallback } from "./env.js";

export function validateConfigFile(configPath?: string): { errors: string[]; summary?: string } {
  const errors: string[] = [];

  // 1. Load env fallback
  loadEnvFallback();

  // 2. Resolve config path (fatal if not found)
  const resolvedPath = resolveConfigPath(configPath); // throws if not found

  // 3. Parse YAML (fatal if invalid syntax)
  const raw = readFileSync(resolvedPath, "utf-8");
  const yaml = parseYaml(raw) as Record<string, unknown>;

  // 4. Validate fields independently, collecting errors
  // ... (each check wrapped in try/catch or conditional, pushing to errors[])

  // 5. Validate critter types
  // ... parseCritterTypes() for each, collecting errors

  // 6. Check provider credentials
  const credErrors = checkProviderCredentials(yaml, critterTypes);
  errors.push(...credErrors);

  const summary = errors.length === 0
    ? `Config valid: ${critterTypes.length} critter type(s), provider: ${yaml.provider ?? "linear"}`
    : undefined;

  return { errors, summary };
}

export async function runValidate(configPath?: string): Promise<void> {
  try {
    const result = validateConfigFile(configPath);
    if (result.errors.length === 0) {
      console.log(result.summary);
    } else {
      console.error(`Found ${result.errors.length} error(s):\n`);
      result.errors.forEach((e, i) => console.error(`  ${i + 1}. ${e}`));
      process.exit(1);
    }
  } catch (e) {
    console.error(`Error: ${(e as Error).message}`);
    process.exit(1);
  }
}
```

## Dependencies

- No new dependencies needed
- Reuses existing `yaml` package, `fs`, `os` modules
- Imports from `config.ts`, `critter-type.ts`, and new `env.ts`

## Edge Cases

- Config file not found: clear error message with search paths (from `resolveConfigPath`)
- Empty YAML file: `parseYaml` returns `null` — handle by treating as empty object, then field checks catch missing fields
- `critterTypes` present but empty object: should report "must have at least one type"
- Provider is an array in a critter type: handled by `parseCritterTypes()` which already expands arrays
- Both `./critters.config.yaml` and `~/.critters/config.yaml` exist: uses the same precedence as the daemon (CWD first)
- `.env` file loading: mirrors daemon behavior via shared `loadEnvFallback()` function
- `loadConfig()` has `mkdirSync` side effect: validate command avoids calling it, uses independent parsing instead
