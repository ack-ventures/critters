# ACK-212: Add /api/v1/metadata and /api/v1/issues endpoints to health server

## Summary

Wire tracker instances and critter type config into the health server so it can serve metadata for the dashboard form and handle issue creation requests. This adds two new endpoints: `GET /api/v1/metadata` (returns providers with teams + critter type summaries) and `POST /api/v1/issues` (creates an issue via the appropriate tracker).

#### c. Add `GET /api/v1/metadata` endpoint

Insert this handler in the `fetch` function, after the `/api/v1/auth-check` handler (around line 282) and before the 404 fallback:

```typescript
if (url.pathname === "/api/v1/metadata") {
  const now = Date.now();
  if (cachedMetadata && now - metadataCachedAt < METADATA_CACHE_TTL_MS) {
    return Response.json(cachedMetadata);
  }

  const providers: Record<string, { teams: TrackerTeam[] }> = {};
  if (context?.trackers) {
    for (const [name, tracker] of context.trackers) {
      try {
        providers[name] = { teams: await tracker.listTeams() };
      } catch {
        providers[name] = { teams: [] };
      }
    }
  }
  const defaultProvider = context?.defaultProvider ?? "linear";
  const critterTypes = (context?.critterTypes ?? []).map((ct) => ({
    name: ct.name,
    triggerLabel: ct.trigger.label,
    triggerStatus: ct.trigger.status,
    provider: ct.provider ?? defaultProvider,
  }));

  cachedMetadata = { providers, critterTypes };
  metadataCachedAt = now;
  return Response.json(cachedMetadata);
}
```

**Key decisions:**
- Uses `context.defaultProvider` (sourced from `config.provider` in index.ts) as the fallback for critter types that don't explicitly set a provider. This is important because `synthesizeDefaultTypes` produces types with `provider: undefined`, and the top-level config provider may be `"jira"`, not `"linear"`. Using a hardcoded `"linear"` fallback would be incorrect for Jira-only configurations.
- Caches with 60-second TTL — `listTeams()` calls external APIs (Linear/Jira), so caching avoids repeated requests. Follows the same pattern as `computeMetricsSummary` (module-level `cachedMetadata` + `metadataCachedAt` + TTL check).
- No auth required — metadata is read-only and non-sensitive (team names/IDs, critter type labels).
- Catches errors per-tracker so one failing provider doesn't block the other.

#### d. Add `POST /api/v1/issues` endpoint

Insert this handler right after the metadata handler:

```typescript
if (url.pathname === "/api/v1/issues") {
  if (req.method !== "POST") {
    return new Response("Method Not Allowed", { status: 405 });
  }
  const authResp = checkAuth(req, dashboardToken);
  if (authResp) return authResp;

  if (!context?.trackers) {
    return Response.json({ error: "Trackers not available" }, { status: 503 });
  }

  let body: {
    provider?: string;
    teamId?: string;
    title?: string;
    description?: string;
    critterType?: string;
  };
  try {
    body = await req.json();
  } catch {
    return Response.json({ error: "Invalid JSON body" }, { status: 400 });
  }

  if (!body.title?.trim()) {
    return Response.json({ error: "Title is required" }, { status: 400 });
  }
  if (!body.teamId?.trim()) {
    return Response.json({ error: "Team is required" }, { status: 400 });
  }

  const providerName = body.provider ?? context.defaultProvider ?? "linear";
  const tracker = context.trackers.get(providerName);
  if (!tracker) {
    return Response.json(
      { error: `No tracker configured for provider "${providerName}"` },
      { status: 400 },
    );
  }

  const critterType = context.critterTypes?.find(
    (ct) => ct.name === body.critterType,
  );
  const triggerLabel = critterType?.trigger.label ?? "Critter";

  const description = body.description?.trim() ?? "";

  try {
    const created = await tracker.createIssue({
      teamId: body.teamId,
      title: body.title.trim(),
      description,
      labelNames: [triggerLabel],
    });
    return Response.json({
      success: true,
      identifier: created.identifier,
      url: created.url,
    });
  } catch (err) {
    const message = err instanceof Error ? err.message : String(err);
    return Response.json({ success: false, error: message }, { status: 500 });
  }
}
```

**Key decisions:**
- Auth required — creating issues is a mutating operation, consistent with `/poll` and `/review-poll`.
- Validates `title` and `teamId` as required fields; `provider`, `description`, and `critterType` are optional.
- Provider fallback uses `context.defaultProvider` (same as metadata endpoint) for consistency.
- Resolves the trigger label from the critter type config; falls back to `"Critter"` if no type specified.
- Returns 400 for unknown provider (not 404, since it's a client input error).
- Returns 503 when trackers aren't available (matches `/poll` pattern for unavailable triggers).

## Testing Approach

- All new endpoints are tested via the existing `health.test.ts` pattern: start a server on a random port, make HTTP requests, assert response status and body.
- Mock tracker with all `IssueTracker` interface methods stubbed — `createIssue` returns a fixed `CreatedIssue`, `listTeams` returns a fixed array.
- Mock critter type config for testing the metadata response shape and trigger label resolution.
- Tests cover: happy path, missing required fields, unknown provider, auth enforcement, method enforcement, no-context fallback, defaultProvider resolution, and tracker error handling.
- The metadata cache is reset in `beforeEach` via `resetMetadataCache()` to prevent cross-test interference.
- Existing tests are unaffected — the new `context` parameter is optional and defaults to `undefined`.

## Edge Cases

- **Config hot-reload**: The mutable `healthContext` object is updated in the reload handler, and `resetMetadataCache()` is called to invalidate the cached metadata so the next request fetches fresh data.
- **Tracker error during metadata fetch**: Caught per-tracker with a try/catch; the failing provider returns `{ teams: [] }` rather than failing the entire request.
- **Empty/whitespace title or teamId**: Validated with `.trim()` check — returns 400.
- **No critterType in issue request body**: Falls back to `"Critter"` as the trigger label.
- **Invalid JSON body**: Caught and returns 400 with "Invalid JSON body" error.
- **Tracker `createIssue` throws**: Caught and returns 500 with the error message.
- **Provider fallback**: Both endpoints use `context.defaultProvider` (from `config.provider`) as the fallback when `ct.provider` is `undefined`, correctly handling Jira-only configurations where `synthesizeDefaultTypes` produces types without an explicit provider.
