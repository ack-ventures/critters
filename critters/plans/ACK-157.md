# ACK-157: Log hook stdout when non-empty

## Summary

In `src/hooks.ts`, the `exec()` callback discards stdout (`_stdout`). When a user's hook produces output (e.g. a deployment URL), it's silently lost. This change captures stdout and logs it when non-empty.

## Files to Modify

### 1. `src/hooks.ts`

**Line 17**: Rename `_stdout` to `stdout` in the `exec` callback signature.

**After the existing `else if (stderr)` block (lines 25-31)**, add a new block to log non-empty stdout. The new block goes after stderr handling, inside the same callback:

```typescript
exec(command, { env: { ...process.env, ...env }, timeout: 30_000 }, (error, stdout, stderr) => {
    if (error) {
      const msg = `Hook ${hookName} failed: ${error.message}`;
      if (identifier) {
        logTaskWarn(identifier, msg);
      } else {
        log(`WARN: ${msg}`);
      }
    } else if (stderr) {
      const msg = `Hook ${hookName} stderr: ${stderr}`;
      if (identifier) {
        logTaskWarn(identifier, msg);
      } else {
        log(`WARN: ${msg}`);
      }
    }

    if (stdout && stdout.trim()) {
      const msg = `Hook ${hookName} output: ${stdout.trim()}`;
      if (identifier) {
        logTask(identifier, msg);
      } else {
        log(msg);
      }
    }
  });
```

Key design decisions:
- **Stdout logging is independent of error/stderr**: Uses a separate `if` (not `else if`) so stdout is logged even when the command fails or has stderr. A hook might write useful output to stdout and also write warnings to stderr — both should be visible.
- **Uses `logTask` (not `logTaskWarn`)**: Stdout is normal output, not a warning. This follows the pattern where `logTask` is for informational messages and `logTaskWarn` is for problems.
- **Trims before logging**: Prevents logging empty/whitespace-only stdout, and removes trailing newlines from echo output.

### 2. `src/__tests__/hooks.test.ts`

Add a new test case in the `describe("runHook")` block to verify stdout logging. Since the logger writes to console (no file logging in tests), we can spy on `console.log` to verify the output was logged.

Add this test after the existing tests:

```typescript
test("logs stdout when non-empty", async () => {
    const originalLog = console.log;
    const logs: string[] = [];
    console.log = (...args: unknown[]) => {
      logs.push(args.map(String).join(" "));
    };
    try {
      runHook("test", "echo hello-world", {}, "TST-3");
      await sleep(500);
      expect(logs.some((l) => l.includes("Hook test output: hello-world"))).toBe(true);
    } finally {
      console.log = originalLog;
    }
  });
```

This test:
- Captures console.log output by temporarily replacing it
- Runs a hook that echoes to stdout
- Verifies the logged message contains the expected format
- Restores the original console.log in a `finally` block for safety
