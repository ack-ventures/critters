# ACK-231: Document MCP Config for Critters

## Summary

The `mcpConfig` and `strictMcpConfig` fields already appear in the config tables of README.md, CLAUDE.md, and docs/configuration.md. However, the MCP section in `docs/configuration.md` (lines 367-390) is too brief — it lacks the MCP config JSON file format, detailed behavioral explanation, and comprehensive examples. This plan expands that section and confirms the existing table entries are sufficient.

## Files to modify

### 1. `docs/configuration.md` — Expand MCP section (lines 367-390)

Replace the current brief MCP section with a comprehensive "MCP Servers" section covering:

**a) Overview paragraph** — what MCP servers are in the context of critters (external tool servers that Claude Code can connect to), and that critters passes `--mcp-config` flags to the `claude` CLI.

**b) Global config** (existing, keep as-is):
```yaml
mcpConfig: ~/.critters/mcp.json
strictMcpConfig: false
```

**c) MCP config JSON format** (new) — explain the format Claude Code expects, with a concrete example:
```json
{
  "mcpServers": {
    "my-server": {
      "command": "npx",
      "args": ["-y", "@example/mcp-server"],
      "env": {
        "API_KEY": "..."
      }
    }
  }
}
```
Mention that the format is defined by Claude Code, not critters — critters just passes the file path through.

**d) Multiple config files** (existing but expand):
```yaml
mcpConfig:
  - ~/.critters/mcp-base.json
  - ~/.critters/mcp-extra.json
```
Explain that each file becomes a separate `--mcp-config` flag.

**e) Per-type override** (existing but expand with full example):
```yaml
critterTypes:
  code-audit:
    mcpConfig: ~/.critters/mcp-audit.json
    strictMcpConfig: true
    # ...
```
Emphasize: per-type fully replaces global (not merged). If a type needs both global + extra servers, it must list all files.

**f) Strict mode** — explain that `strictMcpConfig: true` passes `--strict-mcp-config` to prevent inheriting MCP servers from the operator's Claude Code configuration. Default is `false`.

**g) Path resolution** — `~` is expanded to home directory. Absolute paths used as-is. Relative paths resolve against the daemon's CWD.

**h) Resolution behavior** — MCP config is resolved once per task (not per phase). The same config applies to all phases of a task.
