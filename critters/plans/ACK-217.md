# ACK-217: Add Repo Selector to Dashboard Issue Creation Modal

## Summary

Add a "Repository" dropdown to the "New Critter" modal in the dashboard so users can select a repo from the config's `repos` and `teamRepos` mappings. When a repo is selected, `repo: <url>` is auto-prepended to the description on submit, so the critter knows which repo to clone.

## Files to Modify

### 1. `src/types.ts` — No changes needed

The `Config` interface already has `repos: Record<string, RepoConfig>` and `teamRepos: Record<string, string>`. No type changes needed here.

### 2. `src/health.ts` — Extend context type and metadata response

**Metadata response change (lines 300-327):**

After building `critterTypes` array, build a `repos` array by collecting URLs from `context.repos` (values) and `context.teamRepos` (values), deduplicating by URL, and extracting a short label from each URL.

Label extraction logic: for `git@github.com:org/repo.git` → `org/repo`. Regex: strip the `git@...:` or `https://.../ ` prefix and `.git` suffix, then take the last two path segments as `org/repo`.

```typescript
// Build deduplicated repos list
const repoUrls = new Set<string>();
const reposList: Array<{ url: string; label: string }> = [];

function extractLabel(url: string): string {
  // git@github.com:org/repo.git → org/repo
  // https://github.com/org/repo.git → org/repo
  const match = url.match(/[:/]([\w.-]+\/[\w.-]+?)(?:\.git)?$/);
  return match ? match[1] : url;
}

if (context?.repos) {
  for (const repo of Object.values(context.repos)) {
    if (!repoUrls.has(repo.url)) {
      repoUrls.add(repo.url);
      reposList.push({ url: repo.url, label: extractLabel(repo.url) });
    }
  }
}
if (context?.teamRepos) {
  for (const url of Object.values(context.teamRepos)) {
    if (!repoUrls.has(url)) {
      repoUrls.add(url);
      reposList.push({ url, label: extractLabel(url) });
    }
  }
}
```

Include `repos: reposList` in the `cachedMetadata` object. Update the `cachedMetadata` type accordingly (add `repos: Array<{ url: string; label: string }>` to the inline type on line 33).

### 6. `src/dashboard.ts` — Auto-prepend repo line on submit

**In the form submit handler (lines 1185-1191):**

After building the `body` object, check if a repo is selected and prepend `repo: <url>` to the description if not already present:

```javascript
var repoSelect = document.getElementById('create-repo');
var selectedRepo = repoSelect.value;
var description = document.getElementById('create-description').value;
if (selectedRepo && !/^repo:\s/m.test(description)) {
  description = 'repo: ' + selectedRepo + '\n\n' + description;
}

var body = {
  provider: providerSelect.value,
  teamId: teamSelect.value,
  title: document.getElementById('create-title').value,
  description: description,
  critterType: typeSelect.value
};
```

The regex `/^repo:\s/m` uses the multiline flag to check if any line already starts with `repo: `, preventing duplicate prepending.

## Dependencies

No new dependencies required. All changes are to existing files using existing patterns.

## Edge Cases

1. **Empty repos/teamRepos**: If both are empty/undefined, the repo dropdown is hidden entirely (`display: none` on the wrapper div).
2. **Duplicate URLs**: If the same repo URL appears in both `repos` and `teamRepos`, it's deduplicated by URL so it only appears once in the dropdown.
3. **Description already contains `repo:` line**: The regex check prevents double-prepending. Users who type `repo:` manually in the description won't get a duplicate.
4. **No repo selected**: The blank "None (specify in description)" option means no `repo:` line is prepended — existing behavior is preserved.
5. **Config hot-reload**: When config changes, `healthContext.repos` and `healthContext.teamRepos` are updated and `resetMetadataCache()` clears the cached metadata, so new repos appear on next modal open.
6. **Metadata cache**: The 60s TTL metadata cache already exists. Repos are included in the cached object, so they benefit from the same caching.

## Testing Approach

1. **Manual testing with dashboard**: Start the daemon with a config that has `repos` and `teamRepos` entries. Open the dashboard, click "New Critter", and verify:
   - The Repository dropdown appears with deduplicated repos
   - Labels are correctly extracted from URLs (e.g., `org/repo`)
   - Selecting a repo and submitting prepends `repo: <url>` to the description
   - The "None" option works and doesn't prepend anything
   - Typing `repo: ...` in the description manually prevents double-prepend
2. **Empty config**: Start with no `repos` or `teamRepos`. Verify the dropdown is hidden.
3. **Hot-reload**: Change the config to add/remove repos while the daemon is running. Verify the dropdown updates after the metadata cache expires (60s).
4. **Type checking**: Run `bun run typecheck` to verify no TypeScript errors from the context type changes.
5. **Lint**: Run `bun run lint` to verify no style issues.
