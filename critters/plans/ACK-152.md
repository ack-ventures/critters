# ACK-152: Show latest released version alongside "vdev" in dev builds

## Summary

When `VERSION === "dev"`, fetch the latest version tag from GitHub releases and display it alongside `vdev` everywhere the version is shown. For example: `Critters vdev (latest: v0.4.4)`. The fetch caches the result for the session, fails silently (returning `null`), and doesn't block startup.

## Files to Modify

### 1. `src/updater.ts` — Add `fetchLatestVersion()` and `getDisplayVersion()`

**Add module-level cache variable:**
```ts
let cachedLatestVersion: string | null = null;
```

**Add `fetchLatestVersion()` function (exported):**
```ts
export async function fetchLatestVersion(): Promise<string | null> {
  if (cachedLatestVersion !== null) return cachedLatestVersion;

  try {
    const response = await fetch(RELEASES_URL, {
      headers: {
        Accept: "application/vnd.github+json",
        "User-Agent": "critters-updater",
      },
      signal: AbortSignal.timeout(10_000),
    });

    if (!response.ok) return null;

    const data = await response.json();
    const { tag_name } = data as { tag_name: unknown };

    if (typeof tag_name !== "string") return null;

    // Strip the "v" prefix and any pre-release suffix to get clean semver
    cachedLatestVersion = tag_name.replace(/^v/, "");
    return cachedLatestVersion;
  } catch {
    return null;
  }
}
```

This reuses the existing `RELEASES_URL` constant and follows the same fetch pattern as `checkForUpdate()` (same headers, same 10s timeout, same response parsing). Fails silently on any error.

**Add `getDisplayVersion()` function (exported):**
```ts
export function getDisplayVersion(): string {
  if (VERSION !== "dev") return `v${VERSION}`;
  if (cachedLatestVersion !== null) return `vdev (latest: v${cachedLatestVersion})`;
  return "vdev";
}
```

This is synchronous — it reads from the cached value set by `fetchLatestVersion()`. Import `VERSION` from `./version.js`.

## Dependencies / Setup

No new dependencies needed. Uses only the existing `fetch` API and the already-defined `RELEASES_URL` constant in `src/updater.ts`.

## Edge Cases

1. **Fetch failure (network error, timeout, non-200):** `fetchLatestVersion()` returns `null`, `getDisplayVersion()` returns `"vdev"` — identical to current behavior.
2. **Unexpected API response format:** Returns `null` if `tag_name` is not a string.
3. **Release builds (`VERSION !== "dev"`):** `getDisplayVersion()` returns `v${VERSION}` — identical to current behavior. `fetchLatestVersion()` is only called when `VERSION === "dev"` in the daemon path.
4. **Repeated calls:** `fetchLatestVersion()` returns cached result after first successful fetch (no duplicate API calls).
5. **Status command connecting to older daemon:** Falls back to `v${health.version ?? VERSION}` if `displayVersion` is not in the healthz response.
