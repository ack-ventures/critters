# ACK-279: Add unit tests for `loadEnvFallback` in `env.ts`

## Summary

Add test coverage for `src/env.ts`'s `loadEnvFallback()` function. This function loads environment variables from `~/.critters/.env` as a fallback when no `.env` file exists in the current working directory. It skips blank lines, comments, and lines without `=`, and does not overwrite variables already set in `process.env`.

## Files to Create

### `src/__tests__/env.test.ts`

New test file covering all five required test cases.

## Dependencies / Setup

- **Test framework**: `bun:test` (`describe`, `test`, `expect`, `beforeEach`, `afterEach`, `mock`)
- **Helpers**: `createTempDir` from `./helpers.js` for temp directory creation
- **Mocking**: `mock.module("node:os", ...)` from `bun:test` to control `homedir()` return value, pointing it at a subdirectory within the temp dir. This follows the existing pattern used in `linear.test.ts`, `updater.test.ts`, etc.
- **Filesystem**: `writeFileSync`, `mkdirSync` from `node:fs` to create `.env` files and `.critters/` directories inside the temp structure.
- **CWD control**: `process.chdir()` to control whether `./.env` exists relative to CWD, matching the pattern in `config.test.ts` (CWD fallback resolution tests).

## Test Structure

```typescript
import { afterEach, beforeEach, describe, expect, mock, test } from "bun:test";
import { mkdirSync, writeFileSync } from "node:fs";
import { createTempDir } from "./helpers.js";
```

### Setup/Teardown Pattern

1. **`mock.module("node:os", ...)`** at module level (before importing `loadEnvFallback`), returning a mock `homedir()` that points to `fakeHome` (a variable set per-test in `beforeEach`).
2. **`beforeEach`**: Create a temp dir with two subdirectories:
   - `tempDir/home` — serves as the fake home directory (returned by mocked `homedir()`)
   - `tempDir/cwd` — serves as the fake CWD
   - Create `tempDir/home/.critters/` directory
   - Save `process.cwd()` and any process.env keys that tests will touch
3. **`afterEach`**: Restore original CWD, restore saved env vars, clean up temp dir.
4. **Import `loadEnvFallback`** after `mock.module` call (required by Bun's mock system — see comment in `linear.test.ts` line 16).

### Test Cases

#### 1. "loads vars from ~/.critters/.env when CWD .env doesn't exist"

- Setup: Write `FOO_TEST_VAR=bar` to `fakeHome/.critters/.env`. Do NOT create `.env` in CWD. `chdir` to the CWD dir. Delete `FOO_TEST_VAR` from `process.env`.
- Act: Call `loadEnvFallback()`.
- Assert: `process.env.FOO_TEST_VAR === "bar"`.
- Teardown: Delete `FOO_TEST_VAR` from `process.env`.

#### 2. "does NOT load fallback when CWD .env exists"

- Setup: Write `CWD_VAR=local` to `cwdDir/.env`. Write `CWD_VAR=fallback` to `fakeHome/.critters/.env`. `chdir` to CWD dir. Delete `CWD_VAR` from `process.env`.
- Act: Call `loadEnvFallback()`.
- Assert: `process.env.CWD_VAR` is `undefined` (fallback was not loaded because CWD `.env` exists; the function doesn't load CWD `.env` itself — it only loads the fallback).

#### 3. "skips blank lines and comments"

- Setup: Write a fallback `.env` file with content:
  ```
  # this is a comment
  
  VALID_KEY=value
  
  # another comment
  ```
  No `.env` in CWD. `chdir` to CWD dir. Delete `VALID_KEY` from `process.env`.
- Act: Call `loadEnvFallback()`.
- Assert: `process.env.VALID_KEY === "value"`. No crash occurred (blank lines and comments were silently skipped).

#### 4. "skips lines without ="

- Setup: Write a fallback `.env` with:
  ```
  GOOD_KEY=good_value
  BADLINE_NO_EQUALS
  ANOTHER_GOOD=works
  ```
  No `.env` in CWD. `chdir` to CWD dir. Delete `GOOD_KEY`, `BADLINE_NO_EQUALS`, `ANOTHER_GOOD` from `process.env`.
- Act: Call `loadEnvFallback()`.
- Assert: `process.env.GOOD_KEY === "good_value"`, `process.env.ANOTHER_GOOD === "works"`, `process.env.BADLINE_NO_EQUALS` is `undefined`.

#### 5. "does NOT overwrite vars already in process.env"

- Setup: Write `EXISTING_VAR=from_fallback` to fallback `.env`. No `.env` in CWD. `chdir` to CWD dir. Set `process.env.EXISTING_VAR = "original"`.
- Act: Call `loadEnvFallback()`.
- Assert: `process.env.EXISTING_VAR === "original"` (not overwritten).
- Teardown: Delete `EXISTING_VAR` from `process.env`.

## Env Var Isolation

Each test will use uniquely-named env var keys (e.g., `FOO_TEST_VAR`, `CWD_VAR`, `VALID_KEY`, etc.) that are unlikely to collide with real env vars. The `beforeEach`/`afterEach` hooks will save and restore any env vars touched by tests, following the same pattern as `config.test.ts`.

## Testing Approach

Run with `bun test src/__tests__/env.test.ts` to verify all five tests pass. The tests use real filesystem operations (temp dirs) combined with a mocked `homedir()`, which is the lightest-touch mocking approach — only the piece that can't be controlled via filesystem is mocked.
