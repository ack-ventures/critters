# ACK-235: Add `critters history` command

## Summary

Add a `critters history` CLI command that queries past critter runs from `~/.critters/metrics.jsonl` and displays them as a formatted table (or JSON). This requires:

1. A new `src/cli-history.ts` module
2. A new `readAllMetrics()` function in `src/metrics.ts` for untruncated access to the JSONL file
3. Registration of the `history` subcommand in `src/index.ts`

## Files to Create

### `src/cli-history.ts`

New file exporting `async function runHistory(args: string[]): Promise<void>`.

**Argument parsing:**
- `--last N` — limit to N results (default 20)
- `--failed` — filter to `task_failed` and `review_failed` events only
- `--type <name>` — filter by `critterType` field
- `--json` — output JSON array instead of table

**Core logic:**
1. Read all metrics from `~/.critters/metrics.jsonl` using `readAllMetrics()` (new function, see below)
2. Filter to completion/failure events: `task_completed`, `task_failed`, `review_completed`, `review_failed`
3. Apply `--failed` filter if set (keep only `*_failed` events)
4. Apply `--type` filter if set (match `critterType` field)
5. Sort by timestamp descending (most recent first)
6. Slice to `--last N` entries
7. Output as table or JSON

**Table format:**
```
Identifier  Type     Status     Duration  Cost    Date
ACK-101     create   completed  4m 32s    $1.23   2026-03-11 14:30
ACK-102     review   failed     2m 10s    $0.45   2026-03-11 13:15
```

Column formatting details:
- **Identifier**: `event.identifier` (e.g., "ACK-101")
- **Type**: `event.critterType` (e.g., "create", "review", "code-audit")
- **Status**: Derived from event name — `task_completed` → "completed", `task_failed` → "failed", `review_completed` → "completed", `review_failed` → "failed"
- **Duration**: `formatDuration(event.duration)` from `src/utils.ts` (already handles ms → human-readable)
- **Cost**: `$${event.costUsd.toFixed(2)}` or "-" if not present
- **Date**: Format `event.timestamp` as `YYYY-MM-DD HH:MM` in local time

Column padding: Calculate max width for each column across all rows, pad with spaces. Use the same simple approach as `src/status.ts` (plain `console.log` with string padding).

**JSON output (`--json`):**
Output `JSON.stringify(results, null, 2)` where each result is:
```json
{
  "identifier": "ACK-101",
  "type": "create",
  "status": "completed",
  "duration": "4m 32s",
  "durationMs": 272000,
  "cost": 1.23,
  "date": "2026-03-11T14:30:00.000Z"
}
```

**Edge cases:**
- No metrics file → print "No history found." and exit 0
- No matching results → print "No matching runs found." and exit 0
- Missing fields (identifier, critterType, duration, costUsd) → use "-" for display, `null` for JSON
- Invalid `--last` value (non-numeric, negative) → print usage error and exit 1

## Files to Modify

### `src/metrics.ts`

Add a new exported function `readAllMetrics()` that reads the full JSONL file without truncation:

```typescript
export function readAllMetrics(filePath?: string): MetricEvent[] {
  const file = filePath ?? join(homedir(), ".critters", "metrics.jsonl");
  if (!existsSync(file)) return [];
  try {
    const content = readFileSync(file, "utf-8");
    const lines = content.split("\n").filter(Boolean);
    return lines.flatMap((line) => {
      try {
        return [JSON.parse(line) as MetricEvent];
      } catch {
        return [];
      }
    });
  } catch {
    return [];
  }
}
```

This is needed because `getRecentMetrics()` requires `initMetrics()` to have been called first (it depends on the module-level `metricsFile` variable), and it only returns the last N events. The history command needs to read all events and apply its own filtering. The new function takes an optional file path and defaults to the standard location, without requiring `initMetrics()`.
