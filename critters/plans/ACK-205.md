# ACK-205: Add model name to progress comments on Linear and Jira

## Summary

When critters post progress comments to Linear/Jira during task execution, include the model name (e.g., "opus", "sonnet") so it's easy to see which model handled each phase. The model info is already available on `PhaseConfig.model` — this task threads it through to the relevant comment strings.

## Formatting convention

Use parentheses `(model)` consistently for model annotations in all comments. This aligns with the existing pattern of parenthetical info in comments (e.g., `(completed in 5m)`, `(15 turns, ...)`).

For multi-phase summary comments, deduplicate model names with `[...new Set(...)]` so "opus/opus" becomes just "opus" when all phases use the same model.

## Files to modify

### 1. `src/unified-spawner.ts`

This is the main file where all tracker comments are posted. Changes:

**Phase start comments (line 371):**
Currently: `"Planning..."` / `"Plan approved, executing..."`
Change to include the current phase's model:
- `"Planning (opus)..."` / `"Plan approved, executing (opus)..."`

```typescript
// Before:
await tracker.comment(task.id, `${phase.name === "planning" ? "Planning" : "Plan approved, executing"}...`);

// After:
await tracker.comment(task.id, `${phase.name === "planning" ? "Planning" : "Plan approved, executing"} (${phase.model})...`);
```

**Phase completion comments (line 414-416):**
Currently: `"planning completed in 2m30s (15 turns, 100k in / 50k out / 200k cached, $1.50)"`
Add model name in parentheses after the phase name:

```typescript
// Before:
const phaseStats = `${phase.name} completed in ${formatDuration(phaseDuration)}${formatPhaseStats(phaseResult.spawn)}`;

// After:
const phaseStats = `${phase.name} (${phase.model}) completed in ${formatDuration(phaseDuration)}${formatPhaseStats(phaseResult.spawn)}`;
```

**PR created comment (line 729):**
Currently: `"PR created: <url> (completed in 5m)"`
Add a deduplicated model summary:

```typescript
// Before:
await tracker.comment(task.id, `PR created: ${prUrl} (completed in ${totalDuration})`);

// After:
const modelSummary = [...new Set(critterType.phases.map(p => p.model))].join("/");
await tracker.comment(task.id, `PR created: ${prUrl} (${modelSummary}, completed in ${totalDuration})`);
```

This produces e.g. `"PR created: <url> (opus, completed in 5m)"` when both phases use opus, or `"PR created: <url> (opus/sonnet, completed in 5m)"` when they differ.

### No other files need changes

The model info is already present on `PhaseConfig.model` and `critterType.phases[].model`. No new types, interfaces, or utility functions are needed. The changes are purely string formatting in `unified-spawner.ts`.

## Testing approach

1. **Grep verification**: Search for all `tracker.comment` calls to ensure no comment sites are missed
2. **Type checking**: Run `bun run typecheck` to ensure no TypeScript errors (all accessed fields already exist)
3. **Unit tests**: No existing tests for these comment strings, and adding tests for string formatting in an integration-heavy module isn't worthwhile. The changes are simple string interpolation.
4. **Manual verification**: The comment format changes can be verified by reading the code — each change is a straightforward string template modification

## Edge cases

- **Single-phase types**: `critterType.phases[0].model` is always safe since validation enforces at least one phase
- **Multi-phase with same model**: Deduplicated via `new Set()` so "opus/opus" becomes "opus"
- **Multi-phase with different models**: Shows both, e.g., "opus/sonnet"
- **Model name format**: The model field is already a simple string like "opus", "sonnet", "haiku" — no transformation needed
