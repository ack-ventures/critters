# ACK-219: Reverse release notes order and shorten lines

## Summary

Two display-only changes to `critters release-notes`:

1. **Reverse order**: Show oldest versions first, newest last (so the latest version is closest to the user's prompt).
2. **Shorten body lines**: Strip verbose GitHub URLs and author handles from PR lines, and remove "Full Changelog" links entirely.

## Files to modify

### `src/cli-release-notes.ts`

**Change 1 — Reverse iteration order:**

Replace the `for...of` loop over `RELEASE_NOTES` with iteration over a reversed copy:

```ts
const sorted = [...RELEASE_NOTES].reverse();
for (const release of sorted) {
```

`RELEASE_NOTES` is ordered newest-first from the bundler (`gh release list` returns newest first, and `unshift` adds the current tag to the front). Reversing gives oldest-first display.

**Change 2 — Shorten body lines:**

Add a `shortenBody` helper function that processes each line of the release body:

1. For PR lines matching the pattern `* <description> by @<user> in https://github.com/<org>/<repo>/pull/<num>`, transform to `* <description> (#<num>)`.
2. For PR lines that just have `* <description> in https://github.com/<org>/<repo>/pull/<num>` (no author), transform to `* <description> (#<num>)`.
3. Remove lines matching `**Full Changelog**: https://...` entirely.
4. Leave all other lines unchanged.

Regex for PR lines: `/^(\* .+?) (?:by @\S+ )?in https:\/\/github\.com\/\S+\/pull\/(\d+)$/`
- Captures the description prefix (group 1) and PR number (group 2)
- The `by @username` part is optional (`(?:by @\S+ )?`)
- Replacement: `$1 (#$2)`

Regex for Full Changelog lines: `/^\*\*Full Changelog\*\*: https:\/\/.+$/`
- These lines are removed entirely (filtered out).

The function processes `release.body.split("\n")`, transforms/filters each line, then joins back. Empty trailing lines from removed Full Changelog lines are also trimmed.

### No changes to other files

- `scripts/bundle-release-notes.cjs` — unchanged (data stays as-is)
- `src/release-notes.ts` — generated file, unchanged

## Implementation detail

The updated `runReleaseNotes` function:

```ts
function shortenBody(body: string): string {
  return body
    .split("\n")
    .map((line) =>
      line.replace(
        /^(\* .+?) (?:by @\S+ )?in https:\/\/github\.com\/\S+\/pull\/(\d+)$/,
        "$1 (#$2)"
      )
    )
    .filter((line) => !/^\*\*Full Changelog\*\*: https:\/\/.+$/.test(line))
    .join("\n")
    .trimEnd();
}

export function runReleaseNotes(): void {
  if (RELEASE_NOTES.length === 0) {
    console.log("No release notes available (dev build).");
    return;
  }

  const sorted = [...RELEASE_NOTES].reverse();
  for (const release of sorted) {
    const current = release.tag === `v${VERSION}` ? " (current)" : "";
    console.log(`\x1b[1m${release.tag}${current}\x1b[0m — ${release.date}`);
    if (release.body) {
      console.log(
        shortenBody(release.body)
          .split("\n")
          .map((l) => `  ${l}`)
          .join("\n")
      );
    }
    console.log();
  }
}
```

## Edge cases

- **Empty body**: `shortenBody` handles empty strings fine (splits to `[""]`, no replacements, joins back to `""`). The `if (release.body)` guard already skips falsy bodies.
- **Lines without PR URLs**: The regex only matches lines starting with `* ` that end with `in https://github.com/.../pull/<num>`. Other lines pass through unchanged.
- **"New Contributors" section**: Lines like `* @username made their first contribution in https://...` — these start with `* @` not `* <description> by @`, but the regex handles them correctly since it captures everything after `* ` up to ` by @` or ` in https://`. Actually, these lines match the pattern: `* @username made their first contribution in https://github.com/.../pull/123` — the `by @\S+` part is optional, so it captures `* @username made their first contribution` and `(#123)`.
- **Dev build**: The empty-notes early return is unchanged.
- **RELEASE_NOTES data order**: The bundler stores newest-first. `.reverse()` on a shallow copy doesn't mutate the original.
